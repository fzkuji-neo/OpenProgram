仓库分支整合

整合范围

整合目标是 main。逐一核对所有本地分支和已获取 origin 分支的已提交版本。未提交文件保留在原工作区。整合候选在独立、干净的 checkout 中准备。删除分支是另一项操作。

现有实现

当前 main 已通过 cherry-pick 或后续改写包含许多分支改动。补丁等价的分支可能具有不同提交 ID。origin main 的历史独立，早于本地快照；连接历史前需要与该快照比较。Agent 和 Context 重构及 Anthropic 官方 API 接入要求继续生效。

合并方式

已是祖先的分支满足包含要求。对于重复或被新实现替代的改动，比较独有补丁后保留当前实现并记录分支历史。真正新增的改动使用常规内容合并。旧分支引用已删除 API 时保留较新的实现。依赖更新共同解析为一个 lockfile。不采用覆盖远端历史或直接接受全部历史文件的方式。

验证与失败处理

私有交付记录逐项登记分支提交、远端提交、祖先关系、补丁比较、审查和剩余检查。确认清单中每个分支提交都是最终 main 的祖先。在合并后的版本运行仓库契约、受影响公开入口、依赖锁校验、Web 测试及文档检查。原有全量测试失败继续明确标为未通过。上传前重新获取 origin 并使用正常 fast-forward 推送。冲突或写入失败时保留候选和原有引用。

交付

将经过审查的精确整合提交发布到 origin/main，独立核对远端 SHA，推进本地 main 并保留未跟踪文件，从干净的整合 checkout 刷新唯一默认安装版 App。App 验收使用默认 profile 和端口 18100。

实现状态

分支核对和整合正在进行。最终祖先关系、审查、验证、远端写入及 App 验收在交付记录中分别登记。不宣称完整框架健康检查已通过。
