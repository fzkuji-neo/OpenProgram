Speaker identity: who said it in memory

Several people can share one agent and one memory workspace. Channel entries currently retain a body prefix and also persist trustedspeaker_id/speaker_display as independent fields on message nodes. This page has three layers:Before the change, How eight frameworks in references handle it, Our implementation. Sections 06–08 retain the superseded body-only intermediate design and its tradeoffs before security review. Sections 09–12 describe the replacing dual representation, source framing, and speaker filtering. The prose specification is indocs/reference/design/memory/overview.md; the overall mechanism is inarchitecture.html.

Layer one Before the change

This layer records the state before implementation. Sender display names reached message nodes per message, while stable IDs stopped at the access gate. Memory writing read neither. The next sections explain the problem and where propagation broke. The session shapes in section 01 still apply and motivate this change.

01How many people share one session

Whether identity needs per-message transport depends on whether two speakers can appear in one session. They can. The routing key (openprogram/channels/_session_routing.py:33-52 session_key_for_agent) has two configurations placing multiple people in one session, one of which is the Telegram group default.

Conclusion: identity must accompany every message. In the left two shapes, a session remembers one peer despite several speakers, so session-level fields always identify just one of them. Per-message identity also works for the right two single-person shapes, making it the only approach valid in all four.
Source: _session_routing.py:33-52’s branches (group / channel always isolate bypeer_id; scope == "main" combines all private chats); Telegram’speer_id_for in implementations/telegram.py:55-60, group_sessions defaults toshared (telegram.py:48).

A group message passes through eight stages before reaching a topic file. Before the change, display names reached stage seven; stable IDs stopped after stage two. Layer two How eight frameworks under references handle it

All eight implementations were examined, rather than READMEs. Only three connect chat channels, and only two encounter multiple people in one session. Both use nearly the same approach:prepend the speaker’s name to message content, adding nothing else. The other five are single-user CLIs without the concept of multiple people in one session; that too is a design choice.

Layer three Our implementation

Sections 06–08 record the pre-security-review body-only intermediate design. It used hermes’s body form and openclaw’sName (id) labels and initially planned to modify only two files. It could neither provide trusted filter keys nor prevent body labels from creating false identities, so sections 09–12 replace it with dual representation. The final implementation retains body prefixes, independently carries structured speaker fields, and uses trusted frames in source archives.

06Historical intermediate design: one prefix

This section describes the superseded intermediate design. It added a body prefix only inbase.py:_dispatch_and_reply, where both ch_msg.user_id andch_msg.user_display were available and which was thedispatch_inbound ’sonlycall site. The final implementation still generates the compatibility prefix here, but also passes both values independently to the dispatcher.

Why this design was replaced: body prefixes show names to the current-turn agent, but if_records() reads only role, there is no trusted retrieval key. Parsing identity back fromcontent lets senders forge that key. The final implementation retains prefixes while making_records() read only persisted structured speaker fields.

07Historical intermediate change scope

This section retains the original scope comparison between structured fields and body-only transport. The two-file approach on the right was later replaced because its trust boundary was insufficient. Current implementation uses structured transport on the left, plus source framing and retrieval interfaces.

Current change boundary: Web, CLI, and TUI do not pass throughchannels/base.py, so they have no channel prefix and do not synthesize speaker identity. Channel messages carry both body prefixes and structured fields. Dispatcher, SourceRecord, writer/archive, BM25/inspect, andmemory_search all follow section 11’s final contract. The body-only two-file estimate remains historical design evidence only.

08Tradeoffs and final correction

This section retains six decisions from the reference audit. A changed to dual representation after security review; the others still apply.

A. Identity in content or structured fields?

Final choice: dual representation for current-turn visibility and the memory trust boundary respectively.

Retainbody prefix. hermes usesf"[{user_name}] {text}" (run.py:7759-7765); openclaw uses`${sender}: ${body}` (envelope.ts:214-219). The current-turn agent reads onlycontent, so the compatibility prefix remains.
Addindependently transported structured fields.speaker_id/speaker_display derived only from channel messages. Writers and retrieval never infer new identity from forgeable content.

B. Include a stable ID in labels?

Display names can change or collide; stable IDs persist but are not human-readable. References differ here.

RetainInclude it, using openclaw’s formDisplay name (id) (sender-label.ts:21-30, ten lines).base.py already has both fields, so adding the parenthesized ID needs no additional source.
Do not copyhermes’s display-name-only choice. Renaming would turn one person into two in memory, while shared names would merge two people.

C. Prefix private chats too?

Both references omit private-chat prefixes because one-to-one sessions already identify the person.

Do not copyPrefix private chats too. Our private chats do not guarantee one speaker: with an agent configured assession_scope: main, all private peers share one session (_session_routing.py), containing several people whilechat_type is alwaysdirect. Scope is computed by_conversation.py after obtaining the agent;base.py does not know it here. Skipping by private-chat status is neither safe nor decidable at this stage.
RetainAlways prefix; the cost is measurable. Single-person Discord/Slack private sessions gain roughly a dozen tokens per turn, eliminating a conditional branch to maintain. When identity is genuinely absent (bothuser_id anduser_display empty), use an empty prefix.

D. Sanitize externally supplied display names?

Senders choose platform display names, which are inserted directly into the writing-agent prompt.

RetainRemove newlines, truncate to 64 characters, replace square brackets with parentheses. One record per line is assumed byrender_conversation and archives. A newline in a name splits one record into two and breaks ref/content correspondence; square brackets can forge a second speaker prefix and misattribute content. openclaw does all three (sanitizeEnvelopeHeaderPart, with the comment that header content must not break the bracketed prefix).
Rejecta full escaping system. Archives are human-readable Markdown; escaping harms readability, while the ID is the trusted part.

E. Strip prefixes from display and history?

openclaw wrotestrip-inbound-meta.ts, 317 lines, for this.

Do not copyDo not strip. Those 317 lines handle current-turn JSON metadata, while its body prefix is also retained. hermes has no stripping code. The accepted cost is a bracketed name before the user’s own messages in Web UI and TUI.
Do not copyThe entire JSON metadata block (inbound-meta.ts:436-541, 106 lines), contains openclaw-specific reply chains, forwarding origin, group members, and location—separate from speaker identity.

F. Isolate memory per person?

One shared memory is the product model, not a defect.

RetainDo not isolate. One workspace and one set of topic files are shared by everyone. Identity is record attribution, not access control. Neither reference partitions memory by person.
Adoptpeople as topic pages. openclaw’smemory-wiki: a person is a Markdown page withcanonicalId+aliases+handles (markdown.ts:42-56, compile.ts:424-445), maintained by the model rather than a pipeline field. Ourtopics/people/ serves the same purpose, including merging one person’s cross-channel identities.
RejectAdding memory scopes or per-person directories. A team bot lets others use what one person tells it. Users needing independent memory run their own instance (openprogram --profile <name>).

09Body text can forge a second label

Compatibility prefixes remain in content, so a sender may type another label. That label remains body text without creating a new record identity. Trusted boundaries are persisted speaker fields, speaker fields in writer JSON objects, and valid source frames.

Current protection: speaker_id/speaker_display enters node metadata only from channel messages; _records() never parses the body. Writer input encodes every real turn as one physical JSONL line. Only the complete JSON object’sspeaker field establishes identity;content newlines and forged records remain JSON string content. Source parsing starts only from the fixed format marker at byte zero ofsources/<provider>/_v2/<thread>.md, strictly accepts completerecord-lines frames, and skips body lines by declared count. Speaker IDs must use canonical UTF-8 percent encoding; malformed escapes or literal-- invalidate frames. An empty marker remains a valid display-only identity. Parsing stops at an invalid frame.
Remaining boundary: frozen legacy files have no independently trusted boundary. They retain only limited prefix retrieval hints for strictuser records. Speaker markers and forged frames there never establish trusted identity. Results usespeaker_trusted to distinguish v2 identity (true) from legacy hints (false).

10Three remedies and writer serialization

Change body text: apply display-name bracket rules at its beginning

The most direct approach, and the only one changing the user’s original words.

RejectCovers one line only. The next newline creates another beginning and bypasses it. Covering every line would require rewriting[ in Markdown links, list items, logs, and pasted code—the core material sent to programming agents. No rule can distinguish[2026-08-09] INFO ready from forged labels.

Change prompt and input protocol: separate identity and content fields

Preserve everyone’s text; use no handwritten headers, XML, or Markdown fences.

ImplementedEach turn is one compact JSON object on one physical line.ref, speaker, content use separate fields. Standard JSON encoding escapes LF, CR, quotes, and backslashes; rendering additionally escapes U+2028/U+2029 that a model might display as newlines. The prompt recognizes only thespeaker field;content text can establish neither identity nor a second record.

Add fields: place speaker identity in runtime-populated slots

Structured fields and v2 framing are implemented.

BoundaryThe writer reads identity fromthe JSON object’sspeaker field, generated from runtime structured fields. New sources write only to fixed-marker-prefixed_v2/ files. 11Query by speaker

Current BM25 source retrieval can answer “What did Person A say about the budget?” using trusted speaker keys. Filters match only stable IDs, normalized display names, or complete source-record labels, not mentions in content or topic paragraphs.

Filtering is meaningful only undersources/: topic paragraphs are the writer’s statements about a topic, not utterances by a person. “What did Person A say?” differs from “What is known about Person A?” The latter ispath_prefix=topics/people/, already available. Supplying speaker restricts retrieval to source records and reports that restriction in results.
Body boundary: new archives write only fixed-format-marker-prefixedsources/<provider>/_v2/<thread>.md, usingrecord-lines:N to declare literal LF line counts. Parser and deduplication scans start at the file beginning and skip exactly N lines. Even valid hash anchors,source-id, speaker-id, and record lines inside content cannot create another event or block later real archival. Invalid/truncated frames stop parsing. Onlyspeaker-id within valid v2 frames is trusted. Markdown trailing double spaces, CRLF, and final newlines survive writer and workspace-runtime temporary-file flush/fsync/os.replace unchanged. Temporary files enter neither revisions, visible listings, nor stage copies. Old files stay frozen, support restricted compatibility parsing, and never participate in v2 deduplication. Results usespeaker_trusted=false to identify legacy hints.
Change scope: dispatcher transport, memory records and both renderers, source framing, BM25/inspect, and tools. BM25 still rebuilds indexes from files on each call (persist=False). Persistent cache format advances to v8 and ignores old entries missing current speaker or trust fields.

12Implementation status

Final review progress: JSONL writer serialization, protocol-v4 markers, and collision/exact-round-trip regressions are implemented. U+2028/U+2029 also remain single-line and round-trip exactly.
Sections 06–08 are superseded historical designs; sections 09–11 describe current implementation.Channel entries pass the actual sender’sspeaker_id and speaker_display independently of content and routingpeer_id into persisted nodes. Content retains the [Display name (id)] compatibility prefix, but writers/retrieval never infer new-record identity from content.
SourceRecord.speaker_label generates canonical labels uniformly. Writer serializes every turn into one compact JSON object on one physical line, with ref, speaker, content as separate fields. Prompts recognize onlyspeaker and never parse labels incontent. New sources write only fixed-marker-prefixed_v2/ files. Speaker IDs use canonical UTF-8 percent encoding validated by round trip;record-lines isolates forgeable content. Parsing stops on invalid frames, and only markers in valid v2 frames are trusted. Valid markerless records remain speakerless. BM25 v8 filters by stable ID, display name, or label in combination with path/date filters; results come only fromsources/.memory_search exposesspeaker; combining embeddings and speaker explicitly returnsINVALID_ARGUMENT rather than ignoring the filter.
Local Web entries and local CLI turns started through dispatcher explicitly persistowner/local. Paired channels retain their channel-provided stable speaker IDs. Historical nodes and old framed records lacking trusted fields remain speakerless. Only unframed legacy records strictly headeduser may use limited historical-prefix retrieval compatibility. Legacy archives are frozen and excluded from v2 deduplication. Valid v2 events for the same source ID take precedence in retrieval, linking, and validation; absent v2, legacy remains readable. speaker_trusted is true only for trusted v2 markers; pending, legacy hints, and speakerless records are false. Regressions cover Markdown trailing double spaces, CRLF/final newlines, complete forged blocks, truncation stops, old-cache rebuilding, and independent-process imports.
Before any directory or file change, archival rejects the entire batch for NFC/casefold-equivalent provider/thread path collisions. memory_search source results use real#source-... anchors and show the calling agent speaker_trusted, speaker_id andspeaker_display.
Branch-aware written-node markers are also implemented. Migration of legacyruntime.json’scursors reads validated legacy headers and strict valid v2 prefixes, merges node markers per session, then deletes old fields. It never extracts IDs from body content or after invalid tails.
