Return to the previous browsing location

Folder A → subfolder B → file 1 → file 2. Back retraces previous locations; Forward restores later ones. Opening a different location after Back replaces forward history. Folders restore paths, expansion, and scroll positions; files retain existing autosave behavior.

Loading another list page, background refresh, and file-size updates preserve the viewport. Only explicit user positioning, search navigation, or navigation restoration may change browsing position.

Implementation status and boundaries

Navigation/scroll stability and preserving session routes while opening files passed functional review, quality review, and complete verification. Retain the latest 100 locations per current project, within the current window only. Reuse existing tabs/navigation; do not modify disk files, add polling, or mix navigation history with file-version History.

Actual targets and reuse options for common formats

Text, code, Markdown: preview, source editing, autosave. DOCX, PPTX, XLSX: complete local-engine preview/editing, verified by real-file open, modification, export, and reopen; text extraction cannot replace page/slide previews. Include DOC/PPT/XLS and ODT/ODS/ODP compatibility tests; conversion-only engines explicitly save a new format rather than overwrite originals. CSV/TSV offer at least table preview and text editing. PDF: pages, zoom, search; annotations/editing only as actually supported. PNG/JPEG/WebP/BMP/GIF/SVG/TIFF: preview; static bitmaps offer crop, rotate, annotation, while ordinary save must not silently rasterize animation/vector content. Unified opening, editing, and version protocol

File references carry stable project/session ownership and relative paths; display paths are not credentials. Capability detection verifies extension, type, and contents before choosing adapters. Adapters receive only document content/version, not arbitrary disk access, and expose bytes/Blob export, change/error events, and destroy. Large Office/image resources load only for relevant files, without slowing initial chat.

Human edits and model writes share version validation, complete-file publication, and immutable before/after storage. Existing project_file_write idempotency records hold results/fingerprints, not recoverable versions; this adds actual version storage. Human records use actor=user; model records link real session/turn, without fabricated chat turns or human history becoming sidebar sessions. History aggregates by file while model turn Review retains attribution.

Retain versions by ownership: human project edits belong to projects; model records retain actual sessions/turns. Aggregate indexes reference existing versions without duplicating source documents. Archived sessions remain readable; permanent deletion removes their entries/owned versions under existing rules, and caches must not redisplay originals. Residual Memory sources show “Original session deleted” or lose links, without source copies. Project files and independent human history survive deletion of individual chats.

Autosave and version archival are separate. Editor undo handles immediate changes. Drafts persist first; modified files publish after a short coalescing window. History groups continuous editing periods, approximately five minutes apart; switching documents, ending editing, or recovery also closes periods. File saves do not wait five minutes. Each publication validates the read revision; retries are idempotent and out-of-order responses cannot overwrite newer drafts. Save failures retain drafts and retryable errors. Restart reads persisted records, never reconstructing past versions from current files.

Rich-editor lifecycles are independent of tabs. Hide views on switching while exporting engines stay alive; release engines only after newest content reaches durable drafts. Office iframes do not recreate within a document session because React remounts or DOM moves. Close, rename, and recovery await final export; failure retains editor/draft. Preview/edit reuse one instance; read-only history instances cannot write current files.

Paper reading and annotations

The upstream viewer stylesheet is scoped to the PDF reader, including its root variables. Generic names such as .sidebar cannot change the surrounding application shell.

The PDF workspace follows the compact reading layout in the supplied PDF Expert reference: the existing OpenProgram document tab stays above a flat toolbar, a collapsible left sidebar contains thumbnails and the document outline, and the remaining space shows continuous PDF pages. Reading controls provide page navigation, fit-width/fit-page and numeric zoom, text selection, in-document links and highlighted search results. Only implemented Reading and Annotate tools appear; original-text editing, OCR, page surgery and format conversion are outside this iteration.

The visual system inherits OpenProgram's typography and light/dark tokens: neutral toolbar surfaces, white paper, dark reading background, subdued dividers and one blue selection accent. Reference palette: ink #202124, toolbar #27272a, canvas #151517, paper #ffffff, divider #414145 and focus #4a90e2. Toolbar labels use the application font at 13px; controls are 32px high. Desktop uses a single reading toolbar with a contextual annotation row; narrow panels wrap controls without covering document text. The sidebar is 180px wide and removable. The implementation uses actual rendered pages, with no placeholder content or decorative dashboard elements.

Use the already pinned PDF.js 6.3.289 legacy viewer library, text layer, link service, find controller and annotation editor. Retain its local module/worker compatibility and production CSP. The upstream viewer source defines the lifecycle and editor APIs. PDF Expert's Mac feature reference establishes the reading and annotation comparison. The alternative EmbedPDF viewer is not adopted for this iteration: replacing the decoder and introducing a second rendering engine is unnecessary for the requested reading, highlight and text-note capabilities.

Copying a selection in the PDF text layer joins layout line breaks automatically. Preserve paragraph breaks and literal punctuation, join CJK text without inserted spaces, preserve ordinary hyphens and remove discretionary soft hyphens. This is a local clipboard transform; it never edits the PDF or applies to search fields, annotation text editors or other application content. A visible checkbox allows the reader to keep original line breaks.

Project PDFs support highlight and free-text note annotations through PDF.js. Save standard PDF annotations back through the existing DocumentController rich-editor lease, durable draft store and optimistic revision checks. Debounced export, explicit save, close, history restore and rename use the same controller ownership as Office/raster documents. Draft-byte updates must not recreate a live viewer or lose its undo stack. History snapshots and attachments remain read-only. No PDF-supplied scripting or external document upload is enabled; original bytes, input and canvas limits, errors and download remain available.

Acceptance uses actual FileViewer/DocumentWindow entries under production CSP and desktop-compatible APIs. Verify continuous nonblank pages and selectable text, clipboard payload including prose/CJK/paragraph cases, page/sidebar/outline/zoom/search behavior, readonly history/attachments, highlight and note creation, save and close/reopen using real PDF bytes, persisted annotations through a separate decoder, failure retention and no obsolete editor publication. Existing file/history/controller, complete Web, repository contracts, browser and documentation checks remain required, followed by both independent reviews and installed-App inspection.

PDF runtime compatibility

The local PDF decoder is pinned to PDF.js 6.3.289. Its main module and worker use the matching legacy/build distribution, served at the existing same-origin /document-assets/pdfjs/ URLs. The upstream browser support guidance and package README prescribe this distribution for environments missing recent JavaScript APIs. The modern build requires Uint8Array.prototype.toHex, which the desktop's Electron 37 / Chromium 138 runtime lacks. The legacy pair supplies upstream compatibility code in both execution contexts; a main-page-only polyfill cannot repair the worker.

Keep the reviewed decoder version, local CMaps, fonts, WASM, license inventory, lazy loading, 64 MiB input bound, canvas bounds, disabled scripting and original-file download. Do not upgrade Electron or add application-owned global polyfills for this repair. The generated manifest identifies both the version and build distribution. Read-only PDF capabilities do not change.

The application shell permits connect-src 'self' blob: so decoders can read retained local file versions through their object URLs. This only extends local byte reads; external HTTP/WebSocket destinations remain blocked, and blob scripts, eval, objects and third-party frames are not enabled. PDF acceptance applies the actual shell policy to the test page, including a rejected external-fetch probe. A permissive standalone browser harness does not establish installed-App behavior.

Acceptance uses the public FileViewer entry to render nonblank pages, navigate, zoom, search text, recover from invalid input, and close/reopen without runtime errors. Run the same checks without native toHex and Math.sumPrecise in the main page and worker, plus an installed-desktop check with the reported PDF. The asset manifest must identify the exact staged module and worker bytes. These checks supplement the full Web, repository-contract, browser and documentation gates.

Optional Office installation

Office document support is an optional local component shared by presentations, word-processing documents and spreadsheets. Default App, runtime and Python builds omit its assets and do not download them. Opening an unsupported Office document checks local availability only. If missing, the document surface explains the supported formats, approximately 699 MiB download, local processing and ONLYOFFICE license, and offers Install and Cancel. Cancel dismisses the installation choice without downloading; the user may choose again. PDF viewing remains independent.

Only an owner-authenticated, local-origin POST initiates installation from a fixed release URL and pinned archive SHA-256. The installer bounds downloads and extraction, rejects unsafe archive paths and links, verifies the full existing Office manifest, and atomically publishes the pack to the profile cache. Concurrent requests share one installation. Failures retain the previous selected pack and remove temporary downloads. Once installed the current worker serves the parent module and isolated host without a restart, and the document opens automatically. Closing the document stops its UI requests; an explicitly requested installation may finish for other documents.

Previously installed profile resources remain usable. App-bundled resources from older releases are no longer selected. Development staging remains an explicit standalone command for editor tests; ordinary builds ignore stale staged packs. This change does not introduce a generic extension registry, automatic updates, uninstall controls or third-party document upload.

Office loading

Office startup keeps a full-size rendering surface beneath a centered, theme-aware loading overlay. The status follows the application language and distinguishes loading resources from opening the document. It uses no simulated percentage. Startup errors replace the status and expose an explicit retry.

The adapter uses the pinned upstream mount/activate API so closing a loading document immediately destroys its pending host. An AbortSignal cancels the availability request and pending activation; a bounded startup deadline begins before activation. Failed or cancelled instances never attach to the document controller. Preview/edit transitions preserve the existing editor and native undo. Independent Office origins, asset identity checks and persistence callbacks remain unchanged. This reduces unnecessary concurrent startup work; cold native conversion time is measured separately from the loading presentation.

Office loads pinned local resources from a separate origin allowing only resource-tree GET/HEAD, not main APIs, authentication, or WebSocket. Both pages validate origin, instance, and request; macros default off. Large resources install separately into local cache with user confirmation. Opening checks installation only, never downloads automatically. Remote deployments without a separate resource origin explicitly disable editing rather than redirect to third parties. PDF/images/media load on demand; the file window loads only when opened. KaTeX retains complete WOFF2 fonts without duplicate legacy WOFF/TTF fallbacks. Asset gates retain 2 MiB compressed initial transfer and 350 KiB compressed single-script limits.

Large binaries use bounded byte uploads or local staging, not ordinary chat messages. Enforce size while reading and clean temporary files on cancel; engine messages validate origin, instance, and request ID. Document scripts, macros, and active HTML/SVG gain no main-window authority. Third-party services require explicit user configuration and awareness that files are sent there. If safe original-format writes are unavailable, export a clearly labeled copy rather than writing PNG/OOXML bytes under another extension.

Read-only formats require actual rendering and explicit capabilities. Normal saves, failure retries, and old-version protection

Each before/after uses an independently complete version file. Persist content, verify it, persist the version directory, then publish the manifest. Failed manifest updates leave previously referenced content intact. Failed attempts never overwrite published versions. Only after explicitly cancelling an unsuccessful attempt may retry reread the current file as before; successful modifications always retain the turn’s initial before.

Prepared and committed records are separate. Incomplete writes retain pending-confirmation markers; projections show no exact recovery, never infer script success or invent after from current disk. Cancelled attempts confirmed uncommitted are not displayed as changes. Corrupt/unsupported manifests return explicit errors; only genuinely absent manifests mean no records. Old manifests/blob_ref remain readable without bulk rewrites.

DeepSeek and Codex source evidence

DeepSeek’s JSONL persistence uses synchronized temporary files, exclusive publication, and directory synchronization, distinguishing corrupt from missing records;session repair marks interrupted tools as outcome unknown instead of inventing success. Adopt both principles for version integrity/interruption state. Its fs-local provides target locking, version conditions, and text-write results, but not full-file undo/reapply or Office versioning. Retain OpenProgram recovery transactions; session-log recovery is not file recovery. Retain Codex exact-delta attribution without treating arbitrary Bash as exact edits.

Integrating new tools and excluded capabilities

Local generators uniformly call write(file_path, source_path=...) to publish complete files. Text tools retain write/edit/apply_patch and share checkpoint prepare/commit/abort. Model claims of success are insufficient; arbitrary Bash followed by directory scans cannot establish attribution. CheckpointStore owns state; Review/session summaries are projections, not duplicate version stores. Future Office semantic diffs read immutable versions without implementing undo. Remote stores require conditional writes and verifiable version IDs before claiming exact recovery.

Retain existing turn aggregation, session branches, and recovery transactions. Add no full-disk scans, polling, generic plugin registry, Office revision views, or remote storage. Lost history cannot be reconstructed. System crashes and external programs ignoring locks may still require manual recovery; preserve evidence and refuse uncertain overwrites rather than promising automatic recovery of every external edit.

Implementation and scope

Scripts write results to independent temporary files, then publish through existing write(file_path, source_path=...) . Specify exactly one of content/source_path. source_path is a local regular file subject to read permissions. Targets retain write authorization, read-baseline, and approval fingerprint checks. Both source/target fingerprints participate in approval waits and are rechecked before publication. Write a complete temporary file in the target directory, then replace; failures clean temporary files and preserve the target. Write raw bytes with before/after records, never text-convert documents. Identical source/target, directories, links, oversized or unreadable sources fail before modification. Source reads are capped at 64 MiB. Existing targets revalidate open handles, content, and paths under advisory locks. This serializes only cooperating writers, not external writes between final validation/replacement. Windows closes handles lacking delete sharing before replacement and revalidates again, without OS-level conditional-replacement guarantees.

Reference Codex TurnDiffTracker exact-delta checks and shell snapshot staging/verification/replacement; the latter stores shell environments, not document versions. Retain Codex explicit-edit attribution: generic Bash, background processes, and external editors do not automatically become exact turn changes. Scripts cannot overwrite final targets then append history afterward. Preserve text-write arguments, failures, rollback transactions, branch ownership, and durable session layout. Complete bytes restore document formats, images, and layout; no Word tracked changes or PPT visual diffs currently exist.

Establish read baselines first: models read originals, then generate staged versions. Binary reads return type/byte count, not garbled model output. New files require no prior read. Script-tool descriptions state this flow, without extra Save buttons, full-disk scans, or polling.

Acceptance uses registered write, reopened sessions, and public history operations: version DOCX/PPTX creation/overwrites; byte-identical undo/reapply; conflicts for external changes; failed writes preserve targets; existing text writes remain valid.

Cursor invariants

  • Cursors are valid only with identical originating snapshot, owner, query kind, filters, and sorting. Reject client-supplied offsets, path anchors, and cross-project tokens.
  • Snapshots retain stable candidate ordering or immutable revisions sufficient to reconstruct it. Later pages never rescan and mix new/deleted/reordered entries.
  • Snapshots may have capacity/TTL limits. Eviction/version changes explicitly return stale; clients reload initial results rather than silently continuing old cursors on latest lists.
  • Directories/search use their own cursors; Review lists and single-file diffs have separate noninterchangeable namespaces.

Workspace invariants

  • Snapshot creation fixes all uncommitted candidates at once, sorted by normalized relative path: staged, unstaged, untracked, rename/delete paths, preserving old/new path mappings.
  • Each candidate pins HEAD base, index blob, and worktree content identity/blob pair. Text diffs render only from that pair, never rerun current git diff on later requests as a substitute.
  • Before later pages or file diffs, reread status candidate vectors, index-tree identity, and target no-follow worktree identity. Any addition, deletion, status, mode, index blob, digest, or path-mapping change returns STALE_SNAPSHOT.
  • Snapshot content blobs share Review quotas; missing, oversized, or expired blobs return stale/unavailable, never approximating old diffs from current worktrees.

Idempotency invariants

  • Owner is the authorized profile/project. Canonical payload uses normalized root-relative paths, operation parameters, and content digests, excluding request_id and idempotency_key. Precondition fingerprints include expected mtime/digest, source/target paths, overwrite conditions, and affected-directory versions.
  • Servers atomically claim (owner, action, idempotency_key) in the same durable scope as mutations. A different fingerprint for the same record key returns IDEMPOTENCY_KEY_CONFLICT with zero file writes.
  • Same-fingerprint in-flight retries bind existing operation_id and wait until the current request deadline. If unfinished, return IN_PROGRESS and operation ID. Clients may retry only that key, never submit another write.
  • Durable records retain canonical terminal results. Every same-fingerprint retry replays results even with different request_id, without reexecuting mutations. Restart first recovers or classifies in-flight records before replay.
  • Retention covers client retry windows and worker recovery. Expiry never deletes in-flight records or interprets expired keys as successful replays with different fingerprints.

Performance, retention, security, compatibility
Turn finalize

Complexity depends only on committed changed paths, without workspace traversal. Persist summaries at finalize and return with transcripts.

Review loading

Server filters/stably sorts first; 100 files per page. Clients retain current/adjacent pages only. Selected-file batches contain at most 200 lines or 256 KiB with continuation.

Diff budget

Over-budget computation returns timeout metadata, without blocking Agent completion or approximating cross-turn diffs from before/current disk.

Snapshot pagination

Directory, project search, and Review categories/search/sort/opaque cursors bind one snapshot. Workspace/project changes make old pages stale for complete refresh, never mixed pages.

Request identity

Every file WS request has UUID request_id; changing files/projects cancels old requests. Late responses must also match owner, scope, snapshot revision, change set, blob pair.

Large restore plan

Thousands-file preflight is observable background work with paginated conflicts. Once APPLYING, it cannot cancel, only finish or transactionally roll back.

Recovery blobs

Use separate content-addressed storage, deduplicated by digest and restricted to local users, outside session Git. Default retention: latest 100 checkpoints and first baseline of each lineage.

GC visibility

Never collect pinned checkpoints, active tasks, unresolved conflicts, prepared/applying intents, or branch-referenced checkpoints. Other expired blobs show Review available / Code restore unavailable.

Secrets

Blobs stay outside logs, telemetry, model context. Session deletion cleans unreferenced blobs. External paths require explicit authorization at capture and recovery.

Read cache and drafts

Read cache: 64 entries / 16 MiB LRU. Durable dirty drafts: separate 32 entries / 8 MiB quota, never auto-evicted.

Legacy sessions

Legacy checkpoints allow read-only Review or explicit unavailable only. Without digest/recovery contracts, offer no new Undo/Rewind code modes or request_id-less compatibility entries.

TUI parity

/rewind Shows the same server plan before mode selection/confirmation; never directly invoke old rewind_to.

App/Web parity

Same plan/apply protocol and idempotent request IDs. UI renders canonical server impact without recomputation.

Line comments

Bind change-set ID, before/after blobs, side, hunk/line. Scope/branch/recovery changes mark comments stale; never send against another version.

Portable snapshot consistency

Regular-file snapshots compare descriptor metadata before and after reading, and path metadata before opening and after reading. Descriptor and path identity must agree on device and inode. Metadata from different operating-system APIs is not compared as if it had identical timestamp or mode representation. Either observation changing aborts publication; the path observation supplies the stored permission mode. Legacy migration opens staged files with writable handles on Windows before flushing data, while preserving the source until publication succeeds.
