Agentic 自递归保护

当前行为： agentic 函数在用户轮次中接收情境引导，同时保留按函数计数的递归深度上限作为确定性保护。
事实来源： openprogram/agentic_programming/function.py 和 openprogram/agentic_programming/runtime.py.
测试： tests/unit/programs/runtime/test_self_recursion_guard.py.
1 · 问题 2 · 引导 3 · 深度上限 4 · 源码符号 5 · 行为合同 6 · 边界

1. 问题

agentic 函数运行内部 Agent 循环。工具列表可能包含该函数自身，匹配的 docstring 会导致内部模型再次调用它。如果不加限制，重复直接调用可能造成无限同名递归。

2. 情境引导

openprogram/agentic_programming/runtime.py::_situational_prefix 生成英文用户轮次前缀，说明当前函数名，解释调用它会重新进入当前执行，并引导模型使用较低层工具。

  • 常规执行路径将前缀注入用户内容块的开头。
  • 独立执行的 fallback 从递归上下文取得最深层函数名，并应用相同前缀。
  • system prompt 保持独立。当前函数不会通过 self-deny 项隐藏；引导有明确主体，由模型决定不调用自身。

3. 深度上限

  • openprogram/agentic_programming/function.py::_MAX_AGENTIC_RECURSION_DEPTH 为 5。
  • _recursion_depth 是以函数名为键的上下文本地映射。
  • 同步与异步包装器增加当前函数的深度，超过限制时抛出 RecursionError ，并在以下代码块中重置上下文值： finally.
  • 深度上限对每个函数名独立计数。它防止直接 A → A 递归；A → B → A 等跨函数循环是已记录的剩余限制。

6. 边界与剩余工作

  • 引导不保证能力较弱的模型一定会在到达上限前停止。
  • 本机制未实现跨函数循环检测。
  • 保护不改变工具授权、session DAG 语义或统一 system-prefix 合同。
