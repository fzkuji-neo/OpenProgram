0. 现状复核（对照最新代码）

能力现状与本设计差距
execution_stream.v1已有 attempt_* / block_* / snapshot；块种类含 text、reasoning_summary、tool_arguments、refusal缺函数引用块（指向真实 node_id）、缺并行组；UI 仍用 preview_text/reasoning 拼接
DAG / tree_update工具调用挂在 LLM 节点子节点；TreeStep 递归画函数行树与节点内容未统一为「引用同一节点」；详情仍是 Reply/Reasoning 分区
顶层 chatmsg.blocks 有序；ThinkingStep / FunctionStep / Markdown 交织嵌套 LLM 未复用同一内容组件
providers.last_blocks关节点写入 metadata.blocks（thinking/text/tool）需升级为带稳定 block_id、tool_call_id→node_id、并行组与 attempt 边界的持久化序列
关于「是否必须新增工具事件」：不必重复传输工具参数/结果全文。执行树已有工具节点身份与状态时，流式协议只需在内容序列中插入 tool_ref（及可选 parallel_group）占位，携带 tool_call_id + node_id。参数/进度/结果只读树节点。若某路径尚未把 tool_call_id 打到代码节点，应补齐挂载，而不是在 stream 里再复制一份结果。
现有 tool_arguments 块适合「参数仍在生成」的瞬时预览；终态展示以树节点为准，避免双源真相。

1. 展开后如何排列

  • 正文直接 Markdown，无「LLM Reply」标题。
  • 思考摘要出现在实际发生的位置，默认可折叠；仅当模型返回可展示摘要时显示，不推测不补写。
  • 函数行出现在调用发起位置；展开看参数/进度/结果/错误（数据来自被引用节点）。
  • 函数之后的新正文接在函数行之后，不得并入前一段正文。
  • 内部签名等不作为聊天内容。
  • 「完整」= 全部可展示内容可访问；大工具结果可折叠/按需加载，但不能只留截断摘要却无法打开全文。

2. 执行树与节点内容的职责

视图用途
执行树调用关系、并行分支、运行状态、耗时、失败位置
节点内容该 LLM 节点内部按序发生的正文 / 思考 / 函数引用
  • 卡片折叠：名称、状态、耗时、短预览。
  • 卡片展开与右侧详情：同一 LlmNodeContent 组件，禁止两套逻辑。
  • 函数行 = 对真实执行节点的引用；点击定位树节点；禁止复制工具状态/结果。

3. 函数内部再调模型

  • 允许递归：函数展开后可见内层 LLM 的同一内容组件。
  • 默认：当前选中 LLM 展开；内部函数只显示摘要行；用户展开后再进子内容。
  • 深层用「在详情中查看」，避免缩进塌缩。
  • 展开状态按 node_id（+ block_id）持久在会话 UI 状态；流式更新不重置。
  • 普通代码函数：参数/状态/日志/返回值；仅当内部有模型调用才嵌套模型内容。

4. 并行函数

  • 同一次模型输出中并发的多个 tool_call → 一个 parallel_group 块。
  • 组内顺序 = 发起顺序，稳定；完成先后只改状态，不重排。
  • 各函数行独立更新；禁止因某函数先完成而挪到正文前。

5. 有序块协议（扩展 execution_stream.v1）

每个 LLM node_id 在每次 attempt 内维护有序 blocks[]。顺序由执行端确定；前端不得按 WS 到达时间猜测。

块 kind必要字段说明
textblock_id, content, statusMarkdown 正文；流式 delta
reasoning_summaryblock_id, content, status, retention可展示思考；策略可省略持久化
tool_refblock_id, tool_call_id, node_id, optional group_id引用树节点；不内嵌结果全文
tool_arguments（可保留）参数流式预览；终态以树为准
parallel_groupgroup_id, ordered tool_ref ids并行外壳；子引用保持发起序
attempt_boundaryattempt_id, reason, status失败重试边界；旧 attempt 折叠保留
refusal / unsupported已有保持

继续生成 vs 失败重试

  • 正常工具后继续：同一 attempt 内接着追加 text / tool_ref。
  • 失败重试：新 attempt；UI 显示边界；新输出不得拼到上一段半截 Markdown。
  • 重复事件：同一 tool_call_id 不生成第二行。
  • 工具节点晚到：先占位 tool_ref（稳定 id），再补齐树数据。

6. Markdown 流式与滚动

  • 复用顶层 chat 的 renderMarkdown / ThinkingStep / FunctionStep 视觉与安全策略。
  • 进行中的 text 块增量更新；已结束块不整段重渲。
  • 未闭合代码块/表格/链接不导致整区消失。
  • 大内容按块虚拟化或按需加载。
  • 贴底跟随；上滚停止跟随；展开函数/高亮完成尽量保阅读位置。
  • 「复制正文」≠「复制完整执行记录」（后者可含思考与工具参数）。

7. 断线 / 刷新 / 失败

  • 持久化有序块 + 函数引用（及 attempt 列表）；禁止仅存最终 reply 再靠树临时拼接。
  • 刷新后交织顺序与实时一致；已完成函数不得显示为执行中。
  • 未完成正文保留，并标明中断/取消/失败。
  • 未持久化的思考显示「此内容未保存」，不伪造空白成功。
  • 恢复用 snapshot，禁止为了显示再调模型。

8. 实现顺序

  1. 有序块协议 + 持久化：扩展 kind；tool_ref / parallel_group；metadata 与 checkpoint 写入完整 attempt.blocks。
  2. 统一内容组件 LlmNodeContent：复用 chat Markdown / 思考折叠 / 函数行（只读树）。
  3. 接入节点详情：去掉 Reply/Reasoning 分区；验证序列、刷新、恢复。
  4. 卡片展开复用同一组件。
  5. 并行、递归、重试边界、滚动验收。
任一阶段不得缩成「先拼两个字符串再慢慢加」——那会破坏顺序契约。

9. 验收场景（必须）

模型先输出 Markdown → 并行调用两个函数 → 其中一个函数内部再调模型（含 read_file）→ 外层继续输出；期间断线并刷新。恢复后：块顺序、函数状态、层级与断线前一致。

  • 无 Reply/Reasoning 标题栏。
  • 并行组内顺序不因完成先后重排。
  • 重试出现 attempt 边界，半截 Markdown 不拼接。
  • tool_ref 与树节点一一对应，无重复结果副本。
