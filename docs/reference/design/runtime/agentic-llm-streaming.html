Nested Agentic LLM streaming

Complete product design, not a spike. Goal: in the @agentic_function execution tree, provide llm() / runtime.exec(..., execution_kind="llm") with per-node, per-channel real-time token streams, covering ExecutionStrip cards, right-side details, collapsible thinking, cancellation, reconnection, parallel LLMs, and both in-process and subprocess paths.Define the contract first, then implement the same design in phases—consistent with the context-manager design philosophy.

1. End-to-end product behavior

1.1 ExecutionStrip cards (TreeStep · LLM rows)

  • Open node: an LLM row appears in the tree, running; the secondary note may still show a prompt summary (see §8 / §12).
  • tokens: the main content is a continuously growing reply preview (text channel). Thinking defaults to a collapsed “Thinking…” label or last-line summary, consistent with top-level ThinkingStep.
  • Close node: status becomes completed/error/cancelled; the note settles to → short(final) plus duration. Clear the stream buffer and return authority to tree-node output/raw_reply.
  • tree_update: still drives structure (child additions/removals and status changes); streamed text does not depend on the 1.2s poll and is driven by llm_delta.

1.2 Right-side details panel

  • Selecting a running LLM node: Prompt still reads params._content; Reply prioritizes the full FE buffer with scrolling, falling back to tree fields if no buffer exists.
  • After completion: Reply = persisted raw_reply/output; Thinking, if present, comes from metadata.blocks.

1.3 Multiple parallel LLMs

Multiple LLM children of one RuntimeBlock may run concurrently. Every node_id has an independent buffer and seq space; UI rows grow independently without overwriting each other.

1.4 Cancellation

User Stop / execution.cancel → node status=cancelled; retain generated partial text as visible, persisted output; clear the buffer; show a “Cancelled” badge and reject further deltas for that node.

1.5 Reconnection / refresh

  • After refresh, read the running LLM node’s throttled partial output from SessionDB (§5); the card immediately shows existing text and running state.
  • If the run remains active, WS recovery resumes new llm_delta / tree_update without requiring historical-delta replay.
  • If the worker died, streaming-resume’s abort sweep marks the node aborted; UI shows partial output and aborted.

1.6 In-process and subprocess

User experience is identical. Only backend bridging differs (§7). Mode detection is diagnostic/logging only and does not branch frontend logic.

All events remain within the existing top-level envelope:

2.3 Lifecycle events (optional, but adopted here)

EventWhenPurpose
llm_deltatokenOnly high-frequency path
tree_updateNode open/close, subtree changes, ~1.2s, forced flushStructure + terminal state + throttled partial-output mirror
Do not add llm_open/llm_close—Express opening/closing through DAG + tree_update to avoid races between two channels.

2.4 Ordering, coalescing, and backpressure

  • Ordering: for the same (node_id, channel), if seq is present, append by seq; otherwise use arrival order. Drop out-of-order lower seq values rather than reordering history.
  • Server coalescing: combine deltas within a 16–32ms window for the same node before broadcast (still one llm_delta with concatenated delta). Never coalesce across nodes or channels.
  • FE coalesce: reuse the top-level rAF strategy—Map<nodeId, PartialStream> writes occur immediately, while DOM/store stamps update at most once per frame.
  • Backpressure: bound the WS send queue (suggested: 512 frames per session). On overflow, discard intermediate text deltas first while retaining the latest snapshot frame (periodic full-snapshot llm_delta, using delta since the prior snapshot or a separate snapshot field). V1 skips intermediates on overflow but guarantees a complete final close tree. Thinking follows the same policy with more aggressive dropping.
  • Relationship to tree_update: deltas never write into the tree subtree. §5 throttles partial text into nodes, which the next tree_update then includes.

FE buffer lifecycle: create on the first llm_delta for node_id (or pre-create an empty buffer when a running exec node appears) → append on every delta → clear on terminal tree_update, cancellation, session unload, or node disappearance.

4. FE state architecture

4.1 Recommended store shape

// Alongside the existing Zustand session store, or as a new slice in it
type PartialStream = {
  text: string;
  thinking: string;
  lastSeqText?: number;
  lastSeqThinking?: number;
  updatedAt: number;
};

llmStreamsBySession: {
  [sessionId: string]: {
    // key = DAG node id (aligned with tree child.path / Call.id)
    [nodeId: string]: PartialStream;
  }
}
  • Do not write high-frequency deltas into message-row contextTree (avoid deep-cloning the entire tree).
  • TreeStep / DetailPanel reads buffers through (sessionId, node.path|id). With a buffer and running node, display streaming output; otherwise read note/raw_reply from tree fields.
  • Isolate this from top-level pendingDeltas (assistant reply): nested LLMs never write to reply.content.

4.2 TreeStep selection rules

Conditionnote / main preview
running ∧ text buffer existsPrimary: growing text (short tail or full scrollable text); prompt secondary (§8)
running ∧ no bufferKeep current behavior: parameter summary; optionally show “Generating…”
terminal ∧ output/raw_reply exists→ short(output) + duration (current logic)
terminal ∧ no text“No text output”
thinkingSeparate collapsible row or in-Step fold; running shows the last line, done the first line (aligned with ThinkingStep)

4.3 Clearing rules

  • Node tree status ∈ {completed, error, cancelled, interrupted, aborted}
  • or clearSessionByMsgId / session_loaded changes session
  • or RuntimeBlock unmounts with no running children
  • Before clearing, if the tree has no final output yet, backfill once from the buffer to avoid losing the last tokens in a race.

5. Persistence policy (decision within this design)

Decision (v1): each WS token is not written to the event log; DAG LLM nodes throttle partial writes of text to ~250ms. Thinking is throttled into metadata.streaming_thinking, folded into metadata.blocks on closure, and streaming fields are deleted. Terminal authority is _close_model_call_node.
  • Live authority: FE PartialStream (lowest latency).
  • Recoverable authority: throttled node output/raw_reply snapshots plus terminal full text.
  • Do not create child nodes or an append-only token table for every delta (non-goal).
  • At the same level as operations/streaming-resume alignment: placeholder + last_update_at; worker-restart abort sweeps also cover nested LLM nodes.

7. In-process vs Subprocess

In-process

Runtime.on_stream → wrap as llm_delta (fill current _active_llm_node_id)→ _broadcast_chat_response.

live_progress(..., on_event=None) directly broadcasts tree_update.

Subprocess (required for complete coverage)

The subprocess sends the same llm_delta envelope to mp.Queue; the parent drain thread on_event(env) → broadcasts through the existing placeholder/tree_update/goal_update bridge.

run_agentic_in_subprocess already has a queue; this design requires llm_delta to use the same bridge, never a direct subprocess WS connection.

Mode detection (diagnostics only)

  • Parent: process_runner checks whether this execution_id has a live Process.
  • Child: whether QueueTransport / a subprocess event_queue is installed.
  • Log field agentic_isolation: "inprocess"|"subprocess"; no frontend branching.

8. UI wording and behavior (default proposal)

  • Primary card content: while streaming, show growing reply (text); after completion, an → summary.
  • Prompt _content: remains secondary by default. While running without tokens, show a short prompt; after tokens arrive, reply takes precedence. Full prompt remains available in details.
  • Thinking: collapsed by default, titled “Thinking”; show the latest line while running; click to expand full text in details or an inline fold.
  • Do not copy nested LLM text into the outer assistant bubble.
See open question Q1 on pinning the prompt to the note’s left side. Use this default until decided.

9. Acceptance criteria (complete feature)

9.1 Manual

  1. A single llm() inside an agentic function: node opens → card grows token by token → closure matches raw_reply and removes the buffer.
  2. Dual thinking/text channels: thinking collapses while main text grows.
  3. Two parallel LLMs or consecutive loop calls: independent growing rows, no cross-contamination.
  4. Stop: deltas stop immediately; partial remains; status is cancelled.
  5. Mid-run refresh: partial is visible; new deltas resume if still running.
  6. Subprocess tools such as gui_agent provide the same UX as in-process execution.
  7. Details-panel Reply matches the card.

9.2 Suggested automation

  • Unit: envelope shape (node_id/channel/seq), lower out-of-order seq rejection, and no cross-node coalescing.
  • Unit: subprocess queue forwards llm_delta using mock Process/Queue.
  • Component: TreeStep running+PartialStream snapshot; terminal buffer clearing.
  • Contract: llm_delta in the chat-stream reducer does not contaminate reply.content.
  • Optional E2E: fake provider emits fixed deltas; assert DOM text.

10. Non-goals (v1)

  • Token-level audit logs or replayable delta recordings.
  • Changing top-level chat stream_event.text semantics or complete TUI parity (TUI may later read and ignore llm_delta).
  • Per-field streaming highlights for structured output.
  • Multimodal image deltas.
  • Cross-session LLM stream subscriptions.
  • Replacing tree_update with llm_delta.

11. Implementation phases (ordered delivery of one complete design, not a minimal release followed by reconsideration)

  1. Protocol and backend emission: in the _active_llm_node_id context, Runtime converts on_stream to llm_delta; add broadcast helpers and envelope unit tests.
  2. Subprocess bridge: confirm queue forwarding, add isolation-mode diagnostics, and test both paths.
  3. Throttled persistence: partial output/thinking on running nodes, including close-race tests.
  4. FE store + chat-stream: llmStreams slice, reducer, clearing rules, and no reply contamination.
  5. TreeStep + Detail: selection rules, thinking fold, and styling.
  6. Cancellation/reconnection/parallelism: complete §6 and §1 behavior and sign off the manual checklist.
  7. Documentation and check scripts: mark this page adopted; use check-*.mjs to preserve UI contracts where necessary.
No phase may unilaterally narrow product semantics, such as deferring subprocess support or persistence, which would turn it into a spike. Change this design before code if semantics must change.

12. Open questions (user decisions required · at most four)

Q1 · How prominent should the prompt be in the card note?

A) Reply fully replaces prompt after tokens arrive (default) B) Keep a short prompt on the left and reply on the right C) Show only reply while running; prompt only in details

Q2 · Should thinking expand by default?

A) Collapsed by default (default) B) Expand while running, collapse on completion C) Remember the user’s last choice

Q3 · Should partial persistence include thinking?

A) Throttle both text and thinking to 250ms (default) B) Persist text only; thinking only in terminal blocks C) Persist no partials, only terminal output (harms reconnection; not recommended)

Q4 · msg_id reference when a model-called agentic function is attached to an assistant reply?

A) Always use the runtime placeholder-row ID, consistent with current tree_update for display=runtime (default) B) Use the outer assistant msg_id and distinguish by node_id C) Include both msg_id+runtime_id fields

Choices are recorded in localStorage under key op.design.llmStream.decisions for review comparison, not as a formal vote.
