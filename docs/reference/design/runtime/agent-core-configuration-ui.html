3. Session and workspace contracts

Workspace

Editable persistent files

Show the full path, purpose, last modification time and open action. The workspace is the agent’s default working directory and instruction source; it is not presented as a security sandbox.

Sessions

Independent execution history

The settings page shows only count, storage usage and an Open sessions action. Messages, DAG and retries remain on the Chats page.

Reset

Affects future routing only

Changing scope or reset does not migrate, merge or delete existing sessions. New messages select a session under the new policy; old sessions remain viewable.

Delete

Irrecoverable directory deletion

Deletion confirmation shows the Agent ID, workspace path and session count. The default agent cannot be deleted; failure must not partially update the default pointer.

5. Minimum API contract

6. Acceptance criteria

  1. Agent ID is read-only after creation; Display name and Channel identity can be edited independently.
  2. Model choices come strictly from the selected Provider; credentials are managed only in Provider settings.
  3. System prompt and workspace files are displayed and saved separately, with explicit context sources.
  4. The isolation semantics of the four session scopes exactly match existing Runtime enums.
  5. Changing session policy does not migrate or delete history.
  6. Deletion confirmation lists workspace and session effects; the default agent cannot be deleted directly.
  7. All failures retain unsaved input; a success toast cannot substitute for field errors.
