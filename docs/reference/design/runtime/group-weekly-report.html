Group weekly report: scope, evidence and recovery

group_weekly_report(task) is an independent Workflow package under the weekly-report category. It prepares local drafts from supplied materials or bounded, read-only native WeChat collection. It cannot send messages, edit a message composer or change access permissions.

Request and scope

Structured input specifies source, mode, week, group, ordered members and optional materials/output_dir. Complete structured input requires no interpretation. Natural input uses the existing structured-output contract with bounded repair and inherits the Runtime deployment timeout. Natural-language extraction has no tools and uses only the supplied request. It preserves material bodies and explicit authors, leaving anonymous authors empty. A separate scope lookup runs only when the source group or ordered roster is missing. Its input contains only those two scope fields and retrieved scope evidence, never report bodies, nicknames or author-assignment requests. Read-only memory and file tools remain available for scope source verification. Its output can update only group and members; week is parsed from the explicit request or current context and is never inferred from old records. Complete scope with anonymous material proceeds directly to clarification. The lookup stops when scope is established or evidence is unavailable or conflicting; it does not seek material authors in workflow source, tests or diagnostic artifacts. Recall is evidence rather than instructions. Explicit user scope wins, and old progress is not substituted for current-week material.

Missing information

Validate scope before native access or output creation. Missing group, roster, week or material authors uses the existing ask_user transport. Preserve the request, original supplied text and source identities across clarification. A clarification can update scope and author metadata, never replace material bodies. Anonymous materials are not assigned by position unless the user explicitly establishes that correspondence.

Questions use the current execution's question transport and cancellation handling; no second input queue is introduced. At most two clarification rounds run per invocation. No answer or noninteractive execution returns WAITING_USER with a question and resume_task. A model-format or provider failure propagates its typed exception and retains the pending answer and request as in-process recovery diagnostics; these attributes are not a persisted App recovery protocol. Explicit cancellation returns CANCELLED without collection or delivery. Invalid types, oversized inputs and malformed materials remain validation failures. Existing collection/compose/delivery checkpoints retain their original scope.

Collection and output

Supplied and native sources remain distinct. Native collection verifies the selected group and records screenshots/OCR evidence where required. Unsupported access saves a checkpoint and waits using the existing transport; an answer alone does not establish that access has recovered. The adapter exposes bounded search, exact selection and history scrolling, not arbitrary input or message sending. Native history coverage remains partial.

Code verifies member identity, week, source IDs, explicit supersession and citations. Report bodies, uncertainty and negation remain intact. Per-member source context is bounded; no fixed aggregate model-call, token or elapsed-time quota is imposed. Local outputs include summary.md, sources.json, coverage.json, an optional reminder and immutable checkpoints. Output failures preserve a resumable request/checkpoint without expanding filesystem permissions.

Design basis and exclusions

This adapts the repository's existing Workflow ask_user, Runtime transport, structured-output repair, source validation and checkpoint primitives. It does not claim that Codex or Claude supplies a group-report implementation. It adds no messaging capability, automatic publication, new permission mode, new queue or inferred author identity. Memory can establish a roster; it cannot prove current-week progress or that a message was sent.

Acceptance

  • The public package entry receives six anonymous supplied reports: code extracts supplied material without tools, looks up missing group/roster without exposing those bodies to retrieval, asks for missing metadata, retains all six bodies and continues after a valid answer.
  • No answer preserves the request and a concrete question for resumption; no native collection or output occurs first.
  • Metadata answers cannot overwrite supplied bodies, introduce unknown source IDs or bypass validation.
  • A complete structured request retains its deterministic path. Cancellation and model-format failure preserve their distinct outcomes.
  • Package tests isolate HOME, memory and providers. Native access requires separate live acceptance and is not established by mocked tests.

Implementation status

Supplied-material extraction, isolated scope lookup and existing checkpoint recovery are present in the package. Week values use YYYY-Www or remain empty when unknown. Every extracted material contains nonempty text and a member field that may be empty; materials is required even when the array is empty. Schema validation rejects body aliases and malformed week values before collection. Package regressions and independent reviews cover these contracts. Actual anonymous-input acceptance preserves all six supplied texts and asks only for missing author attribution; explicitly attributed test data produces a complete local draft. Native WeChat collection and external delivery are outside this acceptance. Current installation and release evidence is recorded separately in the task handoff.
