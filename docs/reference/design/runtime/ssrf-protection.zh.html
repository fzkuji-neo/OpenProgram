Hermes共享 url_safety 覆盖 Web、浏览器、vision 和 gateway media。DNS 失败关闭；拒绝 loopback、RFC1918、link-local、CGNAT、metadata、reserved、multicast 和 unspecified 结果；逐跳检查重定向；URL 脱敏，媒体流式处理且有限额。进程级 allow_private_urls 开关同时放宽多个入口。应用检查仍不能替代操作系统网络隔离。采用共享失败关闭验证、完整地址集、重定向检查、脱敏与限额。将全局开关改为精确使用方范围内的服务 origin 例外。
OpenClaw默认拒绝私有、内部和特殊用途目标，支持精确/通配 hostname 例外，并在导航、交互引发加载及最终 URL 处检查。文档指出推测导航和浏览器子资源风险。官方文档说明请求拦截不是网络防火墙：重定向、popup、Service Worker 和后台资源仍可能需要出站隔离或策略代理。采用严格默认值和显式例外。浏览器拦截作为独立验收边界，不计为 Runtime fetch 证据。
Claude CodeWebFetch(domain:...) 支持 allow/deny。请求前将 hostname 发到 Anthropic 安全阻止列表，结果缓存精确五分钟；owner 可禁用 preflight。Bash 沙箱使用子进程继承的 Seatbelt/bubblewrap HTTP/SOCKS 代理。代理信任客户端 hostname 且不检查 TLS 内容，因此宽泛域名和 domain fronting 仍有风险。采用分层工具授权和子进程出站策略；不将 hostname 权限视为 DNS/IP/连接时 SSRF 证据。
Codex审计的主线不以一条 WebFetch 字符串检查替代网络边界。codex-network-proxy 提供 HTTP/SOCKS5 代理、精确/受限通配域、私网解析拒绝、有限只读方法、MITM header hook、Unix socket 控制和结构化审计；操作系统沙箱限制 loopback 绕过。采用结构化拒绝原因、审计和托管策略；保留了解使用方的 Runtime 安全客户端，不只依赖子进程代理。
CodeBuddy 2.109.3WebFetch 应用安全中心域名策略，拒绝 IP 字面值、 localhost和部分私有范围。企业微信媒体使用官方 CDN allowlist，禁用重定向。沙箱 allowedDomains 与 WebFetch 权限取交集。审计 bundle 的普通 WebFetch 只检查 host 字面值；快照未确认完整 hostname A/AAAA、peer 绑定或逐跳重定向约束。采用固定 channel 服务 allowlist 和权限/网络策略交集；拒绝普通 fetch 仅保护 IP 字面值。
Gemini CLI官方工具文档警告 web_fetch 能访问 localhost/私网；Plan Mode 可要求确认。本地 0.35.3 core 含 IP 分类与 DNS 工具，但该警告表明它们不构成通用 WebFetch 私网边界。用户确认是权限决策，不限制实际连接 peer。采用明确风险文档；拒绝以确认替代确定性目标约束。
OpenCodewebfetch 权限使用完整请求 URL，支持 allow、ask、deny。当前官方权限文档不能证明私网 IP 分类、完整 DNS、逐跳重定向或 peer 绑定。shell 使用主机用户网络权限；官方说明字符串规则是尽力处理，不是网络隔离。采用统一资源权限语义；获准 URL 仍必须通过独立传输策略。
pi-mono固定快照未确认核心产品内置任意 URL fetch；网络能力主要来自 shell、安装器或用户扩展。核心快照未确认 OS 出站策略；第三方 pi-sandbox 不计为内置 pi-mono 行为。不作为 Runtime SSRF 算法参考；扩展边界支持将第三方代码排除在安全客户端完成范围外。
pi-ai这是协议参考源码，不是可运行产品，没有 session 或 Runtime URL 使用方。不适用。排除产品级 SSRF 结论，但保留矩阵列以维护审计单位区别。
weclaw固定快照是到外部 ACP/CLI Agent 的消息桥接，未确认独立通用 URL fetch。主要继承启动 CLI 的工具和网络权限；不将受委托产品的控制重复算给 weclaw。保留 channel media 和外部进程启动作为相关边界；不作为通用安全 HTTP 参考。
cc-internal / cx-internal / gm-internalcc-internal 和 cx-internal 包装上游启动器； gm-internal 大量复用 Gemini CLI。审计包未确认独立加强通用 URL fetch 策略。继承大部分 Claude Code、Codex 或 Gemini CLI 的权限和网络行为。增加认证或 endpoint 本身不构成 SSRF 边界。仅审计其新增 endpoint、凭据转发和配置差异；不重复计算为三个独立安全设计。
OWASP区分已知服务 allowlist 与任意公共目标验证，限制协议，验证全部 A/AAAA，可信服务优先使用 allowlist。单次 DNS preflight 仍有 DNS pinning 和检查/使用时差风险，因此也建议网络控制。采用独立信任类别和连接时 peer 约束；拒绝只靠单个 preflight DNS 结果。

04采用、调整与拒绝的选择

决策机制原因
采用一个纯 URL/IP 策略；全部 DNS 地址通过；DNS 失败关闭；每次重定向重新判断；错误只含 origin；限制解码正文统一覆盖 Runtime 的目标、重定向、凭据与资源边界。
采用区分不可信公共、固定公共服务、配置服务及 loopback 回调四种信任类别保留 owner 配置的 localhost/私网服务可用性，不给任意公共使用方私网权限。
采用Claude Code/CodeBuddy 权限与网络分层、Codex 结构化拒绝原因、CodeBuddy 固定 channel media allowlist权限回答谁可请求资源；传输策略回答哪个 peer 接收连接与凭据。
调整Hermes 进程级 allow_private_urls替换为精确使用方加规范 origin 或规范私有/本地 CIDR；metadata 和 link-local 仍不可例外。
调整OpenClaw 浏览器拦截与 Codex 全进程出站代理浏览器控制保持独立门禁；策略代理是可选、owner 声明、独立 peer 约束且 doctor 可见，不允许直接 fallback。
拒绝仅 URL 字符串检查、单次 DNS preflight、隐式重定向、继承环境代理、禁用 TLS 验证或原始客户端 fallback每项都留下目标、重绑定、凭据或绕过路径。
拒绝以用户确认或 hostname allow/deny 实现目标约束两者均不验证全部解析地址，也不约束连接 peer。
拒绝对所有 HTTP 客户端实施仅公共目标规则这会破坏显式配置的本地模型 endpoint、MCP server 和内网服务。
拒绝将 Origin/Host、CORS、owner 认证、浏览器检查或沙箱网络算作 Runtime SSRF 完成这些控制保护不同方向或执行边界。

05.1 传输与策略行为

  • 公共请求仅允许注册表声明的方法、scheme 和 port；全部地址必须为 global，显式拒绝 metadata、loopback、private、link-local、CGNAT、multicast、reserved、unspecified、文档/测试、映射、歧义和无效目标。
  • 同步与异步 httpcore backend 只连接批准的 IP 元组，验证实际 socket peer，保留规范 hostname 用于 HTTP Host、TLS SNI 与证书验证。连接池身份包含使用方、信任类别、规范 origin、批准 IP 和代理身份。
  • 手动重定向且每跳重新决策；跨 origin 配置服务重定向失败，公共请求凭据被移除，拒绝 URL userinfo；日志/公开错误不含 query、fragment、token 路径、cookie 或 peer 控制正文。
  • 限制 header、MIME、content encoding、解码字节、connect/read/write/pool/overall 超时和临时文件生命周期。下载仅在完整验证、flush、 fsync及可安全清理的完成之后替换目标。

05.3 Owner 例外、策略代理、doctor 和清单

Owner 配置只接受注册使用方加一个规范 origin 或规范私有/本地 CIDR。拒绝通配、后缀、凭据、未知字段、公共/默认路由网段、metadata、link-local 和使用方不允许的例外形式。既有 owner 认证设置路径是唯一变更权限。

只有 owner 配置设置 enforces_target_policy: true才可用策略代理。Runtime 先判断目标，独立约束代理 peer，通过 doctor/audit 报告委托，绝不直接重试。
