Persistence failure observability

Baseline:4f8649d1. Scope is limited to DAG entry append and exit update for agentic/traced functions.

Selected approach. The DAG records execution; it is not a success condition for user functions. Append/update failures remain best-effort and must not change the return value or original exception. However, a local logger must emit one structured warning with a traceback so disk, permission and serialization errors are diagnosable.

01 · Contract

StageFailure semanticsDiagnostic fields
entry / store.appendDo not abort the function; execute it normally.phase=entry, node id, exception type, traceback.
exit / store.updateDo not override the function return value or its own exception.phase=exit, node id, exception type, traceback.
No store / hiddenRemain a silent no-op.Do not log a warning.

02 · Trust boundaries and tradeoffs

  • Logs do not include separate fields for function arguments, output or exception messages; the logger traceback preserves the local root cause.
  • Reuse the module logger and the two existing shared helpers; do not duplicate catches in sync/async/traced wrappers.
  • Do not add diagnostics to WebSocket messages or function results, or introduce event types, retries, queues or persistence fallbacks.
  • Catch only Exception; cancellation and process-level BaseException must not be downgraded to best-effort.

03 · Acceptance

ScenarioAssertion
Entry append raises an exceptionThe decorated function still returns its original result; exactly one warning includes entry, node id, exception type and traceback.
Exit update raises an exceptionThe decorated function still returns its original result; exactly one warning includes exit, node id, exception type and traceback.
The function itself raises and exit update failsThe caller receives the original function exception, which must not be overridden by a persistence exception.
hidden / no storeNo persistence warning.

04 · Exclusions

Do not change the DAG schema, SessionStore, wrapper lifecycle, usage context, tool registration, Windows, credential store or orphan files.
