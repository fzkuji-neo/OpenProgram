Agent configuration framework

The Agents page manages runnable agents' identities, models, instructions, capability scope and session policies. Programs, Skills and MCP remain independent entity catalogs; an Agent stores only references and access policies, not copies of entity content.

1. Three responsibility layers

Global entities

Programs / Skills / MCP

Capability entities that exist in the system and can be installed, edited or connected.

  • Entity source, schema, connection status and versions
  • Managed through their respective global pages
  • Do not store a particular Agent's model or session settings
Agent configuration

Agents

Which model, instructions, capabilities and session boundaries an Agent uses.

  • Stores entity references and access rules
  • Creates independent workspace and sessions directories
  • Edit sections within one page and save together
Conversation override

Current session

Overrides only this session without changing persistent Agent configuration.

  • Temporary model, thinking effort or tool scope
  • Explicitly indicates inherited from Agent or overridden
  • New sessions reload Agent configuration
Boundary:Agent configuration does not store schemas for 120 tools, copy Skill bodies or store MCP credentials. Runtime resolves currently available entities from Agent rules; invalid references are marked in the page but never silently deleted.

3. Whole-page prototype

This prototype establishes page hierarchy, creation entry, six sections, save state and lifecycle actions. Production must not create another page-window system: the topManagePageHeader contains only the page title and New / Save actions. New inserts a name input, Cancel and Confirm at the top of the left Agent list, without a backdrop or requiring an Agent ID. The backend generates a unique stable internal ID from the name. The six tabs belong to the current Agent and use the existingTabs component below its title on the right. The split layout and list reusesplitBody andManageRow; right-hand details reuse Settings'pageHeader andpageBody. Production also reuses global typography: body text, fields and buttons use--fs-base, while supporting descriptions use--fs-sm. Reduced prototype fonts used to fit the whole page must not be copied into production CSS; monospace is reserved for explicit metadata such as paths and IDs.

4. Page states and failures

Editing

Local draft

Any field change displays Unsaved changes; switching Agents or leaving prompts Save or Discard. Save requests send changed fields only.

Conflict

Version conflict

If another window updates configuration, reject overwriting and show Reload / Review changes. If the initial backend lacks a version field, add an optimistic-concurrency contract first.

Missing reference

Missing entity

Deleted Programs, Skills or MCP services display Missing without automatically removing references; cleanup requires a user-confirmed save.

8. Framework acceptance contract

  1. The Agents page has one clear creation entry; all six sections can be configured after successful creation.
  2. Overview, Model & Instructions, Programs, Skills, MCP and Sessions use the same Agent ID and persistent version rather than separate configuration objects.
  3. Programs, Skills and MCP entities remain managed globally; the Agent page stores references and policies only.
  4. Complete entity schemas, Skill bodies and MCP credentials are not written into Agent context; Runtime resolves them on demand.
  5. Default Agent, invalid references, unsaved changes, save failures and concurrent conflicts have separate visible states.
  6. Deletion confirmation explicitly states that configuration, workspace and sessions are permanently deleted and prevents direct deletion of the current default Agent.
  7. Arrow Left/Right, Home and End switch tabs; focus, save state and errors remain accessible.
  8. Narrow screens still support selecting Agents, switching tabs and completing forms without hover.
