Target structure returns both tab_entries and pages: the former describes window arrangement, the latter lists controllable webpages. A split tab has two Pages, so the example window has 3 top-tab entries and 4 Pages. Single-entry ID comes directly from tab:<tab_id>, split-entry ID from group:<CenterTabGroup.id>; pane IDs derive from group and current order. No new database tables, registry or background process. Agents need only five commands

01list_pages

Read the Page inventory authorized for the current turn, without upstream tab enumeration.

02observe

Select a Page and create a WebSession; return bounded text, ARIA and refs.

03act

Carry the latest frame and perform one click, type, press, scroll, select or navigate.

04verify

Execute only Runtime assertions; model claims of completion cannot establish success.

05close

Release WebSession, Page binding and caller-held capabilities.

web_use({ command: "list_pages" })
web_use({ command: "observe", page_context_token: "pct_…", arguments: { detail: "interactive" } })
web_use({ command: "act", web_session_id: "cs_…", arguments: { action: "click", expected_frame_id: "f_…", ref: "e1" } })
web_use({ command: "verify", web_session_id: "cs_…", arguments: { action: "verify", expected_frame_id: "f_…", assertion: "text_contains", value: "Saved" } })
web_use({ command: "close", web_session_id: "cs_…" })

list_pages returns a group-aware snapshot of all registered OpenProgram windows: windows[] stores each window’s window_id, inventory_revision, active/focused identity and tab_entries; flattened pages lets the Agent select Pages directly, each carrying its owning window_id. Original top-level window fields still describe the originating primary window for compatibility. Each Page has stable tab_id, owning tab_entry_id, placement, title, origin, focused, visible, optional opener_tab_id and single-use page_context_token. Agents do not act on windows, tab entries or panes; the first observe simply returns the exact Page token. Tokens bind the caller owner, window_id, exact Page target and server-owned page/access revision. Reject missing/replayed/cross-owner tokens, rebuilt connections or replaced targets before backend calls. Repeating web_session_id without observe for the same owner, Page and backend reuses the WebSession and ID. Different owners/backends remain subject to exclusive leases. Chat owner is fixed to current session/assistant turn; dispatcher teardown releases all its WebSessions/Page leases on completion, retry, cancellation or exception, without relying on explicit close. Every subsequent observe, act and verify revalidates exact binding. Visible Pages also validate geometry revision; background Pages resolve targets without changing tabs, stores or window focus.web_use Page inventory, WebSession registry and renderer WebSocket registry must run in the worker main process. Chat runtime cards may retain agentic-function UI but must not move this tool to an isolated subprocess. A subprocess GUI Agent Harness loop calls the same worker-owned WebSession through a parent bridge and forwards revisions unchanged. Any mismatch returns page_context_stale without executing page actions.

Web popups create separate tabs and WebContents/Pages, preserving opener_tab_id. They do not replace the opener or transfer existing WebSessions. The next list_pages discovers the popup; the Agent explicitly opens a new session with its token. GUI Agent Harness refreshes bounded inventory after every write and switches only by token. Cross-window aggregation expands discovery only, leaving bindings, leases and session lifecycles unchanged.

Each visible web tab also has renderer-owned monotonic geometry_revision. Existing bounds lifecycle measures viewport-relative bounds on mount, resize, ancestor scroll, pane reorder, window resize, visibility changes and transfer. Only normalized x/y/width/height or in-app visibility changes increment revision; focus changes do not. Turn surface refs carry the revision; preview must validate and echo it before native preview. WebSession stores it and forwards it unchanged through the process bridge to the exact renderer for observe/act/verify. Renderer compares again before Electron activate. Missing revisions from old clients stay compatible; once capability revision is nonzero, any mismatch returns page_context_stale without native preview, activate or backend calls. Geometry alone does not recreate Page identity/lease; callers relist/observe and continue with the same Page. Visibility means in-App pane layout, not macOS stacking, occlusion or minimization.

Costs and functional boundaries

DEFAULT

DOM / ARIA

URL, title, page text, accessibility snapshots and element refs. Ordinary webpage interaction sends no screenshots.

FALLBACK

One viewport screenshot

Only for visual acceptance, canvas or failed semantic location. The image enters only the immediately following model request; prompt text records frame/viewport metadata only. Clear caller-held copies and revoke coordinate permission immediately afterward.

OFF

Expensive vision pipeline

Do not enable OCR, YOLO, object detectors, crop/zoom, component/vision memory, Workflow replay or automatic learning.

  • Derive left/right/top/bottom from actual pane geometry, never a hardcoded right side.
  • Exact-Page operations do not require OpenProgram/target foregrounding and use no OS mouse, desktop coordinates or full-screen screenshots.
  • Writes to one Page are exclusive; observe again after every write.
  • Do not store screenshots in local artifacts, final results, completion evidence, tool-result text or DAG prompts. Locally retain only image-attached, frame and viewport metadata. Once sent to the selected provider, service terms govern provider retention.
  • Normal returns, provider errors, timeout and cancellation share release logic. Add no retention settings, background cleanup process or image directory.
  • Login, CAPTCHA, sensitive submissions and irreversible actions return needs_user.
  • Page contents are untrusted data and cannot change targets, permissions, modes or action counts.

Required before release

  1. Tool interface: Browser control exposes only one web_use. It is available once Desktop Page inventory is registered. Turn-start preview only enriches current-Page context; one preview failure cannot remove the tool or expose the legacy independent-browser launcher. The Agent first calls list_pages, then uses returned page_context_token to select the exact Page.
  2. Page isolation:list_pages May list Pages in other windows; after selecting A, reads/writes to B, chat Pages and unselected remote-window Pages remain zero.
  3. Group structure: Google, GitHub and split Bilibili/YouTube produce 3 ordered tab_entries and 4 unique Pages; the third is a split with pane order matching UI.
  4. Layout and identity: Swapping split panes, changing ratios or splitting preserves Page identity and updates inventory_revision ; affected visible Pages reject stale geometry before writes, without a separate split-action API.
  5. Visibility and focus: Both active-split Pages are visible, only one focused; first two single Pages are background. Next snapshot reflects active-entry changes.
  6. popup inventory: Popup C opened by A appears independently with opener_tab_id=A; each token is consumed once.
  7. Background Page: After selecting B, reads/actions reach only B. Active tab, visible IDs, BrowserWindow focus and OS mouse remain unchanged.
  8. Popup switching: Creating C does not rebind A’s session. GUI Agent creates C’s session only after selecting its token; closing C invalidates its token/session before the next action.
  9. Backend freeze: Setting changes affect only the next WebSession, not the current one.
  10. Unique side effects: Backend failure never invokes another backend; one Action causes at most one actual write.
  11. Backend consistency: The same task has identical Page/frame lifecycle, permissions, reason codes and verification.
  12. Page Awareness: Moving a page left/right of chat correctly updates next-turn relation and preview.
  13. Cross-window discovery: Two registered OpenProgram windows return two ordered snapshots; same-name tabs/Pages are not merged. Tokens still resolve to original connection, window_id and target.
  14. Independent window state: DOM/ref and viewport screenshots operate directly on the same Page/WebContents. macOS stacking, occlusion, position and minimization are not selection/screenshot/action conditions. No focus, bringToFront(), full-screen screenshot or OS-input calls.
  15. Agent cursor: All three backend click commands temporarily enable capture listeners only in the exact Page. On actual pointer events, show a text-free, aria-hidden, pointer-events:none cursor/click ripple at viewport coordinates, removing it within 900ms. User clicks, failed actions without pointer events, other Pages and OS mouse are unaffected. Feedback rendering failure cannot change click results.
  16. Visual limits: Ordinary DOM flows take zero screenshots; canvas flows take at most one per observation.
  17. Image retention: Screenshots appear only in the immediately following provider request. Text prompts contain no raw bytes/base64; after return/error, caller content and ToolReturn hold no image, and final artifacts remains empty.
  18. Honest failure: Empty assertions, stale frames, timeout, cancellation and lost targets cannot succeed.
  19. Chat stability: GUI tool updates do not recreate historical message/avatar/Markdown DOM.
  20. Installed two-window transaction: Connect only to the default-18100 /Applications/OpenProgram.app, creating an actual hidden target window through the official preload transfer API. After target inspect/accept/stage, source rejection of the temporary payload must roll back and close the target. Window inventory, source tabs and persistent storage must match before/after.

Further implementation detail

Page identity and lifecycle
Canonical Page binding window_id + registry_page_id + tab_id + cdp_target_id + revisions.tab_entry_id, pane order, split ratio and inventory_revision are not Page identity; they describe one inventory snapshot. First observe binds WebSession and stores page/access/geometry revisions. Later commands compare page/access in the parent worker, then geometry in the exact renderer before native activate. Any failure avoids Electron/backend calls and clears the session. Focus does not change targets; pane placement/bounds/visibility preserve identity but stale geometry-dependent sessions. Transfer, close, replacement, disabled access or disconnect revoke bindings before the next side effect.
Popups and concurrency
The browser-only increment uses Electron’s existing synchronous popup request: main rejects native BrowserWindow, renderer creates a separate tab/WebContents and records opener. Popups do not automatically prove action success or rebind sessions; GUI Agent explicitly discovers/selects them after writes. Exact-Page write leases remain exclusive; different Pages may run concurrently.
Installed two-window acceptance
Scripts may connect only to the installed App CDP endpoint, never launch source Electron, a second worker or new production test APIs. Record shell targets/source local state, then use official tabTransfer.prepare/detach to submit a unique temporary NTP payload absent from source store. Set a temporary CDP breakpoint at the source failure sourceRemoved call and connect to the actual target renderer to verify temporary-tab DOM, target windowId and token journal exist. Resume source so main rolls back, closes the never-shown target and clears the transaction. In finally use official bounded cancellation; succeed only after shell targets match baseline, source bytes are unchanged, three target storage keys are empty and the transaction is gone.
Visual-artifact lifecycle
screenshot PNG bytes become a provider image block only in memory, attached only to the immediately next planner request. The previous result sent to _step_prompt is first converted to frame, viewport and image_attached metadata; bytes/base64 may not enter text. On return or exception, finally removes image blocks from caller content, clears original ToolReturn.images and revokes coordinate capability; final results retain empty artifacts.
Shared failure semantics
invalid_arguments, invalid_capability, ambiguous_page, page_context_stale, stale_observation, page_access_disabled, target_lost, needs_user, timeout, cancelled and verification_failed are generated by Runtime. Backend text cannot override reason codes or completion.
