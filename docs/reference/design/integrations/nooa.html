Design scope

Agent defines reusable model configuration. Context defines parent inheritance, named content, dynamic evaluation, and history visibility.

The framework manages execution context automatically. Applications can call agent() or ordinary Agent methods without manual Context construction.

All entries reuse Runtime, AgentSpec, tool policy, execution control, and Session DAG. An Agent configuration does not own a default conversation.

Public usage

Direct call

from openprogram import agent

answer = agent("Analyze this paper",
               model="configured-model")

Use the current execution session; create one independent execution when no outer execution exists.

Reuse an Agent

from openprogram import Agent

bot = Agent(model="configured-model")
first = bot("Investigate this topic")
second = bot(first)

No subclass is required. The instance reuses configuration; execution scope determines history continuity. Independent top-level calls on the same instance do not share history by default.

Define a class

class Researcher(Agent):
    model = "configured-model"

    def research(self, question):
        text = self.prepare(question)
        return self(text)

    def prepare(self, text):
        return text.strip()

result = Researcher().research("A topic")

Write ordinary methods without per-method decorators; research and prepare are recorded. self(...) uses the same Agent execution core.

Lowercase agent() is a convenient call entry; uppercase Agent is a configurable callable class. Both delegate to one internal execution function. No process-global default Bot stores history. Construction resolves configuration only, without a model request or persistent session. The first execution resolves the session and opens the call.

Synchronous entry points serve synchronous code. The asynchronous forms are await bot.arun(...) and await agent_async(...). Calls inside an active event loop use the asynchronous entry.

Invocation ancestry determines inheritance and visibility; predecessor determines conversation order. Context is a runtime construction object, without a requirement to copy or persist each complete intermediate value. Existing session persistence and Trace export remain separate from Agent context ownership.

Execution ownership belongs to Agent calls, registered public Program entries, and ordinary top-level functions in owner-authorized external sources. Framework helpers inherit an active writer and call; when neither a public entry nor a caller owns execution, they run without creating a standalone Session. Inside an active call they retain their full DAG ancestry. Structural calls remain available through the raw DAG view, but do not add chat messages, conversation branch tips, or advance HEAD. Actual model and tool interactions retain their existing conversation behavior.

The behavior-test host initializes the standard SessionStore before applying the OS sandbox. The test runner binds its existing SessionNodeWriter through Context; Agent calls reuse it. Candidate tests cannot spawn processes, write the source snapshot, access host secrets, or use the network. Cancellation closes the canonical execution; unresolved external effects remain available for inspection. The exact assistant projection retries through the durable DAG outbox when its node or storage is unavailable. A display projection failure does not reject an applied cancellation. Cancelling a paused continuation error replaces its error display with cancelled, clears error metadata, and preserves recorded content. Resource-release observer failures remain visible to the control caller. Normal Job completion retains its result-bearing projection owner. Cancellation notifications do not publish other terminal Job rows before that owner supplies result and error fields.

Ordinary function capture

def research(question):
    data = prepare(question)
    return analyze(data)

def prepare(question):
    return question.strip()

def analyze(data):
    return agent(data)

The managed Program loader captures source-defined functions in explicitly authorized package roots, including their submodules and nested definitions. It preserves signatures, return values, exceptions, and imports.

Agent subclasses capture ordinary instance, static, and class methods, including names that start with one underscore. Dunder methods and generators are excluded. Recorded private helpers do not become tools.

Agent methods and managed Agent methods share scope handling without duplicate capture. Entry registration and tool exposure remain explicit.

Arbitrary host files, dependency packages, lambdas, dynamically generated code, and unavailable source do not receive automatic source capture. Their agent() calls still work, but full ordinary-function ancestry requires a managed Program package or an Agent subclass.

One Context model

Context has a parent, named content, dynamic providers, and history visibility rules. Every model request uses this model.

PartBehavior
ParentA child inherits the current execution context. Scope exit restores the parent binding.
ContentNamed values provide instructions and business data. A child can override a name without modifying its parent.
EvaluationPython providers receive the current Context. They run when the framework constructs a model request.
VisibilityExisting Session DAG rules select permitted interactions by branch, call scope, expose, and render_range.

Instance binding is a special case of named content. Agent configuration contributes content when the invocation derives its Context. The Agent instance does not own a default execution session.

parent Context + Agent configuration + call content
    → derive current Context
    → evaluate named content and select visible DAG interactions
    → apply existing budget and compaction
    → Runtime.exec model request

History selection and content replacement are separate operations. Equal text does not identify the same interaction. The framework records selected DAG identities at the actual request.

Context does not provide a second history database or a second provider runtime. Tool authorization remains independent of history visibility.

Explicit event lifetime

Context(store=writer, head_id=None) binds an existing SessionNodeWriter for repeated calls. The Context session continues model interactions using the existing Session DAG.

head_id selects an existing branch tip. With no explicit head, the invocation continues the current session head. The caller owns the supplied store.

This supplies NOOA-style instance event lifetime as an explicit Context binding. Agent configuration still does not implicitly own history.

Configuration and authority

SettingOwnership and precedence
model / effort / instructions / toolsExplicit call override → instance setting → class default → ambient session default → product default. Distinguish omission from explicit empty values.
expose / render_rangePreserve existing defaults. method_options or explicit function metadata supplies visibility settings.
tool visibility / approvalSeparate from DAG visibility; use existing tool registration, authorization and approval. Inner configuration cannot expand outer authority.
AgentSpec / sessionSaved Bot configuration reuses AgentSpec; execution scopes reference Session DAG; instances may configure Context content and sources. Constructing a Python object does not create a sidebar Bot or schedule.

Default context construction needs model interactions and necessary call relationships, not complete ordinary-function arguments, outputs or locals. Explicit model content still uses bounded serialization. Represent self by identity or type, not a whole object or client. Qualify method names by module and class to avoid collisions. Ordinary Python effects remain governed by host execution and sandbox rules; call recording is not per-operation approval of arbitrary Python.

Concurrency and failure

Bind current Context, call identity and effective configuration per task, restoring them on exit. Inheritance does not copy full history or share mutable branch configuration. Permit nested reentry; shared Agent configuration does not imply shared execution context. Explicit mutable instance content and shared sessions require defined synchronization and snapshot rules.

Errors, timeouts and cancellation restore the parent scope and preserve completed model-interaction state. Standalone calls reuse existing permission request context and noninteractive approval rules. Recovery uses existing safe points and explicit steps, without restoring arbitrary Python stacks.

Unified model and implementation contract

Context has a parent scope, named content, dynamic providers, and history visibility rules. Every request uses the same construction process. DAG supplies visible interactions and call relationships. Instance binding is a special case. It attaches named content to an instance and includes that content at invocation.

The public entries are Agent, Context, agent, and agent_async. Agent.__call__ is synchronous. Agent.arun is asynchronous. Ordinary Agent methods, including single-underscore helpers, create scopes automatically. A source loader handles ordinary functions in registered Programs. Application code requires no per-function decorator or manual Trace startup.

Context.current() returns the current binding. Context.derive() creates a child. Context supports named content, dynamic providers, and optional history filters. bind() publishes the selected task context and explicit writer. It rejects a conflicting ambient writer and restores bindings on exit. Dynamic providers receive the current Context and run during request construction. Providers are Python callables. The framework does not evaluate expression strings. Explicit instance content persists on that instance. Model interactions belong to the execution session.

CallScope manages call identity, ancestry, function documentation, terminal state, and Context lifetime. Agent methods and managed source entries share this component. New ordinary-function nodes need only structural information. Explicit capture_io, expose, and render_range retain their recording behavior. Automatic capture excludes generators. Generator creation must not appear as completed execution.

Requests use Runtime.exec and existing providers, tool authorization, budgets, and compaction. Without an outer execution, the entry owns an execution environment and releases it on exit. Shared model configuration or Agent identity does not imply shared history. Concurrent tasks derive separate contexts and retain explicit call identity.

The implementation contains Context, Runtime construction, shared call scopes, Agent entries, registered source capture, product documentation, and shipped migrations. NOOA Predict, CodeAct, and unchanged upstream API execution are separate from context-model equivalence.

Prioritize implementation as requested. Limit verification to public entry behavior, branch isolation, method behavior, and authorization. Implementation boundaries

The implementation reuses Session DAG, Runtime, AgentSpec, permission checks, budgets, and compaction. Shared call scopes handle both explicit method metadata and new automatic scopes.

Automatic source capture applies only to sources selected by the managed Program loader. Ordinary host files and dependency packages do not receive automatic function capture.

Entry registration and tool exposure remain explicit. A recorded private helper does not become a model tool. Generator creation does not produce a completed function record.

The public API and shipped migration must match the implemented loader and execution boundaries. Independent code review and affected checks determine the implementation status below.

Resumable function execution uses one durable function node ID across the initial call and continuation. Provider tool-call identity stays in node metadata. A continuation reuses that node and retains its original provider identity.

Removal of the decorator API

Agent and Context own the complete function execution contract. The removed public decorator has no compatibility adapter. Agent method_options preserves input metadata, Runtime injection, registration and schemas, availability, permissions, visibility, retry behavior, execution controls, and explicit-step recovery.

Managed sources declare PROGRAM_ENTRIES and __agent_options__. Internal modules import call_state.py. Methods carry the _is_agent_method marker. Existing execution node schemas and stored session history remain available.

First-party workflows, generated programs, scanners, dispatchers, and documentation use ordinary Agent classes. No replacement public decorator is introduced.

GUI, research, and wiki harness source migrations retain their agentics package paths. Build-time source patches in scripts/release/program-patches produce the staged packages. stage-program-source.py applies the source changes, and product-runtime.json verifies their checksums. This is a source build step, not a runtime compatibility adapter.

Six locally published workflows also receive isolated source migration and local integration. These local and packaged changes do not establish an upstream remote release.

The decorator removal and source migrations are implemented. Independent specification and quality reviews pass. Focused checks cover source loading, schemas, Runtime injection, permissions, cancellation, recovery, and distinct method identities. Deployment of local sources and the installed App is verified separately.
