Dependency security design

Scope: npm manifests and lockfiles, with a shared record for the parallel Python dependency workstream. The source and installed-App boundaries are recorded separately.

Current implementation and verified gap

The repository uses npm workspaces for apps/web, apps/desktop, and apps/cli. The Web application is an App Router application with output: "export"; its generated files are served by the Python worker. The desktop shell uses Electron and electron-builder. The root lockfile contains runtime, build, and optional dependency graphs for all workspaces.

The canonical Dependabot inventory at /tmp/openprogram-completion-audit/dependabot-open.json records 194 open alerts at the base: 154 npm alerts across 18 package names and 40 pip alerts across uv.lock. The npm baseline has 6 critical, 54 high, 78 medium, and 16 low alerts; 55 records are direct and 99 are transitive. The ignored report reports/content-security/npm-dependency-security-baseline.md records the exact advisories, ranges, versions, and commands. Range reconciliation treats comma-separated GitHub ranges as semver conjunctions and fails on parse errors.

Reference corpus and framework comparison

Fixed versions come from the GitHub advisory records and package registries. Registry metadata is checked with npm view before changing the lockfile. The selected framework versions require Node 22.12 or newer, so the root engine contract, CI bootstrap, and developer setup must use the same minimum.

Adopted, modified, and rejected choices

  • Adopt the advisory's first patched version or a later compatible stable release. Verify the resulting installed graph with both npm audit --json and the canonical inventory ranges.
  • Modify the direct framework upgrade to preserve the static export. Web and root React remain on the existing React 18 contract; the CLI keeps its existing React 19 contract. Only the Next compatibility files and Node engine contract change.
  • Reject npm audit fix --force as an implementation method because its result can choose unrelated major versions without compatibility evidence.
  • Reject dismissing alerts because the Web page is statically exported or a dependency is marked development-only. The complete declared graph is audited; applicability is recorded as evidence rather than used to suppress upgrades.
  • For extract-zip and legacy request, the inventory has no usable fixed release for some records. Trace every parent, remove the affected chain where possible, and record any remaining package-absent record with its parent chain and tested alternative.

Target architecture and boundaries

All package resolution goes through the root npm lockfile. Direct workspace manifests declare the supported framework and shell versions; nested package entries are accepted only when their parent package requires them. The build boundary is npm ci --ignore-scripts followed by workspace checks. The runtime boundary is the exported Web assets, Electron main/preload code, and the Python worker that serves those assets. Untrusted input must not be passed to package CLIs or archive extractors without the existing product validation.

Electron package resolution does not update an existing /Applications/OpenProgram.app by itself. The supported local path is to package the current checkout with the trusted runtime base, install the resulting app over the single default App, then run scripts/refresh-local-app.sh once. Verification must inspect the installed app's actual process.versions.electron; source-only checks do not establish the installed runtime version.

The Python dependency workstream owns uv.lock and records its host policy in the shared report: Intel macOS supports BM25, the optional embedding wheel is unavailable on Intel, and macOS arm64 embedding wheels require Python 3.14 or newer. The current verification host is macOS 15.7.3.

Security failures are handled as dependency-resolution failures: a clean install, audit, typecheck, build, or affected test failure blocks completion and is recorded with the exact command. Compatibility failures preserve the old manifest in Git until the minimum source adjustment is proven by the affected check. No remote write, release, installed-App refresh, or Python source edit is in this workstream.

Acceptance criteria

  1. At the final commit, every direct npm manifest version and every lockfile instance is outside each applicable fixed advisory range in the canonical inventory; no alert is dismissed or hidden.
  2. npm ci --ignore-scripts succeeds on the supported Node/npm engines, npm audit --json reports zero vulnerabilities, and the canonical range reconciliation reports no affected npm version. If an upstream no-patch advisory remains, the report names its parent chain, reason, and tested replacement.
  3. npm run build --workspace apps/web, npm run typecheck --workspace apps/cli, npm test --workspace apps/web, npm run check:web, npm run check:desktop, and npm run check:cli are run from a clean install. The final report distinguishes existing source failures from dependency-induced failures.
  4. The final diff contains only dependency manifests/lockfile, necessary Next/Electron compatibility source, the canonical design, and the ignored evidence rule. The worktree is clean after the scoped commit.

Full gate manifest

  • npm ci --ignore-scripts
  • npm audit --json and the canonical reconciliation script over the final lockfile
  • npm run build --workspace apps/web
  • npm run typecheck --workspace apps/cli and npm test --workspace apps/cli
  • npm test --workspace apps/web and npm run check:web
  • npm run check:desktop
  • git diff --check, manifest/lockfile consistency, and clean-worktree verification

Implementation status

The npm candidate uses Next 16.3.5, Electron 44.4.3, Fabric 7.4.0, and the fixed transitive graph recorded in the lockfile. Source checks cover static export, direct lint invocation, the native desktop surface, and the raster editor's crop, rotate, draw, annotation, save, undo, redo, and destroy paths. The Python section remains a coordination boundary for the separate uv.lock changes. Final audit counts, reconciliation output, and residual source-test failures belong in the ignored final ledger.
