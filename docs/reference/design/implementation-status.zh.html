准确理解实现状态

状态必要含义
已实现所述合同已有实现及要求的验证证据，必须明确已验证边界。
部分实现已有部分路径，但仍存在明确列出的实现或验收要求。
未实现设计规定了仍需实现的行为。
不在范围内该行为被当前设计排除，并非隐含实现任务。
未重新验证现有证据尚未对当前源码或目标环境核查，不得据此标记当前通过。

每份实现文档的内容

  1. 公开入口及其可观察行为。
  2. 源码负责位置和实现链接，包括兼容入口。
  3. 数据归属、状态转换及持久化边界。
  4. 适用时说明失败、取消和恢复行为。
  5. 可复现验证命令及各自检查的具体合同。
  6. 实现状态附录，列明剩余工作和验收缺口。

架构依据维护在主题设计中。实现记录聚焦源码映射和验证。迁移时间线及过往审查输出保留在 Git 历史，不在多个页面重复。
