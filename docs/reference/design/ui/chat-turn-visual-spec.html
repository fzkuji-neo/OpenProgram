Target mutation journal

1 · Before mutation

Before writing, direct-edit tools record canonical path, file type,before_digest , and a recoverable baseline. If a baseline cannot be saved safely, mark recoverability=unavailable, never “original file absent.”

2 · Commit mutation

After successful writes, record after_digest, operation, line counts, binary/large,turn_id and actor_id. Failures create no committed mutation.

3 · Persist summary

Turn finalize merges only this turn’s mutations, generating net file lists and addition/deletion statistics persisted with the transcript. Complexity depends only on changed paths, without cwd scans.

4 · Review on demand

Review reads summaries first, requesting one bounded diff only after file selection. Switching files cancels old requests. Chat DOM never mounts diffs.

Current logic that must be removed:agent_loop._snapshot_cwd, _walk_scan and _checkpoint_changed_files must no longer participate in file attribution. In particular, “over 5 MiB not staged → use nonexistent path → pre_existing=false” must disappear. Missing baselines mean unrecoverable, never newly created files.

Chat math delimiters

Chat markdown already stashes complete $$/$/\[/\( blocks before marked and restores them as escaped text after sanitize. The React bubble still has to run KaTeX: MarkdownText typesets after paint, and the chat-area pin path calls typesetMath on the observed message column. Unclosed streaming math is not a complete stash pair; the next paint with a closer typesets. Sanitize, code, links, and ordinary escapes stay as they were. No new math library.

Acceptance: the sample \(d_t\) / \(v_t = (d_t - d_{t+1}) / d_t\) produces KaTeX HTML on the assistant bubble; display \[/$$ and inline $ do too; prose without math and incomplete openers do not typeset; invalid math does not throw.

Assistant replies omit the token and service-tier usage footer. Only an execution segment containing the final content block may shimmer while the reply is running. Earlier segments remain static; a trailing text block stops execution-summary animation.

Bounded transcript history

The transcript uses bidirectional, byte-budgeted pages. A connection owns a small LRU of immutable disk-backed snapshots with message-ID indexes. A page request reads only its selected display groups, preserving tool descendants and compaction metadata. Snapshot tokens are scoped to the connection, session and captured branch head. Replaced snapshots and disconnected connections release temporary files.

The browser targets four cached conversations, allowing displayed panes and requests in flight to temporarily exceed that limit, and releases page references when conversations are deleted. Each conversation retains at most six ordinary pages and an 8 MiB content budget per loaded transcript, with an indivisible page allowed when needed to preserve a single large turn. Eviction occurs opposite the reading position, never deleting persisted records; active updates are retained. Scrolling back automatically retrieves evicted pages in either direction. Measured rows outside the viewport unmount, preserving their height. Heights of evicted rows are removed.

Prefetch distance follows scroll direction and speed with a bounded maximum. Only one page request runs at a time; failures retry with exponential backoff. Invisible panes stop requesting and stale responses cannot overwrite a newer generation. Page insertion and eviction restore the visible message and its offset before paint. Restoration uses a message ID rather than a pixel offset in an obsolete window. Jump to latest retrieves the latest window directly.

Acceptance uses a 300,000-message synthetic source: repeated bidirectional paging keeps cached pages, rendered rows and measurements bounded; rapid scrolling under latency preserves a visible message; stale replies, reconnect, branch changes and live updates cannot corrupt the window. Backend page reads must not scan or parse the full snapshot after indexing. Cold snapshot construction remains a separate measured operation.

Protocol v2 defers the full graph until its view is visible; ordinary branch metadata requests omit graph bodies. Cold snapshot construction reads and enriches the authoritative branch once. Subsequent indexed pages avoid full hydration.
