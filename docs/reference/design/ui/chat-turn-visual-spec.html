Chat turn visual specification

Message surfaces (no avatars, user bubble, edit box, action row), execution timeline (no outer frame, icons connected vertically, consistent rows), manual function runs, sub-agent parent/child branch navigation, file-change summaries and Review, and left-edge message navigation. All examples are interactive. This is the sole visual authority for chat turns; related implementations are in apps/web/components/chat/messages/ and app/styles/chat/.

2Timeline rows: circles indicate both expandability and open state

The left column retains type icons: filled Solar Bold Duotone glyphs (24×24), the same set as the composer; generic function rows use the sledgehammer. Colors indicate type:purple thinking / orange function / cyan LLM / green sub-agent. Dark and light modes each use clear, vivid type colors. Rows with direct child content always show a circular state:a uniform light solid circle when collapsed, a hollow ring when expanded, independent of hover. Collapsed circles have one uniform surface without separate center and rim. Mix 8% type color in light mode and 14% in dark mode with the page background to create an opaque color that fully covers the timeline behind it. An independent static outer ring is fixed at 2px, with outer diameters of 26px for main rows and 23px for children. The outer ring never transitions or animates; opening and closing change only the inner fill between matching color and page background. During expansion, the inner circle shrinks over 220ms to a 1.5px-wide, 12px-high vertical segment, moves downward from the center to the ring’s lower edge, and fades out to reveal the existing neutral timeline. Do not draw a second translucent line over it. Child content simultaneously uses 0fr→1fr, 220ms height, 140ms opacity, and -3px→0 translation. Collapse reverses these transitions exactly; repeated clicks reverse from current animation progress. Circle centers, outer diameters, and icon positions do not animate. Leaf rows have no circle. Add no arrows or descendant-step counts. 3Manual function runs: one FunctionInvocation, two input modes

The function form and complete function expression are two editors for the same FunctionInvocation { name, kwargs } . Clicking Run in the form submits typed kwargs directly. Entire composer text that exactly matches a registered function with named arguments is converted to the same object before creating a user message. Both create only the ProgramRun below, without UserBubble or an extra Agent text turn. Function fragments with surrounding prose, backticks, or code fences remain ordinary messages to avoid executing code under discussion.

Target mutation journal

1 · Before mutation

Before writing, direct-edit tools record canonical path, file type,before_digest , and a recoverable baseline. If a baseline cannot be saved safely, mark recoverability=unavailable, never “original file absent.”

2 · Commit mutation

After successful writes, record after_digest, operation, line counts, binary/large,turn_id and actor_id. Failures create no committed mutation.

3 · Persist summary

Turn finalize merges only this turn’s mutations, generating net file lists and addition/deletion statistics persisted with the transcript. Complexity depends only on changed paths, without cwd scans.

4 · Review on demand

Review reads summaries first, requesting one bounded diff only after file selection. Switching files cancels old requests. Chat DOM never mounts diffs.

Current logic that must be removed:agent_loop._snapshot_cwd, _walk_scan and _checkpoint_changed_files must no longer participate in file attribution. In particular, “over 5 MiB not staged → use nonexistent path → pre_existing=false” must disappear. Missing baselines mean unrecoverable, never newly created files.
