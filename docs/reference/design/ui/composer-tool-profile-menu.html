Composer Tool Profile Menu Design

Scope:ControlsCluster the submenu opened by the gear on the right of the Tools row. This page also serves as the task design, implementation brief and evidence ledger.

The submenu uses the installed Base UI Menu.SubmenuRoot, SubmenuTrigger, Portal and Positioner. React controls its open state. The gear responds only to clicks; moving the pointer away does not close it. Outside clicks, Escape, profile selection and closing the parent menu close it.

Current implementation and verified gap

The parent menu is mounted through Menu.Portal on document body; its positioner uses z-index: 200. The failed implementation places the submenu inside the composer as a position: fixed node and adds a transparent backdrop. The composer .inputArea itself is a z-index: 5 stacking context. Even with z-index: 9999, the submenu stays behind the parent menu in the body portal. This causes the overlap visible in the screenshot.

Target state and boundaries

State

  • profileMenuOpen is the only submenu open state.
  • Explicitly clear submenu state when the parent closes.
  • Profile selection continues using switchProfile.

DOM and ordering

  • Both menus use Base UI portals mounted on body.
  • The parent positioner is 200 and the submenu is 201.
  • Base UI handles anchoring, flipping and collisions.

Explicit exclusions

  • Do not change the Tools row toggle semantics.
  • Do not add dependencies or a global overlay manager.
  • Do not change profile data, the backend or other overlays.

No trust, privacy, concurrency or cancellation boundary is involved: this change controls local presentation only, without new persisted data or network requests.

The Tools visual row uses a role="none" container with two sibling, non-nested menuitems: the Tools Menu.Item and gear SubmenuTrigger. Mouse and keyboard can activate each independently. Tools toggles the setting and closes the profile menu; the gear only toggles the profile menu. Preserve the original layout: Tools label on the left, gear on the right, and the enabled checkmark at the far right. Preserve the 22px gear button, 14px icon and spacing before the checkmark. Base UI reports pointer moves over parent items with the sibling-open reason. This component ignores only that closing reason; Base UI still handles outside press, Escape, item press and parent closure.

Implementation brief and acceptance

Production file:apps/web/components/chat/composer/controls/controls-cluster.tsx, composer.module.css. Regression entry:npm run check:composer-tool-profile. Compatibility: the Tools row still toggles tools, profile items use the existing callback, and other parent menu items remain unchanged.

  • Click the gear to open the submenu; moving outside does not close it.
  • The entire submenu renders above the parent, unaffected by the composer stacking context.
  • Outside clicks, Escape, profile selection and parent closure all close the submenu.
  • Preserve the Tools row order: label · gear · checkmark, never label · checkmark · gear.
  • There is no longer a menuPosition, profileMenuBackdrop or manually computed fixed coordinates.
