Native page bounds in the built-in browser

The Electron shell DOM toolbar and native WebContentsView must maintain the same page bounds at any shell zoom factor.

Verified gaps

At a shell zoom factor of approximately 1.095 , the renderer sends x=812.63, width=518.64 CSS px, which the main process uses directly as DIP. Correct native bounds should be approximately x=890, width=568. The webpage consequently covers the left chat pane and leaves blank space on the right.

The old occlusion check hides every native Web pane whenever any role=dialog exists in the document. Local working-directory, project and permission menus at the bottom blank the neighboring webpage even when entirely inside the chat pane. Meanwhile, role=menu, role=listbox and several custom fullscreen confirmation overlays are not covered by the same rule.

Multiple split Web panes do not share a global visible flag. Each WebTabPane uses its own body bounds against the same set of current overlays. If a menu covers only the left Web pane, the right pane stays visible. Agent picture-in-picture previews reuse the same registerVisibleWebTabBounds / syncVisible path and publish only the small-window body rectangle, keeping toolbar buttons and the lower-right resize handle outside the native view. Existing MutationObserver, ResizeObserver and scroll/resize listeners republish bounds after overlays close, move or resize. During small-window dragging/resizing the renderer throttles calls to syncVisible to 100ms and publishes immediately on pointer release, avoiding per-frame IPC. Global flush still batches microtasks within the same tick.

Design

  • The renderer continues sending CSS px measured by getBoundingClientRect() .
  • Only at the renderer IPC boundary does the main process read event.sender.getZoomFactor(), convert CSS px into native DIP, then apply existing integer rounding and nonnegative dimension constraints.
  • sync-visible and the compatibility entry set-bounds use the same conversion. Internal show/hide/transfer paths already using DIP are not scaled again.
  • Shell zoom changes trigger the existing renderer resize listener to remeasure and send current bounds. The main process reads the current zoom factor on every IPC call.
  • Invalid or nonpositive zoom factors are treated as 1 .
  • A DOM overlay occludes the native WebContentsView only when its visible rectangle intersects the current Web body. Working-directory, project and permission menus inside the chat pane must not hide pages in neighboring splits. Dialogs, attachment previews and merge backdrops covering a webpage must still hide the native view; existing bounds observers restore it on close.

Boundaries and exclusions

Do not forcibly reset user zoom or change split ratios, DOM layout, preload APIs, site zoom, Browser Agent, dependencies or configuration. Electron WebContentsView.setBounds takes DIP while renderer DOM measurements use CSS px. The renderer retains measurement precision; the main process converts units and performs final rounding.

  • Public regressions must verify: a working-directory/project menu left of a nonintersecting right Web body leaves it visible; a menu/listbox intersecting one Web body hides only that pane; a fullscreen modal backdrop hides every intersecting pane; edge contact without overlapping area leaves it visible.
