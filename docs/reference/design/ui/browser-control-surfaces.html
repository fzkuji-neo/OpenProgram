Browser actions and task controls

The browser toolbar retains its address, navigation, reload, action markers, operation history, and preview controls. Pages have no separate pause or resume button. Conversation execution controls next to the composer own task pause and continuation.

Clicks, scrolling, and typing

Users and Agents may operate pages, including OpenProgram itself. Pointer, wheel, keyboard, edit, and navigation events do not change task state, request a pause, or create a page write prohibition. Legacy client page-input notifications are ignored.

Closing and recovery

Closing a page takes effect immediately without waiting for task pause. When a binding becomes unavailable, the browser tool first reacquires the original window and tab. An existing page is observed in its current state. Only an absent page is reopened at its last known URL. Recovery returns a fresh observation; it never replays the previous click or submission or selects an unrelated page. An unavailable connection is not proof that a page closed.

Task pause

Explicit conversation pause stops later generation and tool dispatch through execution control. Ownership, access, and frame validation remain enforced. Continuation observes current page state and is not subject to a second page-level permission.

Preview and status

The floating preview header offers Open page, More, and a Close preview X icon. Hiding retains the page and its session resource; Resources can reopen it. More contains a checked Automatically show the page the Agent is using item: checked follows the Agent-operated page, unchecked keeps the current page. It does not mean always-on-top or control Agent execution. The header has no pin or expand/shrink button. Dragging and edge resizing remain available, and legacy expanded geometry remains compatible. Operation history, action markers, and page lifecycle describe activity without controlling execution. Lost authentication and unsaved data are reported honestly.

Preview control acceptance

The existing X only hides the preview, the pin changes selection policy, and the diagonal arrows change its dimensions. Reuse the existing hide and follow functions without changing resource lifetime or session ownership. Verify header hide retains the page, Resources can reopen it, the More checkbox changes selection without execution-control requests, native and Web menus agree, and compact chrome retains eight-direction resizing.

Fixed preview viewport

The interactive preview renders a fixed 1920 × 1080 CSS-pixel desktop viewport. Resizing its container changes only presentation scale: min(available width / 1920, available height / 1080). Unused space remains blank. Page identity, DOM layout, scroll position, and Agent CSS coordinates are independent of preview size. Opening the same page in a normal tab disables the preview viewport override and restores the user's page zoom. Hiding a preview retains the Page.

Desktop uses Electron enableDeviceEmulation with fixed viewSize and variable scale. This replaces the previous width-derived browser zoom, whose 25% lower bound could change layout. A screenshot-only surface would lose direct native interaction and is not used. Browser iframe previews use the same fixed dimensions with a CSS transform; cross-origin embedding restrictions and separate iframe state remain unchanged. No resolution selector or desktop-wide emulation is introduced.

Renderer bounds are converted to native DIP before scaling. Native input uses Chromium's emulated-view mapping; Agent input remains in CSS coordinates. Action markers use the same fixed viewport and presentation scale. Owner checks and deferred transfer restoration remain in effect. Navigation reapplies preview geometry; cleanup restores ordinary pane behavior.
