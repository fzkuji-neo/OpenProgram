参考比较与决策

参考相关模型本设计决策
OpenProgram 注册表普通函数与 agentic 函数注册到统一 callable 接口，同时保留源码层元数据。采用统一运行目录；只在管理界面增加只读源码筛选。
Hermes toolsets命名 toolset 表达选择，不表达源码归属。工具 profile 与源码分类保持独立。
Claude Code官方仓库不公开产品内部工具实现树，因此可见界面不能证明源码布局合同。不复制无法验证的每工具一个目录假设。
OpenAI Codex公开工具实现同时使用 handler 文件和子模块。采用相同的按复杂度区分方式，不复制 Rust 专属命名。

采用：用途目录是普通 Python 包。只有一个实现文件的 Function 使用模块；含 provider、prompt、action、worker、共享状态或多个协作入口的 Function/子系统使用包。一个源码包可注册多个 callable，因此 agent 和 memory 等包保持完整。拒绝：强制每个 callable 一个目录、强制每份源码一个文件、纯前端分类、第二分类注册表、旧 import 路径上的兼容副本、原始源码文件浏览，以及在 Programs 中重复外部 MCP 工具。

行为、兼容性与失败

  • 浏览器惰性展开已安装目录层级，不在浏览器端编造分类路径。
  • 单一 callable 的模块或包直接渲染为注册 callable，不增加额外源码包装行。
  • 注册多个 callable 的包展开显示这些 callable 名称，同时保留同一共享源码边界。
  • 刷新 Programs 会重新扫描并加载同一浏览器接口。
  • 来源为 mcp 的条目不出现在 Programs；MCP Servers 是其唯一管理页面。
  • Agentic Function 使用公开 callable 名称；源码路径仅在可用时用于静态调用分析。
  • Workflows、Applications、收藏、聊天启动、调用树与图行为不变。

Application 函数调用

Application 视图每次请求读取当前包源码，从装饰的公开函数开始，跟踪本地函数调用和包 import，而不把仓库中每个 import 都当作执行边。测试、benchmark 和无关文件不进入图。

条件调用标注为条件关系，不作为固定执行顺序。既有树和图共享源码推导节点。报告无法解析的调用和分析限制；分析器绝不执行包代码来发现关系。页面打开时刷新分析。调用树初始展开前三层，显示能力函数并收起内部实现。分支行可通过点击、Enter 或 Space 切换。所选 Program 的展开状态在源码刷新后保留；叶子和重复引用没有开关。

直接函数回复与输入

手动调用的函数保留执行树，并在树下方独立 Markdown 正文中渲染已持久化最终答案；树收起后仍可见。不增加模型调用或持久对话节点。总结和接管说明保持可读；其他值使用文本或 JSON。嵌套调用保留当前展示。选中执行详情随状态更新而变化，无需打开侧栏。

空函数表单按可见字段决定大小。关闭的 Advanced 只计入摘要行，不计隐藏参数标签；仍可显式展开。回归与默认 App 检查验证这些展示合同。
