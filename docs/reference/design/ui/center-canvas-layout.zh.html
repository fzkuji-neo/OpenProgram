中间画布：任意分屏布局

把中间区域从「标签页 + 最多两格分屏」升级成一块可以随意切分的画布：左右、上下、四宫格、九宫格、十六宫格，或者不规则的组合都可以。本页上半部分是可以直接上手操作的原型，下半部分是数据模型、交互规则和实施计划。

原型怎么玩： 把顶部 tab 拖到某一格的边缘，就在那一侧切出新格；拖到格子中央，就替换这一格的内容（被换下来的内容回到 tab 栏）。拖动时 tab 本身跟着鼠标走，不透明，颜色介于当前 tab 和其他 tab 之间；拖到窗口外松手就是新开窗口。 拖格子的标题栏可以挪动整格，拖回 tab 栏就把它移出画布。（原型演示的是早期的画布内落点；App 里拖动改为窗口总览，见 3.1。）格子之间的缝隙可以拖动来调整大小，双击缝隙会把两边恢复成等分。 快捷键：⌘\ 向右切分，⌘⇧\ 向下切分，⌘⇧↩ 放大或还原当前格，⌘W 关闭当前格，⌥⌘←↑→↓ 在格子之间移动焦点。
预设布局
＋

1. 目标与边界

  • 任意数量、任意形状：格数不设硬上限，真正的限制是每格的最小尺寸（见 §4）。在 1440×900 的窗口里大约能放下 4×4。
  • 任何内容都能进格子：会话（chat）、网页、终端、文件预览、程序视图，都是同一种「格子内容」。
  • 布局就是一个 tab：多格画布在顶部 tab 栏里显示为一个布局 tab，上面画着格数徽标。原型里为了演示简化成「画布常驻，tab 栏放没进画布的内容」，真实产品里可以同时存在多个布局 tab，各自记住自己的切分方式。
  • 不做的事：不做浮动或重叠的窗口（那是画中画 PiP 已经覆盖的场景），也不做跨窗口共享同一格。

2. 数据模型：n 叉切分树

布局用一棵树表示。叶子是格子（pane），中间节点是切分（split）。一个切分节点可以有任意多个子节点，每个子节点带一个比例值。这样九宫格就是「一个纵向切分，下面挂三个横向切分，每个横向切分再挂三格」，不需要二叉树那样层层嵌套。

type LayoutNode =
  | { kind: "pane";  id: PaneId; content: TabRef | null }        // null = 空格
  | { kind: "split"; id: string; dir: "row" | "col";
      children: LayoutNode[]; sizes: number[] };                 // sizes 之和为 1

type CanvasLayout = {
  root: LayoutNode;
  focusedPaneId: PaneId;
  zoomedPaneId?: PaneId;          // 放大某一格时其余格不卸载，只是隐藏
};

每次修改之后都要做一遍规范化，这样树永远保持最简形状：

  • 只剩一个子节点的切分，用这个子节点替换掉它自己。
  • 方向和父节点相同的切分，把它的子节点直接并进父节点，比例相乘。所以连续向右切三次得到的是一层三等分，而不是三层嵌套。
  • 比例重新归一，并按最小尺寸夹紧。

这个模型取代现在 center-tab-groups.ts 里的 MAX_CENTER_TAB_GROUP_MEMBERS = 2 分组模型。旧的两格分组可以无损迁移：迁移后就是一个 row 切分下挂两个格子。

3. 交互规则

3.1 拖动时进入窗口总览

拖放走一个仿照 macOS 调度中心和 iPad 后台切换的窗口总览。标签被竖直拖出 tab 栏，或者格子顶部的「•••」把手开始移动时，中间区域退成页面底色，tab 栏里的每个窗口（单个标签，或一个分屏组）都缩成一张卡片，按网格排开，尽量放大，但不超过区域宽度的一半。卡片保持窗口自己的分屏：格子用和画布同一棵布局树、同一套几何计算画出来，每格显示它上次出现在屏幕上时的样子，三格合在一起就是一张三分屏卡片，不拆开显示。被拖的标签会从自己的卡片里拿掉，拿掉后没有标签的卡片不显示。

缩略图按标签存在内存和 IndexedDB 里，重启后还在（启动时标签列表暂时为空不会触发清理）：任何一次打开总览之前，先截下屏幕上的格子，被拖标签自己的格子也截（截图时它的浮动预览先隐藏）；切换窗口或改布局后停 900ms 再截一次；App 失去焦点或被隐藏时截一次；5 秒没有操作时每 30 秒再截一次，所以重启后看到的也是较新的画面。页面类格子走 window:capture-region IPC，只允许窗口自己的主页面截自己的区域，返回最宽 720px 的 JPEG；网页从它自己的视图截，所以不在屏幕上的网页也是最新的。网页视图里只有网页本身，不含上面 App 的工具栏，所以屏幕上的网页格子会先截整个格子区域，再把网页画进它的内容区（[data-web-frame]）；工具栏那一条会存下来（内存和 IndexedDB），之后网页不在屏幕上时也用它拼在网页截图上面，这样每张图都和格子的比例一致。卡片就是整个窗口缩小后的样子：卡片对应整个中间区域，单格窗口贴着中间卡片（1rem 圆角），分屏的每一格是自己的小卡片，在格位里缩进 1px（16px 圆角）。位置、缩进和圆角都按卡片自己的比例画，所以缩放只是等比缩放，落地时圆角和边都不会跳。截图前两帧会隐藏格子的「•••」把手，缩略图里只有内容。从没截到过的格子显示图标和标题。和调度中心一样，不专门标出当前窗口：用按钮或捏合打开时，当前窗口从它各格所在的位置缩进自己的卡片，其他卡片淡入；关闭时，卡片再放大回中间区域。缩放用 framer-motion 的布局动画实现：缩放中的卡片先放在窗口自己的位置（整个中间区域），framer-motion 用 340ms 把它移进网格里的位置，或者反过来移出去；这期间由一个占位块保住它在网格里的位置，卡片的其他布局变化都不做动画。点卡片会先切换到那个窗口再放大，卡片落位时底下已经是实时画面；按 Esc 或双指张开，则把当前窗口放大回去；点空白处没有反应。拖动时打开的总览以淡入出现，因为被拖的标签已经离开了它的卡片。合并的落点只有一次放大，而且在松手时就开始，不等合并提交：提交要先等桌面端取消转移（约 50ms），再渲染新的分屏（约 40ms），以前这约 90ms 里被拖的小窗已经消失、卡片却没变。松手时总览保持打开，记下这次落点和拖动的标签，并设置 landing；被放上去的卡片按原样显示那个窗口，从网格位置在 340 ms 内以统一比例放大到整个中间区域，和点选卡片一样，它是 transform 动画，等待期间照常播放。放大开始时，这个窗口就在总览下面被激活，和点选卡片一样，所以到它让出位置时，各个窗格已经挂载并加载好内容。commitCanvasDrop 把合并交给 landOverview，后者把落点标记为 landed 并先拿着合并不提交。卡片放大完成、合并也就绪后，总览读出放大后的卡片里每个窗格的位置，交给 captureCanvasLanding，然后关闭，关闭时在同一个 tick 里提交合并（兜底计时器或放大失败导致提前关闭时也会提交，只是没有动画）。app shell 像播放其他布局变化一样播放这次记录：窗口的各个窗格把真实几何从整个区域过渡到分屏里的位置，拖进来的标签按最终尺寸从放下的那一侧进入（平移出去，并用 clip-path 在画布边缘裁掉），时长同为 300 ms，所以两边的分界线一起移动，内容也不会重新换行。不会出现一半是静止截图、另一半在变化的情况，那样看起来像卡住了。合并失败（桌面端保留了这个标签）时总览直接关闭；落地播放期间不显示拖动提示。标签栏里分屏显示在它第一个窗格的标签所在位置，所以 dockCanvas 把并进来的标签挪到目标窗口前面（placeDockedTabs）：无论放在哪一侧，分屏都占着目标窗口原来的位置，不会跳到被拖标签原来的地方。分屏标签显示聚焦窗格的名字；聚焦窗格变化，或者刚合并成分屏时，图标和名字在 200ms 内上浮出现。被拖的标签一离开标签栏，它的槽位按宽度收拢（data-drag-out：flex-basis、宽度和左右内边距收到 0，并收回 8px 间距，沿用拖动自己的 160ms 过渡），后面的标签和 + 按钮随之左移；回到标签栏上方时槽位重新撑开。合并落点或移到别的窗口时槽位保持收拢，标签离开前不会闪回；只有标签留在原处时才重新撑开（拖动结束后由 data-slot-reopen 提供过渡）。被拖的标签同时展开成跟随指针的小窗：上面是它的标签，下面是它最近一次的画面，宽 240px，高按画布比例（110 到 190px），200ms 展开；拖回标签栏上方时收回成标签（140ms），再交还给真正的标签。从没截过图的标签保持标签样子，拖动途中拿到画面时再展开。指针下的卡片会稍微放大。

不拖动也能打开同一个总览：点 tab 栏右端主菜单左边的按钮，或者像 Safari 的标签总览那样，在中间区域或 tab 栏上双指捏合。点卡片切换到那个窗口，效果和点标签一样；按 Esc、双指张开或点总览以外的地方都会关闭；点卡片之间的空白处没有反应，浏览时底部也不显示提示（只有拖动时才显示，用来说明标签会落到哪里）。自己处理捏合缩放的内容（上下文图）会先拦下这个手势，不触发总览。网页是独立的原生视图，App 收不到它的滚轮事件：网页标签的会话里有一个预加载脚本（main/webtab-preload.js，在隔离环境里运行，不向网页暴露任何东西）监听真实的捏合滚轮事件，只在手势开始时网页处于正常大小（visualViewport.scale 为 1）时，请外壳打开总览。双指张开像 Safari 一样原生放大网页，每个网页标签允许 1× 到 3× 的视觉缩放；网页放大时双指捏合只把它缩回原大，再捏一次才打开总览。

拖动的视觉效果：被拖的 tab 就是那个元素本身，用 transform 跟着鼠标走，离开 tab 栏以后照样跟着，原来的位置留出空位。它完全不透明，背景色是 color-mix(in srgb, 当前tab色 50%, bg-tertiary)，外加一圈细边和一层阴影。落点的效果由 drop 预览框直接表达。

3.2 格子本身

  • 把手：格子没有标题栏。顶部正中一个 iPadOS 分屏式的「•••」把手，可点范围 88×22px，比三个点本身大。按下把手不会选中下面的文字。拖它挪动格子，规则同 3.1。指针移上去，把手从顶边垂下一小片灰色底片，两肩带弧度地接到顶边：它从一条窄缝向下、向两侧长开，带一点回弹。静止时三个灰点就是窗口按钮本身，它们依次散开、长大，填上 macOS 的红黄绿，长满后再淡入按钮上的符号；离开把手时整个过程倒放。按钮的作用：红色关闭这个标签本身（走标签栏的关闭流程，会先保存打开的文件）；黄色把格子收回标签栏；绿色把它单独打开。在绿灯上停 0.25 秒，这一片继续往下展开成贴靠菜单，和把手连成一块，不另起悬浮小窗；指针离开把手就收起。菜单随把手变宽从底片里向下长出；关闭时先保留 200ms 向上折回，再让把手变窄、按钮变回灰点。右键把手，或在绿灯上按 ↓，打开不会自动收起的菜单。按在按钮上拖动超过 6px 就是拖格子，不会触发按钮；拖动开始后才捕获指针。
  • 调整大小：缝隙平时什么都不画，指针停在缝上时，正中才出现一小段灰色短条，像 macOS 平铺窗口之间那样；整条缝隙都能拖。拖动缝隙只影响相邻的两格，拖到格子小于 240×160px 时停住，本来就更小的格子不会被继续压缩。窗口窄于 900px 时，侧栏平时浮在聊天上面；但画布分屏时，收起的侧栏占自己的列，不会盖住格子。拖到这一组切分的 1/3、1/2、2/3 附近（10px 内）会吸住，缝隙中点显示比例。双击缝隙恢复这两格等分；聚焦缝隙后用方向键每次调 2%。
  • 填满：⌃⌥F、⌘⇧↩ 或菜单里的「填满」，把当前格临时铺满画布，再按一次还原。其他格不卸载。
  • 收回格子（黄灯、⌘W）：只关格子，不关里面的会话；内容回到 tab 栏。格子关掉后，它在树里的空间让给相邻的兄弟格。
  • 布局动画：窗口按钮、贴靠菜单、填满和还原上次布局造成的布局变化，都像 macOS 移动窗口一样带动画（lib/tabs/canvas-transition.ts）。变化前，画布按 tab id 记下每个格子的矩形，并留一份静态副本；app shell 在执行这次变化的那次提交的 layout effect 里播放，首帧绘制之前就开始。格子按 tab id 对应，所以会话从对等格子换到单独的聊天外壳时也能连贯移动。分屏期间聊天外壳隐藏着，停在最后获得焦点的会话上；分屏解散时，它和布局在同一个 tick 里切到留下的会话，而不是等路由几次渲染之后才切，所以第一帧就是这个会话。只有切换后才到达的消息才会淡入；已经加载好的会话直接显示。同理，单条消息只在它到达后一秒内播放出现动画；会话在分屏格子或聊天外壳里重新挂载时，已有的消息直接显示，不会从透明淡入。留下的格子用 Web Animations API 在 300 ms 内把真实几何（left、top、width、height）从旧矩形过渡到新矩形，文字随宽度重新换行而不是被拉伸，格子的内联 calc() 几何保持不动。新出现的格子淡入。离开的格子由副本播放退场：红灯淡出并下沉（180 ms），盖在接手它位置的格子上；黄灯像 macOS 的神灯效果一样折进标签栏里它的标签（600 ms）：布局变化前，桌面端先给格子拍一张全分辨率静态图（captureRegion 带 full；变化最多等它 160 ms），之后每帧把这张图按 2 px 一行画到同一个 canvas 上，每行拉伸到漏斗在该高度的两边之间，弯成以标签底边为颈口的漏斗，无论格子内容多重，每帧开销都很小；拿不到静态图时（普通浏览器）改为把格子副本切成若干横条，每帧用射影 matrix3d 把每条映射到一个四边形；靠近标签的边先收窄，然后格子从颈口往上倾入，越靠近颈口压得越紧，并在颈口处裁掉，不会画到标签上；整个标签按钮在接住格子时底色亮一下，接手位置的格子晚 90 ms 开始展开；从分屏收起的格子变化前没有自己的标签按钮，新按钮先从原来所在的标签旁边滑出来，后面的标签同时滑开让位（260 ms，只动 transform 和 opacity，App 还在排版这次变化时合成线程也能流畅播放），折叠瞄准按钮最终的位置，晚 80 ms 开始，按钮完全滑出后才到达标签栏；折叠用自己的时钟，每帧最多前进 34 ms，主线程忙时动画暂停而不是跳过一段；横条兜底时内容越重的格子切的条数越少（6 到 20 条），标签不在格子上方时副本改为向标签缩小（340 ms）；被绿灯或填满挡住的格子在放大的格子下面淡出。被保存提示拦住的红灯关闭，等标签真正关掉再播放；记下后 1.5 s 内没有对应提交就作废。格子移动期间画布按拖动处理：网页格子显示快照而不是原生视图，聊天只重排可见的行。格子边框和分隔线在移动期间淡出，结束后淡回。「减少动态效果」打开时不播放动画。拖动分隔线不做动画，尺寸本来就跟着指针。
  • 空格：格数比内容多就会出现空格，里面列出 tab 栏的内容，点一下就能填进去。
  • 焦点：同一时间只有一个格子获得焦点，键盘输入、⌘W、贴靠快捷键和右侧栏的上下文都跟着焦点格走。

3.3 贴靠菜单

菜单结构对应 macOS 绿色按钮的菜单，每一项是一个小画布图示，蓝色块是这一格会去的位置。指向图示时，菜单里的提示行说出名字和快捷键（不用原生 title）；平时提示「按住 Option 显示四分之一」。

  • 移动与调整大小（只作用于这一格）：左半边、右半边、上半边、下半边；按住 Option 换成四个四分之一。去半边时，其他格子保持原来的顺序和排列挤进另一半；去的四分之一已经被一格完整占着时，两格交换位置。
  • 填满与排列：先是填满，然后是整块画布的左右、左 + 右侧上下、四宫格。这一格放在第一位，其他内容按阅读顺序依次填入；内容多出来退回 tab 栏，格子多出来留成空格。
  • 还原上次布局：退出填满；不在填满时，回到这次贴靠、排列、拖放、等分、关闭或拖动缝隙之前的布局。记录按涉及的标签和分组查找，所以把格子拖出分屏以后也能还原回去。
  • 均分大小。
  • 更多布局（展开）：上下、单屏、九宫格、十六宫格，已保存的布局，以及「保存布局…」。

3.5 标签栏里的布局标签

分屏窗口在标签栏里只占一个标签，宽度和普通标签一样，做法和 Chrome、Arc 的分屏相同。它显示当前聚焦那一格的图标和标题（随焦点变化），后面是分屏布局的小缩略图（聚焦那一格填深色）和总格数；所有格子在窗口总览里看。标签上的关闭按钮关闭整个分屏窗口，会先保存打开的文件；只关一格，用那一格把手上的红色按钮。

3.6 拖动的生命周期

画布以后要承载各种小窗口应用，拖动必须在任何情况下都能干净结束，并且不打扰其他格子：

  • 同一个收尾：格子拖动的松手、Esc、pointercancel、窗口失焦、计算落点出错，都走同一个清理，只执行一次：移除拖动标签和落点预览，恢复把手，释放指针捕获，清掉 data-canvas-dragging。查找落点出错时按「没有落点」处理，不会跳过清理。
  • 漏掉的松手：在系统窗口拖动区（标签栏空白处）、原生网页视图或别的应用上松手，页面收不到 pointerup。每个拖动（标签、格子、分隔线）都向 setCanvasDragging(true, owner) 登记自己的 cancel / release；之后第一次「没有按键按下」的 pointermove 就当作松手，在那里结束拖动。拖动还挂着时又来一次按下，旧拖动先取消。拖动期间整个窗口暂时没有 -webkit-app-region: drag 区域，系统不会吞掉松手。
  • 状态不写在把手的内联样式里：被拖的格子带 data-pane-dragging 属性，CSS 据此隐藏它的把手；新的拖动开始前清掉所有残留的这个属性。
  • 按下把手不改焦点：按下只准备拖动，不提交 store、不切换活动标签和路由；点一下（打开菜单）才聚焦。按下时阻止默认行为，不会选中下面格子的文字。
  • 分隔线每帧只重绘：拖动中用 previewCanvas 只改内存里的树（不规范化、不持久化、不切焦点），每帧最多一次；松手时 setCanvas 提交一次。
  • 原生网页先截图再隐藏：拖动或格子过小时，网页视图要换成快照。先截图，截图到手（最多等 160ms）再隐藏原生视图，不会先闪一下「网页已暂停」。
  • 落点预览不闪：不加背景模糊，位置变化用 120ms 缓出，没有回弹。

4. 尺寸与性能约束

网页320 × 200低于这个尺寸时原生视图冻结成截图
终端200 × 120xterm 自己重新计算行列数
文件或程序200 × 120—

再往下压，就进入「迷你态」：格子只显示标题和类型，点一下就放大。原型里把宽度小于 150px 或高度小于 110px 的格子当作迷你态来演示。

网页格子是难点。网页是 Electron 的原生 WebContentsView，永远盖在 DOM 上面，所以：
  1. 每个网页格子都要通过现有的 registerVisibleWebTabBounds 上报自己的 bounds，缝隙拖动时要按帧同步；
  2. 拖拽开始时，把所有网页格子冻结成 capturePage 截图并隐藏原生视图，松手后再恢复，否则 drop 预览框和被拖的 tab 会被网页挡住；
  3. 十六格全是网页时，同时存活的 WebContents 太多，需要一个上限（比如最多 8 个活跃，其余冻结成截图，点一下再激活）。

5. 持久化

  • 布局树序列化后跟窗口状态一起存（参见 window-state 设计），格子里只存 TabRef，不存内容本身。
  • 重启后恢复布局；已经失效的 TabRef 变成空格，不让整个布局崩掉。
  • 可以把当前布局存成命名预设（比如「研究：会话 + 3 个网页」），这项放到第三期再做。
