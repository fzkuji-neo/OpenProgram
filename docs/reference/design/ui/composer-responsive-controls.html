Responsive Composer controls

Scope: environment chips above the chat input, and permission, more, active tools, chat model, execution model, effort and context controls below it.

Each control row responds to its own available width. The bottom row retains existing settings; the top row has only two states: all full labels or all icons. As soon as full content overflows, labels for status, surface, project, directory and DAG Fit, zoom percentage and Legend disappear together, and return together when space permits. One transition animation governs the change; menus, values, keyboard operation, tooltips and accessible names remain unchanged.

Current implementation and gaps

.composer-bottom-row Continues responding to its own container..envChips No fixed breakpoint: chat and DAG pages have different numbers of controls and therefore different space requirements at the same width. It uses its own scrollWidth and clientWidth to detect full-content overflow, with one data-compact state controlling all labels. Single-page and split-pane layouts use exactly the same measurement logic.

Existing components already provide four distinct icons: Shield for permission, Message for chat model, Terminal for execution model and Biceps for effort. Every trigger already has a Popover/Menu, tooltip or accessible name, so no new icon components or menus are added.

Component boundaries

Composer directories follow interaction responsibilities: input editing belongs in input/, submission in submit/, mode dispatch in modes/, session settings in state/, while attachments, paste, slash and controls retain their directories. The environment bar separates overall layout from individual chips; ProjectBadge, WorkingDirChips and GoalChip stay in shared business modules. The DAG module owns its HUD and supplies it through EnvironmentRow's generic trailing-content slot; EnvironmentRow contains no DAG names, DOM ids or control logic.

Control-button surface hierarchy

Top environment chips use fill and edge hierarchy, while bottom controls are only 20px high. Bottom permission, more, active tools, chat model, execution model, effort and context controls reuse only theme-level --chip-bg for an always-visible subtle fill. Resting surfaces add no border, inset stroke or outer shadow, preserving internal visual space in small controls. Existing hover foreground colors and keyboard focus-visible indicators remain unchanged.

Context-statistics popover timing

ContextBreakdownPanel Unmounts when closed. If every mount clears existing results and enters loading, reopening the same session and DAG branch first shows a card containing only Loading…, followed by statistics. Even a short network request makes this whole-card replacement visible.

ScenarioImmediate displayBackground behavior
Reopen the same session and branchLast successfully retrieved complete statisticsRequest again and update in place without whole-card loading
First opening or no cacheExisting loading empty stateRequest current statistics and cache on success
Switch session or DAG branchRead only the cache for the new sessionId + headId keyCancel the old request; old responses must not overwrite the current panel
Request fails with an existing cacheKeep cached contentA failed refresh must not replace usable statistics with an error page

Cache exists only in the current frontend process, retaining 32 session branches in least-recently-used order. No persistence, periodic refresh or new dependency. For concurrent refreshes of one key, only the newest request may update the cache. The server remains the sole source of statistics; caching only removes the transitional screen on reopening.

Compaction rules

  1. Environment-chip labels do not participate in flex shrinking and never display partial text.
  2. When full content overflows, all labels fade and collapse width together; they reverse together when space returns.
  3. Icon triggers preserve size, order and operation.

Interaction and accessibility

  • Clicking an icon opens its original menu.
  • Chat and execution use distinct icons.
  • Effort-icon color continues to indicate the current level.
  • Focus, tooltips and accessible names remain when labels are hidden.

Boundaries

  • Do not change model, permission or effort state.
  • Use native ResizeObserver and MutationObserver without new dependencies.
  • No wrapping and no hiding entire controls.
  • Do not change composer height or splitRatio.

Implementation brief and acceptance

Top-row implementation is confined to apps/web/components/chat/composer/environment-row/: component, measurement hook, styles and two dedicated chips are separated by responsibility.composer/index.tsx only renders EnvironmentRow. The Context-cache batch is limited to apps/web/components/chat/context-badge.tsx, context-breakdown-panel.tsx and apps/web/lib/chat/context-breakdown-cache.ts. Independent checks are provided by apps/web/scripts/chat/check-composer-environment-row.mjs and included in npm --prefix apps/web run check:chat-ui. These batches do not change Popover, Menu, providers, session store or submission logic.

  1. Public-entry checks must establish that actual overflow switches environment chips through one data-compact state, with no fixed-width special cases or label-level flex-shrink:1.
  2. Status, surface, project, directory, Fit, zoom percentage and Legend share one animation rule; do not use display:none or collapse only some labels.
  3. In the default installed App, dragging the split-pane divider left past the threshold keeps all four right settings entries and left permission/more controls visible without overlap.
  4. Click permission, chat model, execution model and effort icons separately; original menus or panels open normally.
  5. Widen the pane until full content fits and all labels return together; reselecting split, switching chat/DAG and refreshing preserve this behavior.
  6. Every visible bottom control has a nontransparent --chip-bg surface without hover, computed border 0 and shadow none; hover or open menus must have a stronger background. Keyboard focus-visible indicators are not resting borders and remain available.
  7. After Context statistics load successfully once, closing and reopening the same session and branch immediately reuses cache; background completion updates cache and ring statistics.
  8. Context cache is isolated by session and branch; rapid switches cancel stale requests, and failed refreshes cannot overwrite existing cache.
