Interaction and state boundaries

Independent controlsCollapsing Settings categories does not affect the Provider list, which has no independent collapse control. User state takes precedenceResizing the window does not automatically expand or collapse Settings categories. PersistenceRestore the category column’s last choice after refresh or returning to Settings (settingsNavOpen). Keyboard and screen readersThe Settings collapse button retains native button, aria-expanded, aria-controls and an explicit name. Content adaptationNarrow windows only cause form controls to wrap; detail data, selection, and scroll state remain unchanged. Provider detailsThe Provider list always stays expanded, shrinking continuously to at most 42% of narrow content areas and leaving remaining width for details. The Provider switch belongs in the title row, not a separate row. Each credential is an account card: name and validation status in the header, key in the body, usage state in the footer. Rename, replace, revalidate, and delete become icon actions at narrow widths. Adding credentials first shows a single entry point; the form appears only after expansion. Visual hierarchyThe OpenProgram brand title is 20px. The Settings secondary-navigation title and right-side content title are 18px, one level below it. The Provider third level adds no separate named header. Vertical gridMove the entire Settings category list down 15px so General, LLM Providers, and subsequent rows align with New chat, Programs, and subsequent main-sidebar rows. Preserve row height and 1px gaps. Navigation orderGeneral → LLM Providers → Memory → Web Search → Browser → Channels → Token Usage → System; basic settings first, models and memory adjacent, statistics and system last.

Adopted and excluded

Adopted

  • Reuse the existing two-state collapse behavior and icons in Settings categories.
  • Remove the global Settings topbar.
  • Add no duplicate Memory header; restore the complete Providers page header.
  • Show name and button only in the Settings secondary header; provide no Provider-list collapse control.

Excluded

  • No draggable column resizing.
  • No breakpoint-driven overrides of user state.
  • No changes to Memory, Provider, or model data.
  • No changes to the main application sidebar.

Acceptance criteria

  • Settings no longer renders a separate global Settings topbar.
  • The OpenProgram brand title is 20px; the Settings category Settings and right-side LLM Providers content title are both 18px. Button and name share one row; button tops align with main-sidebar buttons.
  • The first four Settings category rows and main-sidebar rows have identical y coordinates, 32px heights, and 1px gaps.
  • Settings category links appear in General / LLM Providers / Memory / Web Search / Browser / Channels / Token Usage / System order; URLs, icons, active state, and keyboard order follow the same array.
  • The LLM Providers list has no additional named header or collapse button. Search spans the column; group labels and Add Custom Provider remain visible.
  • LLM Providers displays a full page title and introduction above list and details; route loading preserves the same structure.
  • Memory content continues without duplicate titles or introductions.
  • Narrow Provider details have no overlapping controls or horizontal overflow; account name, key, status, and all three action buttons remain usable.
  • API Key name, validation state, masked value, and enabled state occupy one account card. Validation state itself triggers revalidation; no separate Validate button remains.
  • When keys exist, the new-Key form is hidden by default. Users expand it through Add API key and may cancel.
  • Narrow details reduce horizontal padding, keep the Provider switch in the title area, and give icon actions title and aria-label.
  • Narrow details only rearrange internal content: no automatic category collapse, font reduction, or data/interaction changes.
  • Settings categories retain settingsNavOpen, keyboard semantics, icon selection, and 49px collapsed width; the Provider list no longer uses providerListOpen.
