队列与当前轮次引导

默认使用队列：每段对话在前一轮结束后发送一条后续消息。Steer 在支持的安全点向指定的当前执行添加文本。这两种队列操作都不会取消当前执行；取消由独立的停止控件负责。

参考与兼容性

Codex 提示 区分排队的后续消息与当前轮次输入。 Codex App Server 把 steering 绑定到预期的当前轮次，且不接受运行设置覆盖。OpenProgram 使用既有执行命令服务和安全点，不增加第二套 session 收件箱或 provider 专属 steering 传输。

投递

排队文本 → 执行身份与当前版本 → 持久化 execution.steer 命令 → 下一个安全点 → 持久化 steering 用户消息

队列保留条目，直到匹配的 applied 回执确认用户消息已持久化。accepted 或 applying 命令使用同一命令信封自动检查。命令只携带消息、精确执行身份、版本和幂等键，不改变权限、模型、工具或当前程序。不支持或已结束的执行让条目继续排队；空闲时的协调按 FIFO 顺序发送普通后续消息。

发送前，客户端保留不可变命令信封。确认丢失时，投递状态保持未确认：条目仍可见，普通队列处理不能再次发送，自动确认重试复用同一信封。每个排队条目使用一个确认计时器，从 1.5 秒开始，传输失败后退避到最多 30 秒。确定回执清除重试状态；不确定投递不能转为普通重复发送。确认的旧版本拒绝允许依据新快照创建新信封。错误可见；传输失败后总会释放 injected 标志。

归属与界面

当前 session 及其运行执行决定目标，不得临时选择其他 session 或关联子 Agent。队列提供一个不取消执行的操作以向当前轮次添加消息，且在投递并非不确定时允许移除。运行期间消息偏好仍为 queue 或 steer。附件保留既有草稿行为；steering 在规范命令大小限制内接受文本。

普通后续消息准入先从持久 session head 确定 predecessor，再更新服务端对话镜像。它包含前一条助手回复、工具结果和已投递 steering 输入；显式分支 predecessor 保持不变。

被取消或中断的助手轮次保留部分内容并显示终态，包括空回复。取消提示不推断取消由谁发起。

存储边界

队列条目仍只存在于当前 renderer。待定 steering 条目在确定确认解析命令前不能作为普通消息发送。规范的接受操作把命令持久化到服务端；应用命令时持久化用户消息。执行结束后，未投递 steering 命令被拒绝，对应条目可恢复普通排队。已完成的工具批次不会仅因 steering 消息到达而被跳过。本次改动不使用新消息代理替换普通聊天传输。

验收

  • 排队两条后续消息：每条只在前一轮结束后开始。
  • 工具运行期间添加文本：同一执行和工具继续，指令进入后续模型上下文。
  • 确认丢失：保留条目，重放同一命令，不重复投递。
  • 目标已结束、不可用或不支持时保留输入并报告状态。
  • 切换范围不能引导另一段对话；停止仍是独立显式操作。

函数重试确认

每次重试携带请求身份，分发确认或拒绝时回传。接受计时器在分发被接受时结束，而不是等函数执行完成。拒绝或断线发送只恢复对应待处理卡片，并报告一次真实原因。缺少确认保持不确定，不自动重新提交。历史和界面验证仍具权威性。
