# Activity 面板

右侧栏的 **Activity** 针对一个会话回答三个问题：有什么要你处理、现在在跑什么、之前跑过哪些子代理。它列出会话启动的 agent 分支，从不列消息，消息留在聊天里。

[`sub-agents-card.md`](sub-agents-card.zh.md)（子代理自己的对话）。

## 子代理、运行与待处理事项

列表中的每一行是一个**子代理**：显示类型为 `job_agent` 的执行。底层的执行组成**运行**：一个顶层执行，通常是一条消息加上为它做的所有事。子执行、尚未返回的函数调用和托管程序归属于包含它们的运行。运行有自己的页面（从子代理的“来自”或停在问题上的消息进入），但不单独成行。

**待处理事项**是具体在等你的事：

- 结果待确认的调用：运行在它发出后中断；
- 停在问题或审批上的执行，或者持有一个待确认操作、且没有被某个待确认调用说明的执行；
- 状态未知或丢失的程序。

只缺模型响应记录（`provider_response_incomplete`）的执行不算待处理，显示为已结束。

## 总览

三组，顺序固定；空的组不显示，所有组都不能折叠。

1. **要你处理**：待处理事项，从新到旧。行就是这件事本身（“Fix page close · 子代理结果待确认”），不是整段会话。子代理已列出的待确认 `agent` 调用，以该子代理的身份显示，下面不再重复列出。
2. **正在运行**：进行中的子代理，写出当前调用和已用时间；也包括子代理之外正在执行的调用和程序。
3. **子代理**：已结束的子代理，从新到旧，按天分组，每次 20 条，点“显示更早”继续。

调用和程序在执行列表读取之后才归位，不会先闪现为无归属。

## 页面

每一行点进去都是一个页面；面板背后是一个页面栈，返回箭头写出要回到的页面。任何地方都不原地展开。

- **子代理 / 运行**：类型、开始时间和用时、名称或消息、状态。待处理事项排在最前，操作用浮起的胶囊按钮：执行允许时“结束这次运行”（取消），暂停时“去处理”/“查看详情”。子代理另有“打开它的对话”、“来自”（启动它的运行），以及 `agent` 调用未返回时的“交给它的任务”。然后是它做了什么：未返回的调用（`agent` 调用通过它启动的子代理进入）、子执行、程序。“技术详情”打开执行检查器，只有它会读取事件和调试数据。
- **调用**：以说明为标题，显示类型、开始时间、状态、来自哪次运行，以及任务（`prompt`）或命令。任务按正文显示，命令用等宽字体；都先显示几行，点“展开全文”看全部。
- **程序**：状态、来自哪次运行、工作目录、运行环境、退出情况、命令和输出，运行中可以“停止程序”。

## 外观

行在静止时没有框：裸露的类型图标用该类型的颜色，名称下面是以共享状态圆点开头的状态行，右侧一个箭头。悬停时整行浮起成文件卡片那种卡片。页面上的待处理事项用浅琥珀色底，没有边框。
