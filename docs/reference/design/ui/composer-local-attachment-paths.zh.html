输入框本地路径

用户在 Electron 桌面 App 中拖入或选择本地文件、图像或文件夹时，发出的消息必须标识原始绝对路径。现有附件卡片和字节上传行为保持不变。

已确认缺口

边界当前行为要求行为
Electron preload提供窗口和 Web 标签 API，但没有获准的文件路径访问器。通过现有桥接暴露 webUtils.getPathForFile。
输入框待提交状态仅保存来自以下字段的 basename：File.name.为图像与文档保存可选且不可变的 sourcePath。
提交文档仅在后端保存副本后获得路径；图像没有原始路径；无法读取的文件夹被描述为未发送。存在以下字段时，发送带有 JSON 编码原始绝对路径的附件标记：sourcePath。

行为合同

  • 桌面桥接是渲染器唯一可访问的原生路径来源。渲染器不获得 Node 文件系统权限。
  • 每个拖入或选择的 File 在异步读取开始前查询一次。图像和非图像均保留返回路径。
  • 具有可读字节的文档保留当前上传与预览流程。可见及模型使用的标记指向原始路径；后端仍可持久化会话副本。
  • 具有来源路径的文件夹或不可读本地项，即使无法上传字节，也是有效路径引用。不得标记为“过大，未发送”。
  • 图像保留多模态载荷，并额外获得一个原始路径标记。
  • 当前含路径标记将路径编码为 JSON 字符串，保留方括号、引号、反斜杠和尾随空格；读取器继续兼容历史未加引号标记。
  • 每个上传附件携带自身可选的 source_path 来源信息。后端仅在存在该附件的精确来源路径时保留前端标记，避免混淆同名浏览器上传。
  • 本地预览时，存储标记在 @json 中保留供 agent 使用的原始路径，并在 @previewjson 中添加供 UI 使用的不可变会话副本路径。没有预览路径的旧消息仍可读取。原始文件端点不将来源路径的父目录加入可读根目录。
  • 后端在向提供商派发前，从图像附件元数据删除 source_path。该路径仍按设计保留在用户消息标记中。
  • 剪贴板生成的 blob 和普通浏览器文件没有原生路径。它们保留现有上传、保存行为和生成的会话路径。

项目与附加目录控件

环境标签行包含两种路径控件。项目标签选择草稿的主要工作目录；首次提交轮次后变为只读，因为 cwd、权限基线和会话仓库位置已经固定。文件夹加号控件管理附加工作目录，在活动会话中仍可编辑。

  • 草稿中选择现有项目只更新该草稿。打开新文件夹会创建或解析项目，并立即选中返回的项目；仅刷新而未选中不算完成选择操作。
  • 没有会话时，附加目录菜单从草稿待提交的项目选择推导实际主项目。不得把主项目路径作为附加目录选项。
  • 以已连接后端的回复为准。项目请求无法完成时，控件保留之前的状态，不显示虚假的选择成功。

范围与拒绝的修改

涉及 Electron preload 桥接、桥接 TypeScript 合同、输入框附件状态、提交标记构建及现有后端标记改写。不涉及附件卡片样式、目录遍历、递归浏览器上传、任意文件系统扫描、新 IPC 处理器、上传大小修改、Programs UI 或依赖。

拒绝使用非标准旧字段 File.path；拒绝在渲染器启用 Node integration、对可读文件以仅路径消息替代上传、在普通浏览器中编造相对路径，或递归枚举拖入目录。

验收与验证

聚焦检查必须证明：preload 对同一个 File 对象返回精确原生路径；路径捕获处理桥接缺失、空结果和异常；文档、图像及不可读文件夹标记包含完整路径；带括号的文件名安全显示；包含 ]、引号及尾随空格的路径可通过两个解析器往返；无路径浏览器附件保留当前标记；同名浏览器附件及混合来源附件保持区分；后端持久化不重复添加已有路径标记的附件；TypeScript、桌面检查、Web 检查、后端附件测试、构建、文档链接及 diff 空白检查通过。
