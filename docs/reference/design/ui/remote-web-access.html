Remote Web Access / Owner only / Self-hosted

Four access methods, one owner-authentication scheme

Supports same-machine access, LAN or VPN, SSH tunnels, and owner domains behind HTTPS reverse proxies. Every Web startup generates an instance token; HTTP, SSE and WebSocket share authentication rules. OpenProgram operates no public relay and adds no accounts, RBAC or project permissions.

Current implementation and remaining controls

Owner process tokens, canonical Origin, fragment bootstrap, shared HTTP/WS authentication, auth-url, minimal health and non-retrievable secrets are in production paths; complete deployment acceptance remains unfinished.

Current behavior

OwnerAuthMiddleware authenticates first

OwnerAuthState Generate a 32-byte token, hold a per-state lock, write an owner-only token file and token-free access.json, and derive a profile-specific cookie.OwnerAuthMiddleware Validate Host/request origin and cookie or Bearer before route dispatch.

Attach current-profile owner authority only after authentication; validate WebSocket before accept() . Uvicorn uses proxy_headers=False.

Remaining work

Constrain secret handling and acceptance scope

Both plaintext-reveal paths are removed: legacy account routes return 410, config-key reveal queries return 404, and credential responses retain masks only; replace/preserve/delete schemas are implemented.

Still missing direct-HTTP startup warnings and independent acceptance for SSE, real-browser bootstrap/WS, restart, bind failure, multiple profiles and nginx/Caddy smoke deployments.

04

Adopt, adapt and reject

The final design keeps only one root key (instance token), two transport credential forms (Bearer header and profile-scoped HttpOnly cookie), one browser bootstrap and one HTTP/WS/SSE authentication rule set.

Adopt
OpenClaw 's exact Origin, Host/DNS-rebinding controls, SSH and proxy-trust restrictions.
Adapt
Jupyter 's automatic launch-token experience: replace query with fragment, then exchange for an HttpOnly cookie.
Adopt
Generate 32 random bytes with the standard library and compare decoded credentials in constant time; this is OpenProgram's own instance-token construction.
Adopt
Agent Zero 's combined cookie, CSRF, Origin and WebSocket validation, and masked-only secret updates.
Adapt
External proxies or VPNs may add transport and access controls but cannot replace the OpenProgram token.
Reject
Disabling authentication, query/localStorage tokens, plaintext secret reveal, multi-user accounts, RBAC, built-in tunnels and public relays.
05

Final authentication and deployment design

Run one Web process per profile/state instance. Rotate tokens on every startup. Browsers bootstrap once with fragments, then use derived HttpOnly cookies; native clients use Bearer headers.

Generate32 random bytes encoded as 43-character unpadded base64url.
Lock and saveFirst hold <state>/web.lock, then atomically write the owner-only token and token-free access.json.
Derive and compareopenprogram_owner_<owner16> Use a fixed HMAC domain; after decoding, compare only with compare_digest.
InvalidateProcess restart rotates the token, invalidating old Bearer and cookie credentials together.

Unified request-processing order

Fragment to HttpOnly cookie

Public allowlist

Only four public categories

Static shells/assets (including the prebuilt-file-only GET/HEAD /docs documentation site), ownership challenge, bootstrap and minimal health. Source checkouts read docs/_site; installed packages read the same prebuilt site placed under openprogram_server/_webui/_frontend/docs during release. Staleness checks run only when source workers register routes, not on HTTP requests. The shell uses CSP frame-ancestors 'none' and X-Frame-Options: DENY.

Browser cookie

CSRF validation remains

GET/HEAD/OPTIONS must be side-effect-free. Unsafe methods and WS require Origin equal to request_origin; only safe requests may omit Origin.

Native client

Header-only Bearer

HTTP, SSE and native WS use Bearer. Reject query tokens. Except for bootstrap, any Authorization header prevents invalid Bearer credentials from falling back to cookies. Bootstrap with Authorization returns the same 401 directly.

Listener ownership: <state>/web/access.json Freeze bind, port, effective Origin and token fingerprint, but not the token. After verifying worker PID/port, CLI sends a fresh 32-byte nonce only to GET /api/auth/challenge and locally verifies HMAC-SHA256(raw_token, "openprogram-web-challenge-v1\0" || nonce || "\0" || revision); the token is never sent to the probed port.

Origin and proxy trust:Default loopback automatically includes the exact current-port localhost and actual listen literal; other Origins require explicit config.json configuration. HTTP permits only that localhost, loopback, RFC 1918, IPv4/IPv6 link-local, IPv6 ULA and RFC 6598 range; other addresses and DNS names require HTTPS. Each request accepts one valid Host;http/ws and https/wss map to their corresponding browser Origins. Uvicorn uses proxy_headers=False; OpenProgram does not trust X-Forwarded-For and accepts only one X-Forwarded-Proto from the original loopback peer. The request_origin constructed from scheme + Host must be valid.

Non-retrievable secrets

Remove

Remove both reveal paths

Account reveal routes return 410; config-key status retains masks but returns 404 on a reveal query.

Return

Masked responses only

Return has_value and masked/masked_key. Values at least 12 characters use sk-…abc4, hiding at least five characters; shorter values use eight fixed dots.

Replace / delete

Define the two action classes separately

Config keys use POST /api/config for replacement andDELETE /api/config/key/{env} for deletion; API-key accounts use dedicated update for replacement andaccounts/remove to delete the entire account. Empty values and masks are invalid.

06

Implementation contract and acceptance

Accept connections only after configuration validation, secure token persistence and fingerprint calculation. Executable behavior tests establish completion, not documentation.

  1. Loopback HTTP, SSE and WS fail without credentials.
  2. Correct Bearer succeeds without Origin; wrong tokens perform no action and return the same 401.
  3. Clear fragments before other fetches; bootstrap accepts only exact bounded JSON, rejects mixed Authorization and derives the specified HMAC cookie.
  4. Unauthenticated GET/HEAD /docs and /docs/** can read prebuilt static docs in both source checkouts and installed packages without scanning source or triggering builds; the wheel must include openprogram_server/_webui/_frontend/docs/index.html. Host validation still applies; unsafe methods and private APIs are excluded.
  5. Cookie-authenticated unsafe HTTP and WS reject missing, opaque and cross-site Origins.
  6. Loopback, direct bind and proxies reject external, duplicate, unspecified and multicast Hosts and validate HTTP/WS scheme mapping.
  7. Default loopback accepts only implicit Origins; other SSH local ports require explicit configuration.
  8. Non-loopback bind without a valid Origin list rejects startup; explicit local/overlay HTTP ranges are accepted with warnings, other addresses rejected.
  9. Disable Uvicorn proxy-header rewriting; scheme trusts only the original loopback peer, X-Forwarded-For never changes trust, and direct WS/Caddy WSS validate scheme mapping.
  10. A second process using the same state directory cannot alter the live token; failure cleanup verifies ownership.
  11. Restart rotates tokens and invalidates old Bearer and cookies.
  12. Malformed Authorization cannot fall back to a valid cookie.
  13. Static assets and minimal health contain no session, filesystem or credential metadata.
  14. CSP/X-Frame-Options prevent framing; authentication and sensitive responses use no-store.
  15. Legacy account reveal returns 410 and config-key reveal query returns 404. Config keys and accounts enforce exact replace/preserve/delete schemas; 8–11-character values use fixed masks; frontend types contain no plaintext field.
  16. HTTP, SSE and WS authenticate behind nginx/Caddy HTTPS while backend stays on loopback.
  17. Channel turns retain paired authority tiers rather than gaining Web-owner authority.
  18. Profile servers sharing a hostname but using different ports have distinct cookie names and independent authentication.
  19. Listener ownership probes verify worker PID/port and access snapshot, send only random nonces, validate versioned token-HMAC proofs and reject foreign listeners, stale snapshots and port/fingerprint/proof/revision mismatches.
