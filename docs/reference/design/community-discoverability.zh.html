社区可发现性设计

此次改动帮助仓库访客提出有价值的问题、报告和贡献，不增加独立社区平台。

当前缺口

仓库使用规范的 Fzkuji/OpenProgram 贡献链接、公开安全政策、结构化问题表单，以及用于私密漏洞报告的 GitHub Security Advisories 链接。这些仓库内可见的合同实现在 .github/CONTRIBUTING.md, .github/SECURITY.md, .github/ISSUE_TEMPLATE/以及拉取请求模板中。仓库文件不能证明外部 GitHub 安全公告设置是否已启用。

参考行为与决策

  • GitHub 会在仓库贡献流程中展示 .github/CONTRIBUTING.md 。采用一份规范指南，包含当前安装和验证命令。
  • GitHub 识别位于 .github/ISSUE_TEMPLATE下的问题表单。分别提供缺陷与功能表单，将问题咨询引导到 Discussions，并禁用空白公开 Issue。
  • GitHub 识别 .github/SECURITY.md 及私密漏洞报告。两者均采用，避免在公开 Issue 中披露安全报告。
  • 增加 Contributor Covenant 行为准则、支持分流文件和拉取请求模板，使 GitHub 能展示完整社区资料，并为贡献者提供一致的验证提示。
  • 公开首页的页脚直接链接 Discussions 和贡献指南。
  • 不增加论坛、聊天服务器、表单服务或机器人；现有 GitHub 页面已满足要求，避免增加审核渠道。

验收

  • 所有仓库 URL 使用规范的 Fzkuji/OpenProgram 路径。
  • 问题表单 YAML 可解析，包含 GitHub 要求的名称和说明字段，并把支持与安全报告引导至正确的现有页面。
  • 贡献、安全和问题模板链接返回成功响应。
  • 仓库设置已启用私密漏洞报告。
