Context · Measurement contract

Accounting rules

For users and implementers: defines how the bottom Context panel reports actual totals, categorized content and differences that cannot be reconstructed directly.

Status: implemented Scope: shared Web / App API Excluded: new UI styling

01 · The result must answer three questions

How much context is occupied?

Prefer actual input tokens returned by the provider; use local estimates only when no measurement is available.

Where does the content come from?

Show system, tools, MCP, skills, memory and messages as mutually exclusive categories; never count them twice.

What cannot be reconstructed?

Show the positive difference between the measured total and categorized estimates as “Other context (estimated)”; do not hide it.

02 · A single snapshot

Current branch
Read compacted rendered history, the latest system prompt and the frozen tool set.
→
Local categorization
Calculate message structure, tool schemas, Skills and Memory; subtract nested items from their parent categories.
→
Provider calibration
Combine the latest measured total for the same HEAD and calculate the uncategorized difference.

Calculate the local breakdown only once per API response. The panel must not reread the dynamic tool registry within that response, or the categories and estimated may refer to different moments.

04 · Calculation rules

classified = system_other + skills + memory + tools + mcp + deferred + messages other = max(0, provider_total - classified) displayed_used = provider_total if measured else classified free = max(0, window - displayed_used)

If local category estimates exceed the provider measurement, retain the provider total as the occupancy value and scale displayed categories down proportionally. The response retains raw estimates and the calibration factor; never display a negative difference.

05 · Acceptance criteria

  • In the same response, estimated and the raw category total come from the same calculation.
  • When measured, displayed categories sum to total_used; when estimated, they sum to input_used.
  • After a branch switch or graph change, do not reuse the old provider measurement for the new HEAD.
  • After a model switch, immediately use its context window and replace the old measurement with a fresh estimate for the current model. Use the new provider measurement after the next request completes.
  • Tool input/result, thinking and memory prefetch affect Messages.
  • App and Web consume the same /api/sessions/{id}/context contract and do not estimate independently.

Record actual input

Consume the same API
