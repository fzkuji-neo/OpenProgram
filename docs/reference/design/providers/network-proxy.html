Outbound network proxy

Provider clients keep managed URL, credential, redirect and TLS policy while using the user's proxy for audited HTTPS services. The ordinary proxy resolves the exact audited hostname; the client pins and checks the proxy socket peer.

Verified gap

The managed transport ignored environment and system proxies, while product documentation described their use. Direct access to the Codex backend failed; the configured local HTTP proxy returned a service response.

Routing boundaries

Only provider.* and webui.model_listing.* consumers can use ordinary proxies, and only when the exact request origin appears in the provider API or OAuth audit inventory. Custom endpoints, downloads, user URLs and callbacks retain direct peer checking or explicitly configured enforcing policy proxies. Each target is evaluated before proxy selection, including redirects.

Resolution and transport

  1. An explicit security.outbound_url.policy_proxy takes precedence and retains its enforcement requirement.
  2. OPENPROGRAM_PROXY_URL overrides ordinary routing while preserving NO_PROXY.
  3. HTTPX resolves standard environment variables, with Python's macOS and Windows system settings fallback when applicable.

HTTP, HTTPS and SOCKS5 proxies use httpcore proxy pools with a decision-aware backend. The proxy authority is an owner-selected route; metadata and link-local addresses remain forbidden. Proxy authentication is passed only to the proxy handshake. TLS verifies the original service hostname, the Host header is generated from the validated origin, and redirects cannot forward credentials across origins. Failures never fall back to a direct connection.

The routing map is immutable within a client and part of shared-client cache identity. A new call after routing changes retires stale clients. Explicitly supplied transport-security objects stay deterministic and do not inherit ambient routing.

Accepted and excluded choices

Reuse HTTPX's environment parsing and URLPattern precedence instead of implementing a second NO_PROXY matcher. Keep ordinary routing separate from PolicyProxyConfig: a normal Clash proxy does not assert arbitrary URL policy enforcement. Do not introduce a new profile, disable URL protection, modify OAuth credentials or extend ordinary routing to custom services. CA bundles remain explicitly controlled by outbound security configuration.

Acceptance

Public sync model-check and async provider entries must use HTTP, HTTPS and SOCKS5 routes; preserve NO_PROXY and override precedence; invalidate shared clients when routes change; reject unauthorized target and proxy addresses before network activity; isolate service and proxy credentials; retain explicit policy-proxy behavior and cleanup.

Implementation status

The service routing source changes have passed independent specification and quality review, including real httpcore proxy handshakes, TLS hostnames, cancellation, cleanup and credential isolation. Full acceptance remains incomplete while the repository baseline tests fail. A live model reply also requires valid provider credentials and available service quota.

2. How OpenClaw does it

Source: references/openclaw/src/infra/net/proxy-env.ts, proxy-fetch.ts, src/infra/net/proxy/, and https://docs.openclaw.ai/cli/proxy/.

  • One canonical env resolver (proxy-env.ts) that deliberately mirrors undici EnvHttpProxyAgent semantics: lowercase vars take precedence over uppercase; HTTPS requests prefer https_proxy then fall back to http_proxy; ALL_PROXY is a fallback fed in explicitly. A full NO_PROXY matcher (comma/whitespace split, case-insensitive, *, leading-dot, *., subdomain suffix, optional :port, bracketed IPv6, plus their own IPv4-CIDR extension) gates every proxy decision — it is a reimplementation kept in sync with undici because undici doesn't export its matcher.
  • One explicit override: --proxy-url flag / proxy.proxyUrl config / OPENCLAW_PROXY_URL env, with optional --proxy-ca-file, implemented as a makeProxyFetch(proxyUrl) wrapper over undici ProxyAgent, plus a managed-proxy lifecycle (validation, TLS options, active-state tracking).
  • Provider HTTP helpers all route through these helpers; the SSRF guard (fetch-guard.ts) composes with the same matchesNoProxy.

OpenProgram borrows the useful diagnostic property that standard environment variables have one documented interpretation, while its managed provider path adds a separate policy-proxy boundary. OpenClaw goes further with proxy lifecycle validation and SSRF gating, which this design does not need.
