出站网络代理

Provider 客户端保留 URL、凭据、重定向与 TLS 策略，在已审计 HTTPS 服务上使用用户配置的代理。普通代理解析确切的官方 hostname，客户端固定并检查代理 socket 地址。

已确认问题

受管理客户端忽略环境和系统代理，而产品文档写着支持这些配置。Codex 服务直连失败，通过当前本地 HTTP 代理收到服务响应。

适用边界

只有 provider.* 与 webui.model_listing.* consumer，且目标 origin 在 provider API 或 OAuth 审计列表中，才使用普通代理。自定义服务、下载、用户 URL 和 callback 继续使用直接地址检查或显式策略代理。所有目标和重定向都先验证目标策略，再选择代理。

解析和传输

  1. 显式 security.outbound_url.policy_proxy 优先，保留执行目标策略的要求。
  2. OPENPROGRAM_PROXY_URL 覆盖普通代理配置，并保留 NO_PROXY。
  3. HTTPX 解析标准环境变量，在适用时使用 Python 的 macOS 与 Windows 系统代理回退。

HTTP、HTTPS 与 SOCKS5 使用 httpcore 代理连接池和地址策略 backend。代理 authority 是用户选择的连接目标；metadata 和 link-local 地址仍被禁止。代理认证只传递给代理握手。TLS 验证原始服务 hostname，Host 来自验证过的 origin，重定向不能跨 origin 转发凭据。失败不回退直连。

客户端保留不可变的代理配置，配置参与共享客户端缓存身份。代理变更后新调用替换旧客户端。显式提供的传输安全对象不隐式继承环境代理。

采用与排除

复用 HTTPX 环境解析与 URLPattern 优先级，不实现第二套 NO_PROXY 匹配。普通代理和 PolicyProxyConfig 分离：Clash 不被视为执行任意 URL 策略的代理。不增加 profile、不关闭 URL 保护、不改 OAuth 凭据、不扩展到自定义服务。CA 文件由出站安全配置显式控制。

验收条件

同步模型检查与异步 provider 支持 HTTP、HTTPS、SOCKS5；保留 NO_PROXY 和覆盖优先级；配置变化后替换共享客户端；网络连接前拒绝非法目标与代理地址；隔离服务和代理凭据；保留显式策略代理行为与资源清理。

实现状态

服务代理源码修改已通过独立规格和质量评审，覆盖真实 httpcore 代理握手、TLS hostname、取消、资源关闭和凭据隔离。仓库基线测试仍失败，完整验收尚未完成。实际模型回复还需要有效的 provider 凭据和可用额度。

2. OpenClaw 的处理方式

来源： references/openclaw/src/infra/net/proxy-env.ts, proxy-fetch.ts, src/infra/net/proxy/, and https://docs.openclaw.ai/cli/proxy/.

  • 统一环境解析器（proxy-env.ts）刻意复现 undici EnvHttpProxyAgent 语义：小写变量优先于大写；HTTPS 请求优先使用 https_proxy，随后回退到 http_proxy；ALL_PROXY 作为显式传入的回退。完整的 NO_PROXY 匹配器检查每次代理决策，支持逗号/空白分隔、不区分大小写、*、前导点、*.、子域后缀、可选 :port、方括号 IPv6，以及自定义 IPv4-CIDR 扩展。由于 undici 不导出匹配器，此实现需与 undici 保持同步。
  • 统一显式覆盖：--proxy-url 参数 / proxy.proxyUrl 配置 / OPENCLAW_PROXY_URL 环境变量，可选 --proxy-ca-file。以包装 undici ProxyAgent 的 makeProxyFetch(proxyUrl) 实现，并管理代理生命周期，包括验证、TLS 选项和活动状态跟踪。
  • Provider HTTP 辅助函数统一通过这些函数请求；SSRF 防护（fetch-guard.ts）也组合使用同一个 matchesNoProxy。

OpenProgram 采用标准环境变量具有统一且文档化解释这一诊断特性，同时在受管 provider 路径增加独立的策略代理边界。OpenClaw 还提供代理生命周期验证与 SSRF 检查，本设计不需要这些机制。
