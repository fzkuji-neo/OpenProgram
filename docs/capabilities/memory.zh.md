# 查看和编辑 Memory

打开 **History → Memory**，再选择主题。主题和 Core 源记录默认显示预览，点击“编辑”
修改 Markdown。页面没有 Save、Saved 或 Changes 控件。

每次输入立即保留在当前浏览器的草稿存储中，并自动提交文件写入。写入按顺序执行，
旧请求不会覆盖新输入。使用 Cmd+Z 或 Ctrl+Z 撤销，Cmd+Shift+Z、Ctrl+Shift+Z 或
Ctrl+Y 重做；App 保持打开时，自动保存不会清除该文档的撤销记录。

文件保存与 Git 历史分开处理。服务器默认每 5 分钟将手动修改记入历史，调度误差最多
15 秒；计时不会因关闭编辑器而停止，服务器重启后也会继续处理。开始一段手动编辑前的
版本也会保留。

其他对 Memory 的每次修改都单独记一次历史，并写明来源：

- 每次后台写入，写明来自哪个对话；
- 写入后触发的整理，和写入分开记录；
- 夜间整理的每一轮，拆分大文件时每个文件一次；
- agent 在对话中调用的每次 `memory_update`，写明来自哪个对话；
- 在 OpenProgram 之外做的修改，例如用别的编辑器打开 Memory 文件夹直接改。它们会在
  下一次写入落盘前单独提交，所以恢复某次写入之前的版本时，不会把这些修改一起撤掉。

没有通过检查的写入既不改动文件，也不留下历史记录。

“历史”按从新到旧的顺序列出版本，显示本地日期和时间。选择版本即可查看增加和
删除的行。点击“恢复此版本”恢复该文档：先记录当前状态，再为恢复操作创建一条
新记录。已有历史不会被删除，因此也可再次选择其他版本。恢复仍会校验来源引用，
不会破坏其他 Memory 文档指向该文档的链接。

保存被拒绝或发生冲突时，草稿会保留并显示原因。“查看最新版本”会在历史面板中
比较最新文本与草稿；“用当前草稿替换最新版本”按刚查看的版本重新保存。如果此时
又发生其他修改，仍会拒绝覆盖。

## 自动写入停了的时候

对话由后台写入器写进 Memory。出错时它会先自己修，修不好才提示：

- 写入模型完全用不了（登录被拒、套餐没有权限、提供方没有这个模型、用量套餐耗尽）时，
  写入器先换成默认 Agent 的模型，再换成最近用过的模型，继续写。
- 写入的内容没通过格式检查时，会退回给它在原文上修，最多三轮，仍不通过再从头重做一次。
- 有 topic 文件被手工改坏时，在写入新对话之前先派修复 agent 修好格式。修复保留文件里的
  事实和块 ID，并在历史里单独记一条。

最近一次运行仍然失败时，Memory 页顶部会出现一条红色提示，写明原因、上次成功写入的
时间和待写入的对话轮数。会自动重试的失败会注明这一点，只显示在这条提示里；不会再重试
的失败还会弹出一次提示，之后只有原因变化才会再提示。没能写入的轮次会重试；写入器
认为没有值得记的对话算作已写入。

## 格式检查

Topic 正文必须保留 Source 脚注。不构成有来源记录的实质段落会在安装任何写入之前，以 `INVALID_TOPIC_FORMAT` 拒绝；`memory_update` 的全文件 changes 和 patch 也遵守此约束。有效引用记录和空 topic 保持现有行为；被拒绝的整批操作不会提交新 Source、派生视图或 Git 历史。

后台写入器每改完一个文件就跑一遍同样的检查，哪条规则被破坏会在那次修改时就知道，
并在本轮结束前改好。重复写了两遍的脚注定义，以及段落移走或删除后留下的脚注定义，
会被直接删掉，而不是拒绝整次写入。

来源脚注打开只读来源视图。如果本地原会话已删除，会显示“原会话已删除”，不再
展示旧来源原文。删除时不会额外复制来源文档，已提取的记忆继续保留。这个来源可用性
规则不会重写现有 Memory Git 仓库。归档只隐藏会话，保留内容和链接，不会因为超过
某个期限或容量而自动删除。

各 Agent 的记忆模式与独立空间在 [Agents](agents.zh.md) 配置。此编辑器管理已有的共享记忆存储。
