# 调整记忆

打开 **设置 → 记忆**。每项修改立即保存，下一轮生效；只有 **启用 Memory**
需要重启。这些设置也是配置键，列在[配置键](../reference/config-keys.zh.md)的
`memory.*` 下。

## 后台写入

| 设置 | 作用 |
|---|---|
| **写入模型** | 写入和整理 Memory 用的模型。**自动**：用默认 Agent 的模型；该 Agent 没有设模型时，用上次使用的模型。 |
| **自动写入** | 在后台把已完成的对话整理成 Topic 记录。 |
| **写入频率** | 累积多少对话（约 8K、16K 或 32K Token）后写一次。 |
| **写入后校验** | 每次写入后，就刚记下的一条事实提一个问题，在 Memory 副本里查答案；查不到时修复 Topic。默认关闭：每次写入至少多三次模型调用，修复再多三次。 |

`openprogram memory status` 的 `verification` 一项显示校验结果：通过、修复
成功、修复后仍失败、出错各多少次，以及最近一次的结果。

## 检索

| 设置 | 作用 |
|---|---|
| **检索方法** | **Agent**：不自动加入，由模型用工具自己查看 Memory。**关键词**：按 BM25 排序。**语义**：按 Embedding 排序。**混合**：两者都跑再合并。语义和混合需要 Embedding 模型。 |
| **混合权重** | 混合检索中关键词与语义的比重：**关键词优先**（70 / 30）、**均衡**（50 / 50）或 **语义优先**（30 / 70）。**自动**：消息含日期、引号短语或人名时偏向关键词，否则两者均衡。 |
| **同主题加权** | 混合检索时，一个 Topic 有多段匹配就提高它的排名。默认开启。 |
| **检索数量** | 每轮最多加入的记录数：3、5、8 或 10。 |
| **检索 Source 证据** | 除了 Topic，也检索归档的对话原文。 |

混合权重和同主题加权只在检索方法为混合时生效。

语义和混合检索需要 Embedding 模型，以及运行它的 sentence-transformers 和
PyTorch。App 不自带这两个包，所以 **Embedding 模型** 旁边的 **安装** 会连同
模型一起下载它们。这两个包约占 1 GB 磁盘，模型约 90 MB。包装在
`~/.openprogram/extras/embedding/`，不在 App 里，App 更新后仍然保留。

## 项目记忆

项目里的对话可以把只属于这个项目的内容，和到哪儿都适用的内容分开存放。

| 设置 | 作用 |
|---|---|
| **项目记忆** | 项目中的对话同时读取该项目自己的 Memory，存放在 `~/.openprogram/projects/<项目>/memory`。检索、Memory 工具和核心记忆随之覆盖两层，项目在前。默认打开。 |
| **写入项目记忆** | 把项目对话要记下的内容写入该项目的 Memory，而不是个人 Memory。需要先打开项目记忆。默认打开。 |

项目之外的对话属于主目录项目，只读个人 Memory；个人 Memory 就是主目录项目的
Memory，位于 `~/.openprogram/projects/default/memory`。项目的 Memory 在第一次
写入内容后才生效，不会往项目自己的文件夹里写任何东西。在 History 里，
每个项目的 Memory 显示在它的 Memory 标签页下。两层同时生效时，Memory 工具
给每个路径标出所在层，例如 `project:topics/api.md`。一轮对话只写进一层，
所以打开或关闭项目写入都不会把对话复制到另一层；把聊天移到另一个项目后，
只有之后的轮次写进那个项目的 Memory，旧项目 Memory 里已有的内容留在原处。

## 上下文与历史

| 设置 | 作用 |
|---|---|
| **每次聊天注入核心记忆** | 把精简的核心视图加入每次系统提示词。 |
| **Recent 视图大小** | Recent 视图保留的最新记录数。 |

查看和编辑 Memory 的内容，见[查看和编辑 Memory](memory.zh.md)。
