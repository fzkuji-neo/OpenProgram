# 准备每周报告

`weekly_report` 是 Agent 路由入口：理解完整请求，选择飞书个人、群聊个人、小组、腾讯中的一项或多项，再将原话逐字传给对应 Workflow。不会按关键词或冒号拆分要求，不强制只生成草稿，也不设置共同周次或共同检查点。未提飞书时，「写个人周报 / 本周进展」走群聊三段短稿，不走飞书表单。

| 入口 | 用途 |
| --- | --- |
| `personal_weekly_report` | 个人飞书周报草稿、明确要求的飞书查看、提交或修改 |
| `personal_chat_weekly_report` | 群里发的个人三段短稿（本周进展 / 开会讨论要点 / 下周计划），不发送 |
| `group_weekly_report` | 小组周报收集与本地汇总，不发送微信 |
| `tencent_weekly_report` | 约100字的本周腾讯进度稿，不写下周计划，不发送 |
| `weekly_report` | Agent 选择所需类型，完整传递请求，返回子入口结果 |

## 使用

直接输入“写个人周报”“个人和腾讯都做，小组不用”或“三个都做”。Agent 结合完整语义、否定和可用上下文选择；未指定受众时默认生成小组汇总草稿，不通过提问中止路由。单项结果原样返回，多项结果加类型标签。

显式 `requests` JSON 仍可直接指定子 Workflow，参数不改写。各子 Workflow 管理自己的进度与恢复；总入口不再恢复旧的共同检查点，请使用对应子入口的恢复参数。

## 材料与输出

腾讯入口语义理解周次与用户提供的进展，保留完整原话到后续模型上下文；提供的材料必须来自原文。未提供材料时查找已有报告和有日期的记忆，排除其他周次和不可靠记录。目标为约100字，通常80–120字，只报告本周实际进展。微信只读取、整理和生成本地稿件，由用户发送。

五个独立包位于 `openprogram/programs/workflow/weekly_report/`。在 Abilities 展开同名文件夹即可选择各入口。调用图显示总入口到路由 Agent 和四个子 Workflow 的可能调用关系；不代表每次全部执行。

路由、小组请求解析和个人周报的模型调用继承 Runtime 超时配置（`OPENPROGRAM_EXEC_TIMEOUT_S`），不再单独限制为 90 秒。小组请求对未验证原生 schema 能力的提供商允许使用提示词兼容模式，并保留 schema 校验和 Runtime 已有的有限格式修正重试；未恢复的模型异常保留真实失败类型，不再误报为缺少用户输入。外部记录写入结果不确定时不自动重复执行。

小组汇报可以只输入“做小组汇报”。流程主动从记忆、相关本地资料及已确定的微信群查找群、名单、当周材料和作者证据，不再要求用户补字段。原始正文保留；未指定周次时使用当前 ISO 周并标注这一假设。作者未核实则明确标注，资料不足则生成带来源限制的部分草稿，不编造进展。

默认 `source=auto`；显式 `source=supplied` 只使用输入材料。微信读取验证群身份并保留来源证据，历史覆盖始终不完整；微信访问失败时继续查询本地资料。流程不发送消息、不修改系统权限，也不因信息缺失调用 ask_user。

个人字段生成使用只读 Agent 检索指定周次的记忆和本地记录。JSON Schema 校验完整字段或局部修改，使用 prompt fallback 和现有的一次格式修正，随后才允许写入。个人飞书周报将未恢复的模型失败原样抛出。远程写入结果不确定时会抛出不可自动重试的失败，必须先检查实际记录。

结构化 Agent 的正常工具轮次由 `max_iterations` 限制，不消耗失败请求的重试预算。完成工具轮次后保留剩余重试额度；格式修正与失败请求仍共用该额度。达到轮次上限会停止执行，不重新执行已完成的工具。

记忆 search、grep、get、browse 使用正常只读安全工具策略，显式 deny/ask 规则与 `memory.read` 权限仍生效。个人操作选择、来源核验，以及腾讯各 JSON 输出步骤均声明 schema，复用 Runtime 的格式修正。个人飞书周报的格式失败原样抛出；腾讯周报保留现有的模型恢复状态，两者都不当作用户缺少输入。腾讯请求解释继承部署超时。

## 飞书网页操作失败

飞书检查和写入阶段只提供 `web_use`，使用当前的 `command` 参数协议。接受页面观察或报告写入前必须有真实工具回执，模型正文中的工具调用文本不算网页操作。这两个阶段不设置固定的总超时或工具轮次上限，显式 Runtime 部署限制仍然生效。网页访问失败通过总入口传递，不再作为成功文本返回。后续子 Workflow 失败时，原始异常保留此前已完成子任务的结果，总入口不会自动重跑这些任务。
