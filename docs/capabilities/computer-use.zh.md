# 操控电脑

一个工具 `computer_use_agent` 让模型操作屏幕：桌面应用的窗口、一个网页浏览器（App 内置的，或你自己的 Chrome、Edge），或一台虚拟机。应用窗口在你继续工作的同时被读取和操作：应用留在后台，键盘和鼠标仍归你，不会有窗口被带到前台。模型看到的是窗口截图加上它的 Accessibility 树，对编号元素执行动作，然后只拿回发生变化的那几行。应用操作支持 macOS、X11 下的 Linux 和 Windows，差异见[在 Linux 上](#在-linux-上)和[在 Windows 上](#在-windows-上)。

## 目标与指南

每次调用都要指定一个 `target`：

| 目标 | 操作什么 | 需要什么 |
|---|---|---|
| `app` | 本机的应用窗口，由 `args.app` 指定：Finder、备忘录、计算器、Xcode、聊天客户端、游戏启动器 | 下文的桌面权限 |
| `browser` | 网页，在 `args.browser` 指定的浏览器里：默认是 App 内置浏览器（App 窗口里的标签页，以及它在后台打开的标签页），也可以是你自己的 Chrome 或 Edge | App；Chrome 或 Edge 见[你自己的 Chrome 或 Edge](#你自己的-chrome-或-edge) |
| `vm` | 一台运行 OSWorld 兼容服务的远程机器 | `computer_use.vm_url`，见[虚拟机](#虚拟机) |

工具说明里只有这张清单。一个对话第一次调用某个目标时，返回该目标的指南（它的动作及参数）和目标当前的状态，所以模型只学它马上要用的那块屏幕的动作。代码和按描述定位各有自己的指南 `computer_use_agent.code`、`computer_use_agent.describe`：第一次用到它们的调用会被拒绝并附上该指南，下一次调用即可执行。指南只在仍处于模型上下文中时才算读过；对话被压缩后，下一次需要它的调用会重新附上。`action="guide"` 或 `help("computer_use_agent.app")` 可以按需查看指南。每次调用在执行前都会按指南检查：动作或参数不认识就立即报错，错误里写明该动作的参数，不会被悄悄丢掉。几个沿用自 Playwright 的写法会被换成我们的名字，例如 `select_option` 对应 `select`、`values` 对应 `value`、`expression` 对应 `script`。

## 一步长什么样

```
computer_use_agent(target="app", args={"app": "Calculator"})
```

返回指南、窗口截图和这样的树：

```
0 window "Calculator" actions: AXRaise
  12 static text value="0"
  18 button "7"
  23 button "All Clear"
```

每一行是一个元素：序号、角色、标签、当前值、`[focused]`、`[checked]` 之类的状态标记，以及它额外提供的动作。模型随后对序号下手：

```
computer_use_agent(target="app", action="click", args={"app": "Calculator", "element_index": 18})
```

每个动作返回 `Done: …`，后面跟树的 diff：`-` 开头的行消失了，`+` 开头的行是新增或变化的。序号是稳定的：元素只要还在窗口里就保持原序号，即使它上方插入了新东西；新元素拿到一个从未用过的号，所以早先读到的序号绝不会悄悄指向别的元素。给 `get_app_state` 传 `full=true` 可以重新拿到整棵树。树最多 1500 个元素，截图长边最多 1568 像素。

有些应用自己绘制内容，不向辅助功能描述它：游戏、画布类编辑器、远程桌面、部分 Electron 应用。窗口的树少于 12 个元素时，状态里还会列出 macOS 从截图上识别出的文字，每行一条并带中心点的像素位置，例如 `"New Game" at (160, 215), 120x30`；模型用 `x`、`y` 点击它。识别在本机完成，优先使用你的首选语言，并按每张截图检测语言。同一份状态还会列出不带文字的图标和控件（如齿轮、垃圾桶），以轮廓的中心点和尺寸表示，例如 `(112, 169), 55x56`；模型先对照截图认出每个是什么，再去点击。

动作之后工具等待窗口稳定，而不是固定停顿：至少 0.3 秒，直到树不再变化，最多 1.5 秒——界面上有转圈或进度条时最多 5 秒。

## 应用动作

| 动作 | 参数 | 效果 |
|---|---|---|
| `list_apps` | — | 正在运行和已安装的应用，带 bundle id |
| `list_windows` | `app` | 应用的窗口，带 `window_id`、标题、尺寸，以及是否为主窗口、焦点窗口、已最小化或在另一个桌面空间 |
| `get_app_state` | `app`、`window?` 或 `window_id?`、`full?`、`include?` | 截图和树。未打开的应用会在后台启动。`window` 按标题子串或序号选窗口；上次读过的窗口保持选中。`include` 取 `all`、`tree` 或 `screenshot` |
| `zoom` | `app`、`x`、`y`、`width`、`height` | 以显示器的完整像素密度查看上一张截图的一块区域，用于看清小字。动作坐标仍以那张截图为准 |
| `find` | `app`、`text?`、`role?` | 上一棵树里标签、值或占位符包含 `text` 的元素，可限定角色（`button`、`text field`……）。没有元素匹配时，返回截图上显示 `text` 的文字行及其位置 |
| `click` | `app`、`element_index` 或 `x`,`y` 或 `describe`、`mouse_button?`、`click_count?`、`key?`、`duration?` | 按下一个元素，或点击上一张截图上的一点。`key` 是按住的修饰键，如 `cmd`、`shift+alt`；`duration` 是按住鼠标的秒数，至多 10 秒 |
| `type_text` | `app`、`text`、`element_index?` | 向焦点元素输入；给了 `element_index` 就先聚焦它。元素是按钮等不能接收文字的控件时拒绝 |
| `press_key` | `app`、`key`、`element_index?`、`duration?` | 一个 xdotool 写法的组合键：`Return`、`Escape`、`super+c`、`ctrl+shift+Tab`、`KP_0`、`F5`。`super` 和 `cmd` 都是 Command 键 |
| `set_value` | `app`、`element_index`、`value` | 整体替换字段的值、拖动滑块、切换复选框 |
| `scroll` | `app`、`element_index` 或 `x`,`y` 或 `describe`、`direction?`、`pages?` 或 `pixels?` | 按页滚动（可以是小数），或按点数距离滚动 |
| `drag` | `app`、`x`,`y` 或 `describe`、`to_x`,`to_y` 或 `to_describe` | 在上一张截图的两点之间拖拽 |
| `perform_secondary_action` | `app`、`element_index`、`action_name` | 元素列出的某个动作，如 `AXShowMenu`、`AXIncrement` |
| `select_text` | `app`、`element_index`、`text`、`prefix?`、`suffix?`、`selection_type?` | 选中文本元素里的一段文字，或把光标放到它前后 |
| `paste` | `app`、`text`、`format?`、`element_index?` | 经剪贴板以 `text`、`md` 或 `html` 插入，事后恢复剪贴板 |
| `copy` | `app`、`element_index?` | 对当前选区执行应用自己的"拷贝"，返回拷贝到的文字，事后恢复剪贴板 |
| `focus` | `app`、`element_index` | 不点击，直接把键盘焦点移到元素上 |
| `menu` | `app`、`menu_path?` | 不给路径时列出菜单栏。给出 `["View", "Scientific"]` 这样的路径时，列出那个菜单（带快捷键、勾选和禁用项），或选中末端菜单项。标题匹配不分大小写，末尾的 `…` 可省略；屏幕上不会弹出菜单 |
| `show_window` | `app`、`window?` 或 `window_id?` | 恢复最小化的窗口或取消隐藏应用，不把它带到前台 |
| `hover` | `app`、`element_index` 或 `x`,`y` 或 `describe`、`duration?` | 让指针在元素上停留 `duration` 秒（默认 0.8），以打开提示和悬停菜单；你的光标不会动。在后台时不理会指针的应用不会有反应 |
| `wait` | `app`、`duration?` | 等待最多 10 秒（默认 1），然后返回发生的变化：页面加载、播放、收到回复 |
| `start_audio_recording` | `app`、`max_duration?` | 录下该应用播放的声音，最长 `max_duration` 秒（默认 60，最多 300）。只录这个应用，你照常听得到；录音期间可以继续执行其他动作 |
| `stop_audio_recording` | `app`、`transcribe?` | 停止录音，保存 16 kHz WAV 并返回路径；在设置 → 语音里配置了语音引擎时还返回转写文字 |

`app` 是 `list_apps` 打印的名称、bundle id 或 `.app` 路径。`x`、`y` 是该应用最近一张截图上的像素，不是屏幕坐标。

元素动作能到达被隐藏、最小化或被其他窗口盖住的窗口。坐标点击、拖拽和滚轮同样在后台进行：指针不动，前台应用不变。坐标只为树描述不了的画布和自绘控件而存在；凡是列出了序号，优先用序号。

在 macOS 上，桌面 App 会显示每一步落在哪里：agent 光标（与 App 网页上标示操作的是同一个）在应用窗口上滑到目标元素或位置，并在那里播放一次点击，你自己的指针不动。浏览器工具栏里的**显示操作**可以把它关掉，网页和应用一起生效。agent 在某个窗口里操作时，macOS 还会把这个窗口标成共享中：紫色徽标盖住它的标题栏按钮，菜单栏出现屏幕共享图标。最后一步之后约 20 秒两者消失。

## 多个步骤、代码和新 agent

多个步骤放进 `actions`，至多 20 个，按顺序作用于同一个应用。遇到第一个错误即停止，最后只返回一次状态；每一步都使用这批步骤之前读到的状态里的序号和坐标：

```
computer_use_agent(target="app", args={"app": "Calculator"}, actions=[
  {"action": "click", "args": {"element_index": 18}},
  {"action": "press_key", "args": {"key": "KP_Multiply"}},
  {"action": "click", "args": {"element_index": 18}},
  {"action": "press_key", "args": {"key": "KP_Enter"}}
])
```

需要循环、条件判断和数据处理时，模型改为发送 `code`：带顶层 `await` 的 Python，在没有文件、网络和进程权限的隔离解释器里运行，变量在本轮内保留。每个目标是一个对象，它的方法就是它的动作：`await cu.app.click(app="Numbers", element_index=3)`、`await cu.browser.read()`、`await cu.vm.screenshot()`。在代码里，`dir(cu.app)` 列出一个目标的动作，`help(cu.app.click)` 显示一个动作的参数。代码只能操作本次调用指定的应用，不能运行页面脚本、上传文件或打开新网站，每次调用最多运行 120 秒、执行 100 个动作。代码模式只支持 macOS。

`context` 决定由谁来做。默认的 `inherit` 表示模型在这个对话里亲自操作，看到每一步结果。`fresh` 把任务交给一个使用相同模型和设置的新 agent：它从 `brief`（任务、已知信息、要汇报什么）和该目标的指南开始，用自己的 `computer_use_agent` 调用完成工作，只有最终回复回到对话。适合中间画面对话不需要看的长操作。新 agent 不能再启动新的 agent。

## 按描述定位

凡是接受 `x`,`y` 的动作，模型都可以改给 `describe`：按外观对目标的简短描述，如“蓝色的发送按钮”“右上角的齿轮图标”（拖拽终点用 `to_describe`）。工具会重新截图，用 GUI 感知包（图标检测器、OCR 和记住的组件，由对话的模型核对）找到描述的东西，并在它的中心执行动作。这种方式更慢且要调用模型，所以优先用元素序号和 ref；它和按书面简报工作的新 agent 搭配很好。

感知包是 [GUI-Agent-Harness](https://github.com/Fzkuji/GUI-Agent-Harness) Program。每个 release 都带着它和 GPA detector 权重，但检测器依赖的库（PyTorch、OpenCV、EasyOCR）不在 product runtime 里，所以 `describe` 只在装了这些库的环境（例如开发环境）里可用。其他环境里指南会说明 `describe` 不可用，其他定位方式照常可用。

## 网页

`browser` 目标驱动 App 内置浏览器的标签页。每个标签页有一个短 id，例如 `tk3fa`，由 App 的窗口和标签页推导而来，所以在每个轮次、子 agent 和工作流程序里都一样。`tabs` 列出它们，`open(url)` 新开一个，其他动作默认作用于最近用过的标签页，用 `tab` 可以指定别的。

`read` 返回 Playwright 的无障碍大纲：每个元素一行，带角色、名称、状态和 ref，例如 `- button "Next" [ref=e12]`。只要元素还在页面上，它的 ref 就一直有效，跨任意多个动作和轮次。也可以不用 ref，用 `role` 加 `name` 指定元素。每个动作都返回它改变了什么：变化的行标为 `<changed>`，`[unchanged]` 代表已经看过的部分；动作让标签页跳到了另一个地址时，返回整个新页面。所以一整张表单可以在一个动作列表里填完。ref 对应的元素被重新渲染时，会按角色和名称重新找到；元素已经不在时，错误里附带页面的当前状态。

| 动作 | 参数 | 作用 |
|---|---|---|
| `tabs` / `open` / `close` | — / `url`、`visible?` / `tab?` | 列出标签页；新开标签页（默认在后台，`visible: true` 时在前台）；关闭标签页 |
| `read` | `changes_only?` | 整个页面，或只返回上次结果之后的变化 |
| `click` | `ref` 或 `role`、`name` 或 `x`、`y`，`mouse_button?`、`click_count?`、`modifiers?` | 右键、中键、双击和带修饰键的点击，例如 `modifiers="cmd"`；`x`、`y` 是该 agent 上一张截图的像素，截图之后页面被操作、跳转或滚动过就不再可用 |
| `type` | `ref?`、`text`、`clear?`、`submit?` | 替换字段内容；`clear: false` 在光标处插入；`submit: true` 输入后按回车；不带 `ref` 时输入到当前焦点元素 |
| `paste` | `text`、`format?`、`ref?` | 以粘贴的方式把文字交给页面：`md` 和 `html` 在富文本编辑器里插入带格式的内容，自己处理粘贴的页面会收到这次粘贴 |
| `select` | `ref`、`value` | 按值或标签选择下拉框的选项 |
| `press` | `key`、`ref?` | 不带 `ref` 时按键发给页面的焦点 |
| `hover` / `drag` / `scroll` | `ref` / `ref`、`to_ref` / `ref?`、`direction?`、`amount?` | 带 `ref` 时 `scroll` 滚动该元素最近的可滚动容器；`amount` 以像素计 |
| `navigate` / `back` / `forward` / `reload` / `wait` | `url` / — / `text?`、`seconds?` | 历史导航；`wait` 等到某段文字出现，或等待若干秒 |
| `upload` | `ref`、`path` | 把不超过 50 MiB 的本地文件放进文件输入框 |
| `screenshot` | — | 标签页的截图，截取时不把它调到前台 |
| `console` / `network` | `pattern?`、`only_errors?`、`limit?` | agent 第一次使用该标签页以来的控制台输出和网络请求 |
| `evaluate` | `script` | 在页面里运行 JavaScript 表达式或函数（如 `() => document.title`），以 JSON 返回结果，最多 20,000 字符；结果里的密码字段值会被遮盖 |

多个 agent 可以同时使用浏览器，同一对话的子 agent 也一样。一个动作在读到结果之前一直占着它的标签页，一组动作在结束之前占着它碰到的所有标签页，所以别的 agent 的输入不会插进正在填写的表单中间；一个标签页被占用一分钟仍未释放时，动作以 `tab_busy` 失败。每个 agent 有自己的当前标签页，看到的是自己上次查看之后的全部变化，不论是谁改的；期间若有别的 agent 操作过同一个标签页，结果里会注明。一个 agent 在等页面时不会挡住其他 agent。

任何动作都不会被发送两次。动作在输入可能已经到达页面之后失败（例如超时）时，错误会说明这一点并附上页面的当前状态，且不会再试一次。动作打开了新标签页（例如在新窗口打开的链接）时，结果会给出那个标签页；agent 的当前标签页不变，直到它指定新的那个。在工作流程序里，浏览器限于程序启动时所在的窗口，程序打开的标签页在它结束时关闭。你关闭了某个对话对页面的 agent 访问时，浏览器在那里拒绝所有动作。

App 浏览器里的标签页全程留在后台：输入送达时不会激活它，`open` 打开的标签页也在你的工作后面；`visible: true` 则把它放到前台，用于你要求看着它操作的时候。`file://` 地址同样能打开本地文件，前提是沙箱允许 agent 读取该文件。密码字段的值不会出现在模型读到的内容里。

App 内置浏览器的标签页不需要审批。打开你电脑之外的网站、上传文件会先询问。脚本能读取和修改已登录页面持有的一切，所以每次 `evaluate` 调用都会先问你并展示完整脚本，任何权限模式下都如此，即使有规则允许 `computer_use_agent` 也一样。批准只覆盖这一次调用：它没有“始终允许”，无法询问的定时任务或频道轮次会被拒绝。批准后脚本在它所针对的标签页上运行。

## 查看和接管网页

在桌面 App 中，Agent 打开的网页保留在后台。右侧栏的 **Resources** 按分支列出当前会话的网页，包括子 Agent 使用的网页。继续同一分支时保持原有资源分组。即使 URL 相同，不同 Page 也保持独立；无法确定分支归属的网页显示在“未归属”中。

Agent 的网页打开的弹窗或新窗口会作为独立的 Page 在后台加载，并归入 **Resources** 中同一会话和分支，不抢占你的视图。Agent 对原网页的下一次结果会告诉它这个弹窗，让它在弹窗里继续，而不是在原网页重新走一遍流程。你自己打开的网页弹出的窗口照常作为普通标签显示在前台。

单击资源在聊天中查看它的图像预览。“在会话中预览”是针对同一现有 Page 的显式控件：不增加顶部标签；若当前正在查看网页，则回到所属会话，使聊天预览可见。聊天预览标题栏提供持续的“固定预览 / 取消固定预览”：固定后保持当前页面；取消固定后恢复自动显示该分支最近实际操作的网页。选择资源只显示它、不固定，也不抢占标签焦点；处于自动预览时，Agent 下一次读取或操作其他网页就会切换过去。打开、读取和操作网页都算在内，不只是点击和输入。该固定控件只在聊天预览上，会话资源没有固定按钮。“隐藏”停止预览截图并保留网页。用资源行或“在会话中预览”恢复已隐藏的预览，没有单独的“显示预览”控件。“展开”放大图像预览且不改变自动或固定预览，“打开页面”把原来的 Page 显示为普通顶部标签并隐藏聊天预览。返回会话后，除非已经隐藏，否则恢复预览。这些选择按会话和分支保存。固定只在本次打开 App 期间有效，重新加载后恢复自动预览。

网页标签与其预览不得同时显示。真实网页在自己的标签中保持可用，不会变暗或被遮罩阻挡。工具栏显示当前操作者，并提供“暂停 Agent，我来操作”“让 Agent 继续”“显示操作”和“操作记录”。聊天预览使用单行紧凑控件栏；空闲和已关闭显示“可直接操作”，不提供暂停或继续按钮。默认小窗为 300×198.75。拖动标题栏移动，或从任一边/角调整大小；画面比例保持联动，底层页面不被缩放。操作位置提示短暂显示，不拦截输入；记录显示操作类型和结果，不保存网页中输入的完整文字。

在真实网页中点击、输入、滚动或导航会请求暂停：停止接纳后续 Agent 输入，并请求暂停执行。仅聚焦页面或查看预览不会暂停。已经发送的动作仍可能完成。“正在暂停…”表示停止尚未确认；“已暂停”需要执行确认及状态核对。“暂停失败，请重试”表示 App 尚未确认停止，在仍连接时可用“重试暂停”；真实网页仍然可以正常使用。“让 Agent 继续”需要明确操作，并重新观察页面、检查当前权限。

关闭网页会影响所有引用同一 Page 的分支。正在使用的网页先请求停止，在确认停止前继续保留。关闭网页与隐藏预览是不同操作。连接中断或目标不可用时，最后一张图像会标注为旧画面。已保存的资源描述不会恢复 Agent 输入租约，也不会重新创建已关闭的 Page。

若 App 或 worker 重启，你尚未关闭的网页在后台恢复，不额外增加顶部标签。保留的 tab、会话与分支以及最后确认的标题和 URL 保持不变。应用为该保留 tab 创建新的活页面。先前的活句柄无效。明确关闭的网页留在“已关闭的网页”。已隐藏的预览保持隐藏，直到你选择该资源或使用“在会话中预览”。正在恢复、恢复失败或需要重新连接的行留在原分支，分别显示“正在恢复网页…”、“网页恢复失败”或“需要重新连接”，不进入通用不可用分组。恢复网页不要求“让 Agent 继续”。空闲页面仍显示“可直接操作”。新任务动作仍须在新页面上重新观察并检查当前权限。恢复会重新加载最后确认的 URL，并使用已有站点持久存储；上一进程中未保存的 DOM 与表单值不会恢复。没有保留 tab 描述的旧资源记录不会自动重建，在原分组显示“网页恢复失败”。这一有界重启恢复已经实现。

聊天小窗也会跟随 Agent 操作的其他东西。Agent 操作桌面应用窗口时，小窗显示这个应用，画面是 Agent 最近一次对该窗口的截图，每一步后更新。Agent 接管终端或向终端输入时，小窗只读显示该终端的实时输出。自动预览、固定和关闭的规则相同；Agent 下一次操作网页时，小窗切回网页。截图只保存在内存里，worker 重启后不保留。

这些控制作用于 OpenProgram 中确切的 Page。应用窗口和虚拟机显示仍按上文各自的审批进行。

## 你自己的 Chrome 或 Edge

调用把 `args.browser` 设为 `chrome` 或 `edge` 时，`browser` 目标就在你平时浏览用的浏览器里工作，页面带着你的登录状态和 Cookie 打开。动作与内置浏览器相同：`tabs` 按序号列出你的标签页，带 `tab=<序号>` 的 `read` 切到其中一个，`open(url)` 打开新标签页，`click`、`type`、`press`、`scroll`、`screenshot` 等作用在最新快照给出的 ref 上。模型被要求只在你点名或任务需要你的登录状态时才用你的浏览器，并且只用你点名的那一个。

它以扩展模式运行微软的 Playwright MCP 服务器（`@playwright/mcp --extension`），由你浏览器里的 [Playwright Extension](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm) 连接过来；Edge 也从 Chrome 应用商店安装同一个扩展。安装一次即可；服务器本身通过 `npx` 获取，所以需要装有 Node.js。第一次动作时扩展会询问共享哪个标签页。要免去这一步，复制扩展里显示的令牌并设置：

```bash
openprogram config set computer_use.chrome_extension_token <token>
```

一次批准覆盖本会话的 Chrome（或 Edge）；`evaluate`（页面 JavaScript）每次都询问，`upload` 会写明上传。代码模式不覆盖你的浏览器。

## 虚拟机

`vm` 目标驱动一台运行 [OSWorld](https://os-world.github.io/) 兼容服务的机器：工具用 `GET /screenshot` 截图，并通过 `POST /execute` 在那台机器上用 pyautogui 执行指针和键盘输入。设置一次服务地址：

```bash
openprogram config set computer_use.vm_url http://192.168.64.2:5000
```

虚拟机没有元素树：它的动作是 `screenshot`、`click`、`move`、`drag`、`scroll`、`type_text`、`press_key` 和 `wait`，用上一张截图的像素或 `describe` 定位。每个执行类调用都会返回一张新截图。一个对话第一次使用虚拟机时会请求审批，审批里写明服务地址。

## 审批

一个会话第一次触碰某个应用时，审批卡片会显示这个应用本身（图标、名字和 bundle id），说明这一步要做什么（如“点击 元素 #7”“输入 12 个字”“运行操作它的代码”），并说明它在后台进行。原始参数收在“查看执行详情”里。卡片提供：

- **允许一次**——仅这一次调用。
- **允许此对话**——本会话里之后对同一应用的所有 `computer_use_agent` 调用，保存为会话规则。
- **始终允许**——保存为项目规则 `computer_use_agent(<app>)`，项目里以后的会话不再询问。以工具旧名保存的规则 `computer_use(<app>)` 继续有效。
- **拒绝**。

在会询问的模式（默认和接受编辑）下，卡片会一直出现，直到有规则点名该应用。Bypass 下直接操作、不询问；Auto 下每次操作和其他工具调用一样交给自动审查。定时任务等无人值守的运行无法回答卡片，因此除 Bypass 外只能操作项目里已允许的应用。`list_apps` 从不询问。每个应用单独审批：允许了备忘录，不代表允许邮件。`fresh` 新 agent 沿用它那次调用得到的批准：它工作期间，该应用在本对话中处于允许状态。项目的设置页在**操控电脑**下列出始终允许的应用，每个应用一行并带图标；移除一行即删除对应规则，下次操作该应用会重新询问。只对某个对话有效的授权随对话结束，不列在这里。一般的权限规则见[权限](permissions.zh.md)。

允许一个应用，是让模型可以操作它，并不让模型自行完成有后果的步骤。工具要求模型在发送消息、提交表单、购买、删除，或按照屏幕上出现的指示行事之前先向你确认。验证码、密码和安全提示交给你来处理。模型在屏幕上读到的文字从不被当作你的许可。

## 系统权限

系统设置显示执行电脑上的可选桌面权限。打开页面或运行 `openprogram doctor`
不会申请权限。TUI 的 `/doctor` 和 `GET /api/system/access` 使用同一套检查。
未开放可选桌面权限不会阻止普通对话或升级。

macOS 托管安装通过内置的 **OpenProgram** 应用运行后台和 Python 子进程，
使用 OpenProgram 图标和稳定的应用标识。系统设置中应查找这个名称；安装程序不会
替用户授权。录屏和辅助功能权限分别由新启动的进程检查，使用与桌面任务相同的程序。本机系统设置中的“设置权限”
只会在用户点击后申请缺少的权限，已有授权保持不变。在系统中确认后返回页面，
页面自动重新检查。远程客户端需要在执行电脑上完成授权；其他应用的授权不能
证明 worker 已获得授权。

Linux 无图形桌面和暂不支持的 Wayland 桌面捕获会与缺少依赖分别报告。
仅存在 X11 显示配置不能证明具有访问权限。Windows 的桌面访问取决于当前会话
和目标程序，普通程序不能假定可以访问系统安全桌面或高权限目标。不会要求用户
关闭安全限制或将整个程序改为管理员运行。Linux、Windows 原生桌面验收尚未完成。

当前 macOS 开发构建没有正式生产签名。正式签名版本升级后的授权保持、首次使用
功能引导、授权后自动恢复任务尚未验证。设置系统权限不会重新执行已拒绝的操作。


### 授权

缺少系统权限时，应用调用在操作前暂停。OpenProgram 直接请求缺少的系统权限，必要时打开对应的系统设置页面。会话显示简短的暂停等待状态及“打开系统设置”文字入口；暂停的运行卡不显示权限表单、继续按钮、空结果、重试或修改操作。真正失败和取消的运行保留各自的终态。

后台保存等待中的任务，通过新启动的 OpenProgram 进程检查权限，使用与桌面任务相同的程序，避免沿用系统设置改变前保存的检查结果。检查本身不会申请权限。权限可用后，同一个任务继续一次。关闭页面不会停止检查；如果需要重启应用，启动后会再次检查保存的任务。取消任务后不会恢复。检查失败时保留等待状态，不会当作已经授权。查看旧会话本身不会启动操作或重新弹出系统授权。系统授权不会替代工具操作审批。

本地临时签名的 macOS 版本更新后，旧录屏授权可能失效，而系统开关仍显示开启。OpenProgram 会记录已安装应用成功取得录屏权限时的身份。如果之后应用身份改变且录屏检查失败，下一次本机授权操作会先更新 OpenProgram 自己的旧录屏登记，再进入系统授权流程。每个变化后的身份最多处理一次；状态检查和重连不会重置权限。使用稳定 Developer ID 签名的发行版沿用正常系统授权流程。

切换会话时，同一个等待任务的重复消息不会再次打开系统授权。你仍可主动打开系统设置。

### macOS 自动化权限错误

部分桌面命令会向 System Events 或目标应用发送 Apple Events。macOS 按目标应用分别控制“自动化”权限；录屏和辅助功能授权不代表已取得自动化权限。操作报告自动化权限拒绝时，请在执行任务的 Mac 上打开“系统设置 → 隐私与安全性 → 自动化”，检查发起请求的应用对错误中所列目标的授权。失败的操作仍保持失败；修改系统设置不会批准或重复执行该操作。其他原生命令失败会保留实际错误，不会显示为成功。

## 另一个桌面空间里的窗口

在另一个桌面空间里的窗口就地读取和操作：`list_windows` 会标出它，截图、点击、滚动、拖拽和元素动作都能送达，不用切换桌面空间。macOS 不把按键送给这样的窗口，所以在那里 `type_text` 和 `paste` 改为把纯文本插入有焦点的输入框，`press_key` 会报告按键发不过去。工具不能把窗口移到你当前的桌面空间，只有你自己（或 Dock）能移。

## 要求

- macOS、使用 X11（Xorg）会话的 Linux，或 Windows 10、11。
- 在 macOS 上，签名的运行时（`ai.openprogram.runtime`）必须持有**辅助功能**和**屏幕录制**权限。工具会报告缺哪一项，设置 → 系统访问可以发起请求。[权限](permissions.zh.md)描述了运行时的 macOS 授权方式。

## 在 Linux 上

Linux 上，工具通过 AT-SPI 读取窗口的无障碍树（GTK 3、GTK 4 应用默认提供；Qt 应用需要 `QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1`），并用 `xdotool` 执行动作。需要：

- X11 会话：Wayland 不允许一个应用读取或操作另一个应用的窗口，所以在 Wayland 下工具会报告不可用；
- `python3-gi`，以及 `gir1.2-atspi-2.0`、`gir1.2-gtk-3.0` 和 `xdotool`；
- 可选：`x11-utils`（`xprop`，用来区分真正的窗口和辅助窗口）、`tesseract-ocr`（为没有无障碍树的应用识别截图上的文字）、`pulseaudio-utils`（录音）。

相同的部分：树的格式、稳定的编号和差异、截图、`zoom`、`find`、`actions` 里的多个步骤、`menu`（有菜单栏的应用）、`select_text`、`set_value`、按元素拖动滚动条，以及审批。应用按 `list_apps` 打印的桌面条目 id（`org.gnome.Calculator`）、名称或进程名来指定；已安装的应用通过它的桌面条目启动。

不同的部分：

- 元素动作（按下、切换、设值、插入和选中文字、选择菜单项、在输入框里按回车）在后台进行。按 `x`、`y` 的指针输入（点击、拖拽、滚轮）、`hover`，以及回车以外的按键，只有在 GTK 或 Qt 窗口获得焦点时才能送达，所以这一步会把窗口短暂切到前台，输入完成后把焦点和鼠标指针还回原处。`hover` 会让指针停在窗口上。审批卡片会对这些步骤如实说明。
- `paste` 把纯文本直接插入有焦点的输入框，不经过剪贴板；不支持 `format=md` 和 `html`。`copy` 直接返回选中的文字，不动剪贴板。
- 不接入无障碍总线的应用在列表里标为 "no accessibility tree"：模型读它的截图（装了 tesseract 时带 OCR 文字），按坐标操作。
- 录音只读取该应用（及其子进程）自己的音频流，来源是 PipeWire 或 PulseAudio。PipeWire 下四分之一秒内就开始录；只有 PulseAudio、没有 PipeWire 时，已经在播放的音频流开头约一秒可能录不到。
- 拒绝操作：密码框、Seahorse 和 KWallet、polkit 与 gcr 认证弹窗，以及 OpenProgram 自身。

## 在 Windows 上

Windows 上，工具读取窗口的 UI Automation 树（Win32、WPF、WinForms、应用商店应用（UWP、WinUI）和基于 Chromium 的应用都提供），窗口被挡住时也能截图。需要 `comtypes` 包，Windows 安装已包含；`PATH` 上有 `tesseract` 时，没有树的应用的截图文字也能识别。Windows 支持是新加的，项目还没有在 Windows 机器上实际跑过；遇到问题请连同失败的那一步一起反馈。

相同的部分：树的格式、稳定的编号和差异、截图、`zoom`、`find`、`actions` 里的多个步骤、`select_text`、`set_value`、`copy`、`paste`（纯文本、markdown 和 HTML）、按元素滚动、录音以及审批。应用按 `list_apps` 打印的名字指定：开始菜单里的名称（`计算器`）、可执行文件名（`notepad`）或进程号；已安装的应用从它的开始菜单条目启动。

不同的部分：

- 元素动作通过 UI Automation 在后台进行。对窗口的点击、滚动和不带修饰键的按键以窗口消息发给这个窗口，不会把它切到前台；`hover` 不移动你的鼠标指针。
- 带修饰键的按键（`ctrl+s`）需要真实的键盘状态，`paste` 在多数应用里要按 `ctrl+v`，所以这一步会把窗口短暂切到前台，完成后把焦点和鼠标指针还给你。只接收真实输入的窗口（应用商店应用的外框、Chromium、Firefox）的指针输入也这样处理。请用 Windows 的快捷键：`ctrl+c`，不是 `cmd+c`。
- `menu` 支持传统菜单栏和通过 UI Automation 提供的菜单；用功能区（Ribbon）的应用，命令在窗口的树里。
- `copy` 直接返回选中的文字，不动剪贴板。`paste` 之后恢复剪贴板里原来的文字，其他格式不保留。
- 录音通过 Windows 的进程回环采集该应用自己的进程树（需要 Windows 10 2004 或更高版本）。
- 拒绝操作：密码框、凭据与提权（UAC）弹窗、锁屏，以及 OpenProgram 自身。

## 录音

录音使用截图本来就需要的屏幕录制权限，只采集所指定应用自己的输出：其他应用、麦克风和系统提示音都不在里面。录音保存在 `~/.openprogram/computer-use/audio/`，保留最新的 20 个。`stop_audio_recording` 用设置 → 语音里选的引擎转写：whisper.cpp 让声音留在本机，OpenAI 和 Groq 引擎则会把声音发给对应的服务商。传 `transcribe=false` 只保留文件。静音的录音会如实报告，不做转写。对话模型接受音频输入时（如 Gemini 和 OpenAI 的 gpt-audio 模型），它还会直接收到录音本身，能听到转写文字里没有的音乐、语气等声音。

## 工具拒绝做的事

工具不向安全文本框输入，macOS 报告安全键盘输入期间也不输入；它从不操作钥匙串访问和密码 App、系统登录与授权弹窗，以及 OpenProgram 自身。任务需要这些步骤时，模型会请你来做。

工具说明要求模型在删除数据、发送消息、提交表单、花钱、更改账户、权限或系统设置以及安装软件之前先征得你同意，并把验证码、输入密码和安全提示交给你处理。窗口里显示的文字从不被当作你的许可。

该工具在微信、Telegram 渠道和规划模式下不提供。
