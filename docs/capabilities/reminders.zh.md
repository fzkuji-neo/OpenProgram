# 提醒

在任何对话里用平常的话，让 agent 到点提醒你，或者过一会儿回来做某件事：

- “20 分钟后提醒我把面包拿出来。”
- “下午 5 点提醒我发发票。”
- “每个工作日 9:00 提醒我看站会记录。”
- “明天 9 点检查一下 CI 有没有通过，告诉我哪里失败了。”

前三条是**通知**：到点你会收到这条消息。最后一条会**唤醒 agent**：到点时同一个对话里会以这条请求开始一轮，agent 在那时把事情做完。

## 设置提醒

agent 用 `remind` 工具设置提醒。它的回复会写明提醒触发的确切时间，例如 “fires Fri 2026-10-23 17:00 CST (in 2.5 h)”，你可以据此确认它理解对了。

| 你说 | 触发时间 |
| --- | --- |
| “20 分钟后” | 从现在起 20 分钟 |
| “17:00” | 下一个 17:00：今天还没到就是今天，否则是明天 |
| “12 月 1 日 10:00” | 那个日期和时间 |
| “每个工作日 9:00” | 重复；agent 会写一个 cron 表达式，如 `0 9 * * 1-5` |

除非你指定别的时区，时间都按这台电脑的本地时区计算。提醒会在设定时间后一分钟内触发。

提醒是只通知你还是唤醒 agent，取决于你怎么说：说“提醒我”是通知；让 agent 之后去“做”某件事，就会唤醒它。如果在意，可以直接说明要哪一种。

## 到点之后

通知类提醒会：

- 在每个打开的 OpenProgram 窗口里弹出提示；
- 发一条系统通知，即使你正在用 App 也会发。由桌面 App 发出（点击打开该对话）；没有打开任何 App 窗口时，由 worker 自己发，同样显示 OpenProgram 的名字和图标。不是随 App 安装、而是用 pip 安装的 worker，在 macOS 上通过“脚本编辑器”发，在 Linux 上需要 `notify-send`；
- 如果是在[聊天渠道](../integrations/channels.zh.md)对话里设置的（Telegram、Slack、Discord 或微信），同时以消息发到那个对话。

唤醒 agent 的提醒做完上面这些之后，会在设置它的那个对话里开始一轮。这一轮的消息以 ⏰ 和提醒内容开头，使用该对话的权限模式和规则。如果那里正有一轮在运行，它最多等 10 分钟，等那一轮结束再开始。在聊天渠道对话里，agent 的回答也会发到渠道。

如果提醒触发时对话已被删除，你仍会收到通知，但不会开始新的一轮。

## 查看、暂停或取消提醒

打开侧栏的 **Scheduler（定时任务）**。提醒和其他定时任务列在一起，标有 **提醒** 或 **提醒 · 唤醒 Agent**。可以在那里暂停、恢复或删除；也可以直接告诉 agent（“取消我 5 点的提醒”），它会用 `scheduler` 工具列出并删除。

## 限制

- 提醒在这台电脑上的 OpenProgram worker 里运行。如果到点时 worker 没在运行，一次性提醒会在它重新启动后立即触发；重复提醒会跳过错过的时间。用 `openprogram worker install` 让 worker 随登录启动。
- 系统通知遵循系统设置：开着专注模式或勿扰模式时，通知会留在通知中心。App 的**通知**设置关掉后，App 自己的通知也会关掉。
- 只有你本人（本地 owner，在交互式对话里）可以设置提醒。

## 运行你自己的命令

每次提醒触发都是一个 `reminder.fired` 事件。在 `config.json` 里加一条 `hooks`，就能在提醒触发时运行你自己的命令，事件以 JSON 形式从标准输入传入：

```json
{"hooks": {"reminder.fired": [{"command": "python ~/bin/on_reminder.py", "timeout": 30}]}}
```

事件的 `payload` 包含 `message`、`title`、`session_id`、`wake` 和 `fired_at`。hooks 在 worker 启动时读取。[事件层设计](../reference/design/proactive/event-layer.zh.md)介绍了事件和 hooks。
